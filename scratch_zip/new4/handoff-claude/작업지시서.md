# MSO 모바일 — 작업지시서 (Claude 핸드오프)

> 병원 그룹웨어(MSO)의 **모바일 웹 프로토타입**입니다. PC 버전 기능을 모바일 화면에 이식하는 작업을 진행 중입니다.
> 이 문서는 Claude가 이 코드베이스를 이어받아 작업할 수 있도록 구조·규칙·수정 방법을 설명합니다.

---

## 1. 무엇을 만드는가

- **대상**: 병원(박철홍정형외과 외 4법인) 임직원용 모바일 그룹웨어
- **형태**: 단일 HTML + React(인라인 JSX, Babel standalone) 프로토타입. 빌드 도구 없음.
- **핵심 4개 업무 모듈**
  1. **전자결재** — 결재함 + 문서 조회(연차신청·출결정정·연차계획서 등 양식별 조회/승인)
  2. **인사관리** — 구성원·근태·연차/휴가·급여 워크센터·복지·계약/문서
  3. **재고관리** — 재고현황·입출고/발주·물품/자산·분석/마감
  4. **관리자** — 경영 대시보드·시스템 마스터·회사 관리·권한 관리·운영 설정·결재 양식·감사/백업
- **디자인 원칙**: PC 버전과 **기능·메뉴 구조는 100% 동일**하게 유지하되, **표현만 모바일에 맞게** 최적화한다.
  - 메뉴 위계: **허브(상위 메뉴) → 탭(하위 메뉴) → 상세/폼(드릴다운)**. PC의 SUBMENUS/TABS 구조를 그대로 따른다.

---

## 2. 실행 방법

1. `code/MSO 모바일.html` 을 브라우저에서 연다 (로컬 서버 권장 — 일부 브라우저는 `file://` 에서 JSX fetch 차단).
   ```
   cd code && python3 -m http.server 8000
   # http://localhost:8000/MSO%20모바일.html
   ```
2. 우측 하단 iOS/Android 프레임 토글로 두 OS 미리보기 확인 가능.
3. 하단 탭바: 홈 / 채팅 / 전자결재 / 더보기(인사·재고·관리자·게시판).

## 3. 파일 구조 (code/)

```
MSO 모바일.html          ← 엔트리. 스크립트 로드 순서 중요(아래 의존성 참고)
wn/
  ├ 데이터 (순수 JS, window 전역)
  │   msm-data.js        ← 채팅·전자결재·홈 등 공통 목 데이터 (window.MSM)
  │   msm-leaf-data.js   ← ★인사·재고·관리자 메뉴트리 + 모든 화면 스펙(LEAF). 작업의 90%는 여기.
  │   gl-data.js         ← 그룹웨어 공통 데이터(채팅 등)
  │
  ├ 렌더러 / 화면 (JSX)
  │   icons.jsx          ← <Icon name=… /> SVG 아이콘 세트
  │   msm-shell.jsx      ← 앱 셸: 하단 탭바 + 화면 라우터
  │   msm-home.jsx       ← 홈(내정보) + 톤 헬퍼(msmTone, avTone)
  │   msm-personal.jsx   ← 내정보 상세(출퇴근/연차 — 90일 조회·승인)
  │   msm-comms.jsx      ← 채팅 + ★전자결재(ApprovalScreen: 결재함/문서조회)
  │   msm-leaves.jsx     ← ★데이터기반 렌더러(LeafView/LeafHub/LfXxx 블록) + 위저드
  │   msm-more.jsx       ← ★인사/재고/관리자 허브 화면(HrScreen/StockScreen/AdminScreen)
  │   msm-addon-*.jsx    ← 게시판 등 부가 화면
  │   msm-canvas-app.jsx ← iOS/Android 프레임 캔버스(미리보기 셸)
  │
  └ 스타일 (CSS)
      msm.css            ← 모바일 공통 토큰·컴포넌트(.msm-row/.msm-sec/.mm-kpi 등)
      msm-modules.css    ← ★Leaf 전용(.lf-table/.lf-kv/.lf-tab/.lf-wiz 등)
      gl-mobile.css      ← 그룹웨어 공통
```

### 스크립트 로드 순서 (HTML에서)
데이터(js) → React/Babel → icons → frames → gl-* → **msm-home → msm-personal → msm-comms → msm-leaves → msm-more** → addons → shell → canvas-app.
`msm-leaves.jsx` 는 반드시 `msm-more.jsx` **앞**에 로드되어야 한다(LeafHub/LeafView 사용).

## 4. 핵심 아키텍처 — 데이터 기반 Leaf 시스템

인사·재고·관리자 화면은 **코드가 아니라 데이터(`LEAF`)로 정의**한다.
`msm-leaves.jsx` 의 렌더러가 블록 배열을 받아 그린다. **새 화면을 추가/수정하려면 `msm-leaf-data.js` 의 데이터만 고치면 된다.**

### 4-1. 메뉴 트리 (허브에 노출되는 상위 메뉴)
```js
window.HR_TREE    = [{ group:'인사관리 메뉴', items:[ {id,label,icon,tone,sub,badge,bt}, … ] }];
window.STOCK_TREE = [ … ];
window.ADMIN_TREE = [ … ];
```
- `id` 는 `LEAF[id]` 와 연결된다. `tone`: accent|success|warn|danger|muted. `badge`/`bt`: 우측 뱃지.

### 4-2. 화면 스펙 (`window.LEAF`)
각 `id` 는 아래 셋 중 하나:
```js
// (A) 단일 화면 — 블록 배열
'st-status': { title:'재고 현황', blocks:[ …블록… ] }

// (B) 탭 화면 — PC의 하위 탭(서브메뉴)
'hr-member': { tabs:[
  { label:'구성원', cnt:27, blocks:[…] },
  { label:'인사발령', cnt:3, blocks:[…] },
  { label:'교육·자격', cnt:12, blocks:[…] },
]}

// (C) 파라미터 화면 — 드릴다운(목록행/버튼에서 nav+params로 진입)
'hr-member-card': { title:'인사카드', build:function(p){ return [ …p로 채운 블록… ]; } }
```

### 4-3. 블록 종류 (msm-leaves.jsx 의 LeafBlocks 가 디스패치)
| 키 | 용도 | 형태 |
|---|---|---|
| `hero` | 상단 히어로 카드 | `{tone:'dark\|green\|blue\|amber', label, big, unit, sub}` |
| `kpis` | 2×2 지표 카드 | `[[icon,tone,label,sub,value,unit,emphValue?], …]` |
| `stat` | 2열 통계 | `{sec, stat:[[value,label,tone?], …]}` |
| `list` | 행 목록(드릴다운 가능) | `{sec, more, list:[{ic\|av, nm, sub, badge, bt, val, vBadge, vTone, nav, params}]}` |
| `table` | 표 | `{sec, cols:[…], table:[[셀\|{v,bt}], …], w:'1.4fr 1fr'}` |
| `kv` | 라벨-값 명세(급여/공제 등) | `{sec, kv:[{l, v, note?, tone?, strong?}]}` |
| `prog` | 진행률 막대 | `{sec, prog:[{nm, sub, p, bt, ic}]}` |
| `note` | 콜아웃 | `{note:{tone, ic?, t, s}}` |
| `chips` | 필터 칩 | `{chips:['전체 27','유효 44', …]}` |
| `form` | 입력 폼 | `{sec, form:[{l, type:'text\|num\|select\|date\|time\|textarea', v, ph, opts}], submit:{t,ic}}` |
| `wizard` | 단계형 입력 | `{wizard:{submit, steps:[{title, sub?, fields:[…], roles?}]}}` |
| `cal` | 월 달력 | `{cal:{sec?, holidays:[5,24], mark?}}` |
| `shift` | 교대 근무 카드 | `{sec, shift:[{b,bt,t,n,staff:[…]}]}` |
| `profile` | 상세 헤더(인사카드 등) | `{profile:{av, nm, code?, role?, chips:[{t,tone}]}}` |
| `meta` | 3열 메타 | `{meta:[['입사일','2020.06.15'], …]}` |
| `timeline` | 타임라인(이력/결재선) | `{sec, timeline:[{d, t, tone}]}` |
| `btns` | 액션 버튼(드릴다운 진입) | `{btns:[{t, ic, primary?, danger?, nav?, params?}]}` |
| `cap` | 작은 설명문 | `{cap:'…'}` |

### 4-4. 위저드 필드 종류(wizard fields)
`text|num|tel|email|date|time|textarea` / `select`(드롭다운) / `multiselect`(중복선택+칩) / `seg`(세그먼트) / `chips` / `toggle`(스위치) / `head`(그룹 제목) / `row`(한 줄에 여러 필드: `{k:'row', cols:[…]}`) / `photo`(사진) / `summary`(요약 카드) / `cap`.

> 예시: 신규 직원 등록(`hr-member-new`)은 PC 폼과 동일한 **3단계 위저드**(인적사항 / 소속·근무 / 급여·보험)이며 회사·팀·직함 드롭다운, 근무형태 multiselect, 4대보험 toggle, 급여 summary 카드를 사용한다.

## 5. 전자결재 (msm-comms.jsx · ApprovalScreen)

- 상단 세그먼트: **결재함 / 문서 조회**(기본 진입 = 문서 조회).
- **문서 조회**: 문서 종류(select) + 기간 칩(최근 30일 / **90일 기본** / 전체) + 조회 버튼.
  - 결과는 **진행 중 / 처리 완료**로 분리. 90일 초과 문서는 제외, 미래일 결재중 문서는 포함.
  - 진행 중 문서의 `결재 승인(시연)` 버튼 → 페이드되며 진행 중에서 제거(승인 시 사라짐 데모).
- 데이터: `window.MSM.approvals` (msm-data.js). 양식명은 PC 기준(연차신청·출결정정·연차계획서·물품신청·수리요청서·업무기안 등).

## 6. 작업 규칙 (반드시 지킬 것)

1. **PC 기준 우선** — 메뉴/탭/필드 구성은 임의로 만들지 말고, `uploads/기능부품/*서브/` 의 실제 PC 컴포넌트(SUBMENUS/TABS, 폼 필드, 요율 등)를 먼저 확인하고 그대로 맞춘다.
2. **기능 동일, 표현만 모바일** — 기능을 빼거나 합치지 않는다. 모바일에선 표를 카드/KV로, 다단 폼을 위저드로 바꾸는 식으로 표현만 조정.
3. **데이터로 작업** — 화면 추가/수정은 `msm-leaf-data.js` 에서. 새 블록 표현이 필요할 때만 `msm-leaves.jsx`(렌더러) + `msm-modules.css`(스타일)를 건드린다.
4. **스타일 토큰 재사용** — 색은 CSS 변수(`--accent`, `--success`, `--danger`, `--warn`, `--z-50~900`)와 `msmTone()` 사용. 새 색 임의 도입 금지.
5. **JSX 규칙** — 컴포넌트 간 공유는 파일 끝에서 `Object.assign(window, {…})`. 전역 `const styles` 금지(이름 충돌). 인라인 스타일 또는 고유명 객체 사용.
6. **숫자/금액** — `font-feature-settings:"tnum"` 적용된 클래스(.lf-kv 등) 사용, 천단위 콤마.
7. **터치 타깃** ≥ 44px, **본문 글자** ≥ 13px. 표 라벨 열은 줄바꿈 허용, 값 열은 `nowrap`.
8. **검증** — 수정 후 콘솔 에러 0, iOS·Android 양쪽에서 레이아웃 확인.

---

## 7. 자주 하는 작업 레시피

- **상위 메뉴에 탭 추가**: 해당 `LEAF[id].tabs` 배열에 `{label, cnt?, blocks:[…]}` 추가.
- **목록 항목을 상세로 연결**: 그 `list` 행에 `nav:'<상세 id>', params:{…}` 추가 → `LEAF['<상세 id>'] = { title, build(p){…} }` 정의.
- **버튼으로 폼 열기**: `btns:[{t, ic, primary, nav:'<폼 id>'}]` → `LEAF['<폼 id>'] = { title, blocks:[{form\|wizard …}] }`.
- **신규 등록 위저드**: `hr-member-new` 를 템플릿으로 복사해 steps/fields 수정.
