현재 모바일 문제점 (추정)

  • 96장 화면 대부분이 데스크톱 전제 — 좁은 화면에서 좌우 스크롤·축소 필수
  • OP체크·근태 체크인은 현장 모바일 사용이 핵심인데 모바일 UX 부재
  • 테이블·다중 패널·복잡 폼은 모바일에서 사용 불가 수준
  • 터치 타깃 44px 미만, 햄버거 메뉴 5뎁스 이상

개선 방향

  • Mobile-first 우선순위 화면 식별 — 현장형(OP체크·출퇴근·할일·결재·게시판) vs 사무형(급여·관리자) 분리
  • 반응형 브레이크포인트 3종 — Mobile 360 / Tablet 768 / Desktop 1280
  • 같은 데이터, 다른 레이아웃 — 테이블 → 카드, 다중패널 → 단일패널 + 시트, 사이드바 → 바텀탭
  • 핵심 14개 화면은 PC·Mobile 양쪽 mockup 필수 제작

추가 개선 대상 발견 — 업무공유

📋 회사·팀별 할일·업무공유 (게시판 내 별도 메뉴)

라벨링 96장 외 발견된 화면. 회사/팀 단위 업무 자료·인수인계·할일을 공유하는 영역으로, 라벨 #24(자유게시판)와 별개의 핵심 협업 도구. 다인 협업 흐름이 끊기고 정보가 분산되는 사용성 문제 다수.

현재 발견된 사용성 이슈

  • 3분할 레이아웃 정보 단절 — 회사·팀 선택 패널 / 자료 목록 / 상세 보기가 가로로 나란히 배치되어 모바일에서 사용 불가, PC에서도 패널 폭이 좁아 가독성 저하
  • 분류 체계 혼란 — "업무자료/업무 인수인계" 카테고리 + "신규직원/기존직원/전체직원" 대상 + "회사/팀" 선택이 동시에 작용. 어디서 어떤 글이 보이는지 불명확
  • 팀 할일이 자료 하단에 매몰 — "외래팀 팀별 할일"이 자료 상세 페이지 하단에 묶여 있어, 할일만 따로 확인하려면 자료를 클릭해야 함
  • 0건 할일 vs 8건 인수인계 vs 10건 자료 — 우상단 카운트가 따로 표시되지만 어떻게 필터링하는지 직관적이지 않음
  • 등록 폼이 상세 화면에 인라인 노출 — 자료를 보던 사용자가 할일 등록 폼을 헷갈리게 됨

개선 방향

  • 3분할 → 마스터-디테일 구조 — 좌측 목록 + 우측 상세 (회사·팀은 상단 필터로 흡수). 모바일에서는 자연스럽게 목록↔상세 전환
  • 탭으로 분리 — 자료 / 인수인계 / 팀 할일을 동등한 탭으로 분리. 카운트는 탭 옆에 배지
  • 팀 할일을 독립 영역으로 승격 — 자료 하단이 아닌 별도 탭/페이지. 자료와 연결은 "관련 자료" 링크로
  • 현재 컨텍스트 강조 — "박철홍정형외과 · 간호부 · 외래팀" 빵부스러기를 상단 고정
  • 📱 모바일 — 카드 리스트 + 풀스크린 상세 + 바텀 시트 폼

→ Phase 3 우선순위 그룹에 ⑦ 업무공유 협업센터 신규 추가. 현행 1개 화면이지만 협업 핵심이므로 PC·Mobile 양쪽 mockup 필수.

리스크 & 가정

최대 리스크 — 도메인 검증 부족 퇴원심사·OP체크·급여 등 의료/HR 특화 워크플로우는 사용자 인터뷰 없이 통합하면 실제 업무를 깰 위험. Phase 1 종료 시점에 현장 검증 1회 필수.
마이그레이션 비용 기존 사용자 매뉴얼·교육자료·즐겨찾기·딥링크가 모두 영향받음. Phase 2 산출물에 구→신 매핑표 포함.
병행 개발 충돌 리디자인 진행 중 신규 기능이 추가되면 통합 매트릭스가 무효화. 8주간 신규 화면 추가 보류 협의 필요.
📱 모바일 사용 패턴 데이터 부재 어느 화면이 실제로 모바일에서 많이 쓰이는지 객관적 데이터가 없으면 Phase 1의 "Mobile First 그룹" 분류가 추측에 머무름. 가능하면 GA/로그 데이터 또는 사용자 인터뷰로 검증.

지금 결정해주실 사항

  1. 전체 8주 스케줄로 진행할지, Phase 1만 먼저 받고 검토 후 진행할지 — 매트릭스만 먼저 받아보시고 결정하는 안을 권장
  2. Phase 3 우선순위 그룹 6개 중 가장 시급한 1~2개 — 가장 임팩트 큰 곳부터 mockup 진행
  3. 현장 검증 인터뷰 가능 여부 — 퇴원심사·OP체크 실사용자 1~2명 30분씩 인터뷰 가능한지
  4. 최종 산출물 형태 — HTML 인터랙티브 프로토타입 / Figma 핸드오프 / 개발 가능한 React 코드 중 선호
  5. 채팅 메뉴 처리 — 라벨 0장이지만 메뉴에는 존재. 별도 라벨링 필요한지 / 범위 제외인지
  6. 📱 모바일 사용 비중 데이터 제공 가능 여부 — 어느 화면이 실제 모바일에서 많이 쓰이는지 로그·통계가 있다면 Phase 1 정확도가 크게 올라감
  7. 📱 모바일 앱 형태 — 반응형 웹 / PWA / 네이티브앱(별도 개발) 중 어디까지 책임 범위인지
