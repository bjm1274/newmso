## 패턴 1 — 상태전이 통합 (State-Transition Consolidation)

### 적용 화면
`#08` OP체크 메인 · `#09` 환자정보 · `#10` 준비완료 · `#11` 수술시작 · `#12` 수술완료

### Before / After
| 구분 | 화면 수 |
|---|---|
| Before | 5장 (상태별 별도 화면) |
| After  | **1장** (`OP-01` — 실시간 보드) |

### 핵심 UX 패턴 설명
현재 OP체크는 환자의 수술 상태(대기→준비완료→수술시작→수술완료)가 바뀔 때마다 별도 화면으로 이동하는 구조다. 이를 **단일 실시간 카드 보드**로 통합한다. 각 환자 카드는 현재 상태를 색상·아이콘으로 표시하며, 카드 탭/길게 누름으로 인라인 액션(상태 전진, 메모 입력)을 수행한다. 상태 전환은 화면 이동 없이 카드 애니메이션으로 처리한다. 실시간 채널(Supabase Realtime)은 단일 채널로 통합하여 API 호출 최소화(K8 준수).

### 모바일 변형
- 375px: 카드 리스트 뷰, 풀스크린 스와이프로 상세 열기
- 바텀시트로 인라인 액션 노출
- 터치 타깃 ≥ 44px 필수

## 패턴 2 — 워크플로우 스텝 통합 (Workflow Step Panel)

### 적용 화면
`#17` 퇴원심사 목록 · `#18` 새심사(a) · `#19` 새심사(b) · `#20` 기본항목설정 · `#21` 템플릿목록 · `#22` 템플릿수정

### Before / After
| 구분 | 화면 수 |
|---|---|
| Before | 6장 |
| After  | **2장** (`DC-03` 심사 워크플로우 + `DC-04` 설정) |

### 핵심 UX 패턴 설명
퇴원심사는 목록(DC-03)과 새심사 진행(스텝 a→b)을 하나의 화면에서 처리한다. 목록 우측(PC) 또는 슬라이드업(모바일)으로 **사이드 패널 스텝**이 열리며, 스텝 1(기본정보 입력)→스텝 2(항목 평가)→제출 흐름을 단계 표시기(stepper)와 함께 안내한다. 설정 화면(DC-04)은 독립 탭으로 유지하되, 템플릿 목록·수정을 인라인 편집 또는 모달로 처리해 별도 라우트를 제거한다.

### 모바일 변형
- 375px: 목록 전체화면 → 심사 시작 시 바텀시트로 스텝 표시
- 스텝 이동은 "다음/이전" 버튼 + 스와이프 제스처 지원
- 임시저장 자동 지원(언마운트 시 draft 유지)

## 패턴 3 — 탭 통합 (Tab Consolidation)

### 적용 화면 그룹

| 그룹 | 화면 번호 | Before | After |
|---|---|---|---|
| 연차휴가 | `#35` `#36` `#37` `#38` | 4장 | `AT-02` 1장 (4탭) |
| 근태이상감지 | `#39` `#40` | 2장 | `AT-03` 1장 (2탭) |
| 경영분석 | `#76` `#77` | 2장 | `MG-05` 1장 (2탭) |
| 감사센터 | `#94` `#95` | 2장 | `AD-07` 1장 (2탭) |

### 핵심 UX 패턴 설명
동일한 데이터 도메인의 다른 뷰(목록/캘린더/신청/관리)를 **상단 탭 컴포넌트** 하나로 묶는다. 탭 사이 URL 파라미터(`?tab=calendar`)로 딥링크·북마크를 지원한다. 탭 수가 4개인 연차휴가는 스크롤 탭(overflow scroll)으로 처리하여 좁은 화면에서도 접근 가능하게 한다. 탭 전환 시 데이터는 캐싱하여 재요청 없이 즉시 표시(SWR `keepPreviousData` 활용).

### 모바일 변형
- 탭 바는 화면 상단 고정, 스크롤 가능
- 터치 탭 최소 너비 72px
- 세로 스크롤 콘텐츠와 독립적으로 스크롤

### 적용 화면 그룹

| 그룹 | 화면 번호 | Before | After |
|---|---|---|---|
| 경조사 | `#54` 관리 · `#55` 등록 | 2장 | `HR-04` 1장 |
| 마감보고 | `#14` 목록 · `#15` 생성 | 2장 | `DC-01` 1장 |
| 계약현황 | `#59` 현황 · `#60` 자동생성 | 2장 | `HR-08` 1장 |
| 결재양식 | `#91` 관리 · `#92` 편집 | 2장 | `AD-05` 1장 |

### 핵심 UX 패턴 설명
목록(마스터)과 단일 액션(디테일/생성)을 동일 화면에서 처리한다. PC(≥1024px)에서는 좌측 목록 + 우측 패널(2-column)로 동시 표시하고, 모바일에서는 목록 → 디테일 푸시 네비게이션으로 전환한다. "새로 만들기" 버튼은 목록 상단 FAB 또는 인라인 버튼으로 모달/패널을 열어 생성 폼을 표시한다. 생성 완료 후 목록을 낙관적 업데이트(optimistic update)로 즉시 반영한다.

### 모바일 변형
- 모바일: 목록 전체화면 → 항목 탭 → 디테일 슬라이드인
- 생성 폼은 바텀시트 또는 풀스크린 모달

## 패턴 5 — 설정 통합 (Settings Consolidation)

### 적용 화면
`#86` 운영설정 · `#87` 템플릿(a) · `#88` 템플릿(b) · `#89` 템플릿(c) · `#81` 회사관리 계약템플릿

### Before / After
| 구분 | 화면 수 |
|---|---|
| Before | 5장 (운영설정 4장 + 회사관리 계약템플릿 1장) |
| After  | **2장** (`AD-02` 운영설정+템플릿 라이브러리, `#89` 삭제 검토) |

### 핵심 UX 패턴 설명
운영설정 템플릿(a/b)과 회사관리 계약템플릿을 하나의 **템플릿 라이브러리 탭** (`AD-02`)으로 통합한다. 템플릿 종류(계약서·평가·인계·마감)를 세그먼트 컨트롤로 전환한다. 템플릿(c)는 사용 빈도가 극히 낮아 삭제 후 탭에 흡수를 검토한다(삭제 전 사용자 확인 필요). 각 템플릿의 편집은 슬라이드오버 패널로 인라인 처리하여 별도 라우트를 제거한다.

### 모바일 변형
- 설정 화면은 PC 전용으로 우선 설계
- 모바일에서는 읽기 전용 뷰만 제공, 편집은 PC 유도
- 단, 계약서 서명·확인은 모바일 지원 필수
