# 퇴원심사 워크플로우 — 수락 기준 (Acceptance Criteria)

Phase 3 그룹 ③ · `ops_discharge_review_list` / `ops_discharge_review_detail`

---

## 1. 화면 구성

| ID | 기준 | 검증 방법 |
|---|---|---|
| AC-01 | PC: 좌측 목록(360px) + 우측 상세 패널 스플릿뷰로 표시된다 | 1024px 이상 브라우저에서 확인 |
| AC-02 | Mobile: 목록 → 환자 카드 탭 시 풀스크린 상세로 전환된다 | 430px 이하 뷰포트에서 확인 |
| AC-03 | Tablet(768~1023px): 모바일 레이아웃이 최대 600px 폼 너비로 확장된다 | DevTools 에뮬레이터 확인 |

## 2. 목록 화면 (`ops_discharge_review_list`)

| ID | 기준 | 검증 방법 |
|---|---|---|
| AC-04 | 환자 카드마다 이름·나이·성별, 진료과, 병실, 퇴원 예정일, 상태 뱃지가 표시된다 | 목록 화면 육안 확인 |
| AC-05 | 상태 뱃지 색상: 대기=gray, 진행=blue, 완료=green, 반려=red | 각 상태 카드 확인 |
| AC-06 | 탭 필터(전체/대기/진행/완료/반려) 클릭 시 해당 상태 카드만 표시된다 | 각 탭 클릭 확인 |
| AC-07 | 검색 입력 시 환자명 또는 병실로 필터링된다 | 검색창 입력 테스트 |
| AC-08 | "새 심사 등록" 버튼 클릭 시 상세 패널(STEP 1)이 열린다 | 버튼 클릭 확인 |

## 3. 상세 화면 스텝 (`ops_discharge_review_detail`)

### 공통

| ID | 기준 | 검증 방법 |
|---|---|---|
| AC-09 | 스텝 인디케이터(1 기본정보 / 2 항목체크 / 3 결재)가 상단에 표시된다 | 상세 패널 확인 |
| AC-10 | 현재 활성 스텝이 파란색(--accent)으로 강조된다 | 각 스텝 전환 확인 |
| AC-11 | 완료된 스텝은 초록색으로 표시된다 | 스텝 완료 후 확인 |
| AC-12 | 스텝 탭 클릭 또는 이전/다음 버튼으로 스텝 전환이 가능하다 | 탭 클릭 + 버튼 클릭 테스트 |
| AC-13 | 스텝 전환은 페이지 이동 없이 클라이언트 사이드에서 처리된다 (JM2) | 네트워크 탭에서 요청 없음 확인 |

### STEP 1 기본 정보 (#17, #18, #19 흡수)

| ID | 기준 | 검증 방법 |
|---|---|---|
| AC-14 | 환자 번호, 이름, 진료과, 병실, 입원일은 읽기 전용으로 표시된다 | 필드 편집 불가 확인 |
| AC-15 | 퇴원 예정일은 편집 가능하다 | 날짜 수정 후 저장 확인 |
| AC-16 | 주요 진단명은 필수 입력(required) 처리된다 | 빈 채로 다음 단계 이동 시 오류 표시 확인 |
| AC-17 | 퇴원 사유 셀렉트박스에 5개 옵션이 표시된다 | 드롭다운 클릭 확인 |
| AC-18 | 오류 메시지는 `aria-live="polite"` 영역에 표시된다 (JM6) | 스크린리더 또는 aria 속성 확인 |

### STEP 2 항목 체크 (#19, #20, #21, #22 흡수)

| ID | 기준 | 검증 방법 |
|---|---|---|
| AC-19 | 체크리스트 항목마다 체크박스, 제목, 설명, 상태 뱃지가 표시된다 | STEP 2 화면 확인 |
| AC-20 | 체크박스 체크 시 상태 뱃지가 "미완료(gray)" → "완료(green)"로 즉시 변경된다 | 체크박스 클릭 테스트 |
| AC-21 | 진행률 카운터(`x / n 완료`)가 실시간으로 업데이트된다 | 체크 후 카운터 확인 |
| AC-22 | "템플릿 적용" 버튼 클릭 시 템플릿 선택 모달(PC) / 바텀시트(Mobile)가 열린다 | 버튼 클릭 테스트 |
| AC-23 | 템플릿 선택 후 "적용" 클릭 시 체크리스트 항목이 교체된다 | 템플릿 선택 후 목록 변경 확인 |
| AC-24 | 새 항목 이름 입력 후 "추가" 클릭 시 리스트 하단에 새 항목이 삽입된다 | 항목 추가 테스트 |

### STEP 3 결재

| ID | 기준 | 검증 방법 |
|---|---|---|
| AC-25 | 환자명, 퇴원 예정일, 체크리스트 진행률이 요약으로 표시된다 | STEP 3 화면 확인 |
| AC-26 | 결재선(간호사 → 의사 → 과장)이 표시된다 | 결재선 카드 확인 |
| AC-27 | 체크리스트 미완료 항목 존재 시 제출 시 경고 메시지가 표시된다 | 미완료 상태에서 제출 테스트 |
| AC-28 | 오류 메시지는 `aria-live="assertive"` 영역에 표시된다 (JM6) | aria 속성 확인 |

## 4. 접근성 (WCAG 2.1 AA, JM6)

| ID | 기준 | 검증 방법 |
|---|---|---|
| AC-29 | 모든 인터랙티브 요소는 키보드(Tab / Enter / Space / Esc)로 조작 가능하다 | 키보드만으로 전체 플로우 진행 확인 |
| AC-30 | 모든 입력 필드에 `<label>` 또는 `aria-label`이 연결되어 있다 | 소스 또는 axe 검사 |
| AC-31 | 모달/바텀시트 열릴 때 포커스가 내부로 이동하고, Esc로 닫힌다 | 키보드 테스트 |
| AC-32 | 색상 대비가 WCAG AA 기준(4.5:1 텍스트, 3:1 UI)을 충족한다 | Chrome DevTools 또는 Lighthouse |
| AC-33 | 모바일 모든 터치 타겟은 최소 44×44px 이상이다 | DevTools 레이어 확인 |
