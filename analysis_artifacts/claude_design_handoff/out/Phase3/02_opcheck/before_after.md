## 통합 전 (Before) — 5장 분리

| 화면 ID | 역할 | 문제점 |
|---|---|---|
| #08 OP체크 메인 | 환자 목록 나열 | 상태 없는 단순 목록, 필터 없음 |
| #09 환자 탭 | 환자 카드 탭 시 이동 화면 | 페이지 전환 발생 — 현장에서 느림 |
| #10 준비완료 | 준비완료 확인 별도 화면 | 화면 이동 1회 추가 |

| #12 수술완료 | 수술 완료 확인 별도 화면 | 화면 이동 1회 추가 |

총 화면 이동: 상태 전환 1회당 최대 4회 페이지 이동
현장 문제: 수술실에서 장갑 낀 손으로 여러 화면 이동 — 실수·지연 발생

## 통합 후 (After) — 1장으로

| 항목 | 개선 내용 |
|---|---|
| 화면 수 | 5장 → 1장 (`ops_op_check_board`) |
| 페이지 이동 | 최대 4회 → **0회** |
| 상태 전환 UX | 별도 화면 이동 → 카드 인라인 전환 (사이드 패널 / 바텀시트) |
| 실시간 전체 보기 | 없음 → 4가지 상태 전체를 1화면에서 파악 |
| 필터 | 없음 → 전체/대기/준비완료/수술중/완료 탭 필터 |
| 색상 스캔 | 없음 → 상태별 색상 인디케이터로 즉시 파악 |
| 모바일 UX | 페이지 네비게이션 → 바텀시트 패턴으로 터치 최적화 |
| 접근성 | 색상만 → 색상 + 아이콘 + 텍스트 3중 표시 |

## 상태 전환 플로우 (단일 화면 내)

```
대기 ──→ 준비완료 ──→ 수술중 ──→ 수술완료
  [카드 탭]   [패널/시트 버튼]   [패널/시트 버튼]   [패널/시트 버튼]
  = 사이드 패널 또는 바텀시트 내에서 전체 처리
  = 페이지 이동 0회
```

## 레이아웃 구조 비교

### PC (1280px)
| Before | After |
|---|---|
| 단순 리스트 테이블 | 4열 카드 그리드 (상태 섹션별 분리) |
| 카드 클릭 → 새 페이지 | 카드 클릭 → 우측 사이드 패널 슬라이드 |
| 상태 표시 없음 | 좌측 컬러 인디케이터 + 배지 + 아이콘 |
| 필터 없음 | 상단 상태 필터 칩 |

### Mobile (375px)
| Before | After |
|---|---|
| 리스트 + 페이지 이동 | 카드 리스트 + 바텀시트 (페이지 이동 없음) |
| 버튼 타깃 크기 미정 | 최소 48px 터치 타깃 보장 |
| 하단 네비게이션 없음 | 고정 바텀 네비게이션 (OP체크/스케줄/환자/내 정보) |
| 다크모드 미지원 | CSS 변수 기반 다크모드 완전 지원 |
