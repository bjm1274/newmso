# 관리자 중복/삭제/과호출 감사 보고서

작성일: 2026-04-30  
범위: 관리자 내부 삭제 기능, 삭제 후 잔존 코드, 중복 구현, 과도한 호출/구독으로 인한 성능 저하 가능성

## 1. 조사 방법

- `rg --files`는 현재 작업공간에서 `Access is denied`로 실패하여 PowerShell `Get-ChildItem`/`Select-String`, `git`, 인라인 Node 스크립트로 전수 스캔했다.
- 관리자 진입점은 `app/main/admin-menu-config.ts`, `app/main/기능부품/관리자전용.tsx`, `app/main/기능부품/관리자전용서브/*`를 기준으로 추적했다.
- 삭제된 tracked 파일 169개와 현재 `app`, `lib`, `tests`, `scripts`, `docs` 참조를 대조했다.
- Supabase 호출 밀집도는 `scripts/audit-supabase-hotspots.mjs`로 확인했다.
- `npx tsc --noEmit --pretty false`는 통과했다. 즉, 삭제 파일 때문에 즉시 깨지는 TypeScript import는 발견되지 않았다.

## 2. 핵심 결론

P0 즉시 장애급 문제는 발견되지 않았다. 다만 P1/P2급으로 정리해야 할 중복 삭제 경로와 과호출 지점이 있다.

가장 먼저 손봐야 할 영역은 세 가지다.

1. 채팅/팝업 삭제 기능이 관리자 여러 위치에 중복되어 있고, 삭제 범위가 서로 다르다.
2. 업로드 API와 재고 처리 로직이 거의 같은 코드를 여러 파일에 갖고 있어 정책 drift가 이미 발생했다.
3. 알림/채팅/시스템마스터센터가 Realtime 구독과 폴링을 동시에 많이 걸어, 사용자 체감 버벅임을 만들 가능성이 높다.

## 4. 삭제 파일/잔존 참조 상태

삭제된 파일 때문에 현재 빌드가 깨지는 활성 import는 발견되지 않았다. 다음 항목들은 삭제 파일 stem을 import하지만, 같은 이름의 디렉터리 `index.tsx`가 있어 TypeScript/Next 해석상 동작한다.

- `app/main/기능부품/마이페이지/index.tsx:6` -> `./출퇴근기록`은 `출퇴근기록/index.tsx`로 resolve된다.
- `app/main/기능부품/마이페이지/index.tsx:15`, `app/main/기능부품/조직도서브/조직도본문.tsx:14` -> `알림인박스/index.tsx`로 resolve된다.
- `app/main/기능부품/추가기능공통.tsx:133` -> `인계노트/index.tsx`로 resolve된다.

정리 후보:

- 명확성을 높이려면 위 import를 `./출퇴근기록/index`, `../알림인박스/index`, `./인계노트/index`처럼 바꿀 수 있다.
- 루트 `main/**/*` 삭제 파일은 `tsconfig.json`에서 제외된 레거시 복제본으로 보이며, 현재 앱은 `app/main/**/*`를 사용한다.
- `app/api/ai/roster-recommendation/route.ts` 삭제 API는 활성 코드/문서/테스트 참조가 발견되지 않았다.
- 루트 문서 `DATA_RETENTION_ANALYSIS.md`, `DEPLOY_GUIDE.md`, `INVENTORY_ADVANCED_GUIDE.md`, `INVENTORY_FIX.md`, `TOTAL_RECOVERY_SCHEMA.sql`은 `docs/` 아래 대체 파일이 있다.

## 5. 중복 코드 통합 후보

1. 삭제/정리 기능
   - 채팅: 데이터초기화, 시스템마스터센터 방 삭제, 메시지 개별 삭제가 서로 다른 삭제 정책을 가진다.
   - 팝업: 팝업 관리자 삭제 API와 데이터초기화의 직접 DB 삭제가 갈라져 있다.
   - 권고: destructive action은 모두 서버 API/service role 경로로 통합하고 감사로그를 남긴다.

2. 업로드 기능
   - board/chat signed upload plan, approvals upload 검증, popup upload 검증이 분산되어 있다.
   - 권고: 공통 `createUploadRouteHandler` 또는 `createSignedUploadPlan` helper를 만들고, 기능별 bucket/path/validation preset만 전달한다.

3. 재고 기능
   - `inventory-utils.ts`와 `inventory-transaction-utils.ts`가 출고/되돌림 로직을 중복 보유한다.
   - `inventory-workflow-utils.ts`의 워크플로우 helper도 `inventory-utils.ts`와 겹친다.
   - 권고: 실제 import되는 `inventory-utils.ts`를 기준으로 하나만 남긴다.

4. Supabase select column builder
   - `lib/*query-columns.ts`에 `buildXSelect(omittedColumns)` 패턴이 반복된다.
   - 현재 일부는 untracked/helper 상태라 실제 route에 연결되지 않았다.
   - 권고: 연결할 계획이면 공통 `buildSelectColumns(base, omitted)` helper를 만들고, 아니면 helper 파일을 제거한다.

5. 알림/푸시 상태 처리
   - `알림시스템.tsx`와 `알림푸시.ts`가 push 상태, init, retry queue, debug log 성격의 코드를 나눠 갖고 있다.
   - 권고: push service hook/helper로 분리하고 UI 컴포넌트는 상태 표시와 사용자 액션만 담당하게 한다.

## 6. 성능/버벅임 의심 지점

`scripts/audit-supabase-hotspots.mjs` 기준 Supabase 호출이 많은 테이블은 `staff_members`, `inventory`, `approvals`, `notifications`, `chat_rooms`, `payroll_records`, `push_subscriptions`, `work_shifts`, `audit_logs`, `messages` 순서였다.

특히 다음 경로는 실제 사용자 체감 지연 후보로 본다.

- 시스템마스터센터 운영대시보드: 30초마다 큰 집계성 요청을 반복한다.
- 시스템마스터센터 전체채팅: 목록과 메시지를 한 API에서 같이 가져오고, 자동 선택 때문에 초기 호출이 중복된다.
- 알림시스템: 다수 Realtime 채널, 초기 보강 조회 중복, 10초/30초/60초 폴링이 동시에 존재한다.
- 메신저: 전역 메시지 채널, 선택 방 채널, 방 목록 bridge, 15초 fallback refresh가 겹친다.
- 데이터초기화: destructive delete를 클라이언트에서 순차 실행하므로 UI 대기와 부분 실패 위험이 크다.

## 7. 권장 실행 순서

1. P1 채팅 삭제 통합
   - `데이터초기화.tsx`의 직접 삭제를 제거하고 `app/api/admin/system-master/route.ts` 또는 새 `app/api/admin/cleanup/chats`로 통일한다.
   - 메시지 개별 삭제도 서버 경로로 옮기고 soft delete/hard delete 정책을 화면에 명확히 분리한다.

2. P1/P2 시스템마스터센터 호출 분리
   - `scope=chats`를 rooms/messages로 분리한다.
   - `scope=operations`는 서버 캐시와 SQL 집계로 바꾼다.

3. P2 알림/메신저 구독 다이어트
   - 알림 초기 보강 조회 중복 제거.
   - Realtime 정상 연결 시 fallback poll 비활성화.
   - `user.permissions` 의존성을 stable key로 바꿔 재구독을 줄인다.

4. P2 업로드 공통화
   - board/chat/approvals/popup upload를 공통 builder로 묶는다.
   - 결재 업로드의 50MB content-length 제한과 200MB video 정책 충돌을 먼저 결정한다.

5. P2/P3 고아 코드 정리
   - `inventory-transaction-utils.ts`, `inventory-workflow-utils.ts`, 근태/근무표/급여 신규 untracked 모듈의 연결 여부를 결정한다.
   - 권한 UI와 주석/문서를 현재 메뉴 구조로 정리한다.

## 8. 검증 결과

- TypeScript: `npx tsc --noEmit --pretty false` 통과.
- Supabase hotspot 스캔: `node scripts/audit-supabase-hotspots.mjs` 실행 완료.
- 삭제 파일 활성 import: 즉시 깨지는 P0/P1 참조 없음. 일부 stem import는 `index.tsx` 대체로 resolve됨.

## 9. 이번 보고서에서 코드 수정하지 않은 항목

이 문서는 감사 보고서만 추가한다. 실제 삭제 로직 통합, API 분리, 폴링 축소, 고아 코드 제거는 별도 작업으로 진행하는 것이 안전하다. 현재 작업트리에 변경/삭제/신규 파일이 매우 많으므로, 기능 코드 정리는 우선순위별로 작은 PR 단위로 나누는 것이 좋다.
