## D 중복

### D-1 [높음] `게시판공통.ts` ↔ `게시판-view-utils.ts` 대규모 중복 + **동작 분기(divergence)**
두 파일이 다음 함수/타입을 **거의 동일하게 중복 정의**한다:
`buildSelectColumns, inferAttachmentType, extractAttachmentMetaFromContent, buildAttachmentMetaContent, normalizeScheduledPublishAtValue, formatScheduledPublishInputValue, buildScheduleTimeValue, normalizeScheduleDateValue, normalizeScheduleTimeValue, isScheduleBoardType, extractScheduleMetaFromContent, buildScheduleMetaContent, extractBoardMetaFromContent, buildBoardMetaContent, normalizeBoardPost, isScheduledNoticePending, getMissingBoardPostColumn, isMissingBoardReadStorageError, normalizeBoardPostStatus, getBoardStatusTone, runBoardPostMutation, BOARD_POST_STATUSES` + 모든 Row 타입.

그런데 **구현이 미묘하게 다르다** — 같은 이름·다른 동작:
- `buildScheduleMetaContent(chartNo, meta)`
  - 게시판공통.ts:286 → `const metaPayload = { chartNo, ...meta }; return PREFIX+JSON+SUFFIX` (**가시 텍스트 없이 메타 블록만 반환, chartNo가 화면에서 사라짐**)
  - 게시판-view-utils.ts:272 → `return chartNo + '\n' + PREFIX+JSON(meta)+SUFFIX` (chartNo를 본문으로 표시)
- `normalizeScheduleTimeValue`
  - 게시판공통.ts:253 → 빈 문자열 가드 없음, `^(\d{2}):(\d{2})` 캡처
  - 게시판-view-utils.ts:238 → `if(!raw) return ''` 가드 있음, `^(\d{2}:\d{2})` 단일캡처
- `normalizeBoardPost` — view-utils만 `schedule_meta_embedded`/`schedule_meta_legacy_missing` 필드 부여 & `typeof === 'boolean'` 정밀분기. 게시판공통판은 `Boolean(post.x ?? meta?.x)` 단순분기 → **surgery_* 체크값이 두 경로에서 다르게 정규화됨**.
- `normalizeBoardPostStatus` — 게시판공통은 BOARD_POST_STATUSES에 없으면 '게시중' 강제, view-utils는 임의 문자열 통과.
- `getMissingBoardPostColumn`/`isMissingBoardReadStorageError` — 게시판공통은 `message`만, view-utils는 `code(42P01/42703/42P10)+details+hint`까지 검사.

근거(사용처 분기):
- `게시판.tsx:27-64` 상수는 `게시판공통`에서, 함수는 `게시판-view-utils`에서 import.
- `app/main/모바일/게시판/data-hooks.ts:17-24` 는 `normalizeBoardPost`/`buildAttachmentMetaContent`를 **게시판공통**에서 import → **모바일과 PC가 서로 다른 normalize 로직 사용**.

심각도: 높음. 조치: 한 파일을 정본으로 통합(권장: 함수는 게시판-view-utils, 상수는 게시판공통 유지 또는 단일 `게시판공통.ts`로 병합)하고 다른 쪽은 re-export만. 모바일/PC가 동일 normalize를 쓰도록 강제.

## SEC 보안
- SEC-1 [중간] **익명소리함 본문이 클라이언트로 먼저 전송된 뒤 화면에서만 숨겨짐**. `게시판.tsx:464-497`: `board_posts` 전체 fetch 후 `:488-491` `if(!isAdmin) setPosts([])`. 비관리자도 네트워크 응답에는 익명글 전문이 담겨 옴(DevTools로 열람 가능). 조치: 서버측(라우트/RLS 대응)에서 board_type='익명소리함' 비관리자 필터링.
- SEC-2 [중간] 업로드 **signed-URL 직접 PUT 경로는 magic-byte 검증을 우회**. `app/api/board/upload/route.ts`: formData 폴백 경로만 `validateKnownFileContentType`(:264) 실행. JSON(signed-url) 경로(`createSignedUploadPlan` :181)는 size·확장자만 검증하고 실제 바이트 미검증 → 클라이언트가 mimeType만 image로 보내고 임의 바이트 PUT 가능. 1차 업로드 경로가 바로 이 경로(`게시판업로드.ts:106 uploadBoardAttachmentFile`). 조치: 직접 업로드 후 서버 검증 or 콘텐츠 타입 강제.
- SEC-3 [낮음] MIME **allowlist 부재**. `validateUploadTarget`(route.ts:118)은 image/video는 무조건 통과, 그 외 50MB 이하면 통과 → `.svg/.html` 등 허용. 단 첨부는 R2 도메인에서 `<img src>`/다운로드로만 노출돼 XSS 직접 실행은 어려움(SVG via img는 스크립트 미실행). 의심 수준. 조치: 확장자 allowlist 권장.
- SEC-OK: 게시글/댓글 본문은 모두 JSX 텍스트노드(`{selectedPost.content}` :3111, `{c.content}` :3191/:3219)로 렌더 → React 자동 이스케이프. **dangerouslySetInnerHTML 없음**(게시판 파일 전체 Grep 0건). XSS 안전.
