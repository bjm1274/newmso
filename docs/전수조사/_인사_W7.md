## ★특별임무 결론

### 1. 계약서 미리보기/생성 HTML 렌더 XSS — **양호 (취약점 없음)**
- 인쇄용 HTML 빌더 `lib/contract-body-print-html.ts`(`esc()` line 7-14, 모든 동적값 `esc()` 통과), `lib/contract-template-closing.ts` `buildClosingPrintHTML`(`escapeHTML()` line 189-195, 모든 row/seal/signature 통과) → 정상 이스케이프.
- React 컴포넌트(`계약서본문블록.tsx`, `계약서마무리블록.tsx`, `LaborContractViewer.tsx`)는 모두 `{값}` JSX 텍스트 렌더 → React 자동 이스케이프.
- 유일한 `dangerouslySetInnerHTML`은 `계약서양식편집.tsx:214`인데, `escapeHtml()`(line 94-95)로 먼저 이스케이프 후 `{{변수}}`만 `<mark>` 치환 → **안전**.
- (경미) `전자서명모달.tsx`의 `agreementsSection`/`confidentialitySection`(line 336-376)에서 `${user?.name}`이 이스케이프 없이 인쇄 HTML에 삽입됨. 단, 본인 이름이 본인 클라이언트가 여는 `window.open` 인쇄창에 들어가므로 self-XSS 수준(저위험). 일관성·방어적으로 esc 권장.

### 2. 전자서명 데이터 저장 보안 — **PII/평문 우려**
- 서명 이미지(base64 PNG)는 `employment_contracts.signature_data`에 평문 저장(마이페이지 `handleSignComplete` line 273).
- 동시에 서명 이미지가 **3중 임베드된 전체 통합 HTML**(본문+동의서+비밀유지서약서, `fullContractHTML`)이 `document_repository.content`에 평문 저장(line 308-315). 즉 서명 + 직원 주소/연락처 PII가 일반 문서보관함 테이블에 그대로 들어감.
- `전자서명패드.tsx` 안내문구(line 147-149) "암호화되어 분산 저장"은 **사실과 불일치**(실제로는 평문). 허위 고지.

### 3. 계약관리 vs 계약서자동생성 — **중복/별개 시스템 공존(Q)**
- 두 컴포넌트는 **완전히 다른 테이블/플로우**: `계약관리.tsx`→`employment_contracts`(전자서명 워크플로우, 정본), `계약서자동생성.tsx`→`generated_contracts`(단순 insert+인쇄, 별개).
- 기능적으로 "근로계약서 생성"이라는 동일 목적의 두 경로가 공존 → 사용자 혼란·데이터 분산. 단 코드 중복(D)은 아님.

### 4. employment_contracts 테이블 정합성 — **타입 불일치 + 컬럼 환상**
- 정본 `employment_contracts.staff_id`는 `text`이고 `staff_members.id`도 `text`(schema.ts:701, 1999). 그러나 `계약관리.tsx`/`계약서명단.tsx`는 staff id를 **number**로 취급(`useState<number[]>`, `Number(key)`, `c.staff_id === selectedStaffId`). 문자열 PK와 number 비교 → `===` 불일치 잠재 버그.
- `계약관리.tsx`의 optional 컬럼 목록(line 50-61: `conditions_applied_at`, `contract_start_date`, `shift_id` 등)은 정본 `employment_contracts` 스키마에 **존재하지 않음**(schema.ts:699-730엔 `start_date`만 있고 `contract_start_date`/`conditions_applied_at`/`shift_id` 없음). `withMissingColumnsFallback`로 무음 폴백 처리 중이나, 정본/코드 드리프트.

### T (타입)
- **[높음] staff id text vs number** `계약관리.tsx:23,25,134-135,489 / 계약서명단.tsx:6-7,38,72-76` — 정본 PK는 `text`인데 number로 모델링. `staff.id === selectedStaffId`(number===number 가정) 및 `staff_id: staffId`(number) upsert가 text 컬럼과 충돌 가능.
