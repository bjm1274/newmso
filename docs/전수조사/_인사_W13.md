# 모바일 인사관리 전수조사 (W13)

조사일: 2026-05-29
대상: `app/main/모바일/인사관리/` 17개 파일 + 정본 스키마 `lib/db/schema.ts` 대조
런타임 경로: `@/lib/supabase` → `d1Client`(`lib/d1-supabase-compat.ts`) → `/api/d1/query|mutate` → Cloudflare D1.
즉 모든 `supabase.from('x')` 은 D1 SQL 로 실행되며, **존재하지 않는 테이블/컬럼은 SQLite "no such table/column" 에러를 던지고, 본 모듈 훅들은 전부 try/catch 로 그 에러를 삼키고 빈 배열로 폴백** → 화면은 "내역 없음" 으로만 보이는 무음 기능불능 상태.

## 상세 발견

### S — 문법/런타임 (무음 기능불능) — 위 "미존재 목록" 1~9 가 본 분류의 핵심
가장 심각. D1 정본과 옛 Supabase 스키마 불일치로, 다음 화면이 **사용자에게 에러 없이 빈 화면**으로 나타남:
- 복지(경조사·면허) / 구성원(교육·자격) / 인사발령 / 급여명세서 / 팀 근태이상 / 계약문서(계약 탭) / 근태조정신청(INSERT)

대표 인용:
- `data-hooks.ts:551-553`
  ```ts
  .from('notifications')
  .select('title, body')
  .eq('staff_id', staffId)   // notifications 에 staff_id 없음 → user_id 여야 함
  ```
  이 쿼리가 에러 나면 `Promise.all` 전체가 reject → catch(587) → `setSlips([])`. **급여명세서 기능 전체가 죽음.** (가장 높음)
- `data-hooks.ts:419-420`, `구성원.tsx:261-262`: `from('licenses')` → 정본 `staff_licenses`.
- `발령탭.tsx:71`: `from('staff_appointments')` → 정본 `personnel_appointments`.
- `근태조정신청.tsx:62-66`: `table: 'attendance_adjustments'`, payload `target_date/adjustment_type/note` → 정본 테이블 `attendance_corrections`, 컬럼 `attendance_date`/`original_date`/`correction_type`/`reason`. 테이블·컬럼 모두 불일치.

### E — 에러처리
1. **무음 폴백 일괄**: 위 모든 훅이 `catch → setX([])`. 스키마 오류와 "실제 데이터 없음"이 사용자/개발자에게 구분 불가. (`data-hooks.ts` 전반, `계약문서.tsx:209`, `발령탭.tsx:94`)
2. `data-hooks.ts:933-948` 의 attendances update 폴백은 `late_minutes` 컬럼 부재를 의도적으로 `console.warn` 처리하나, 정본에 컬럼이 영구 부재이므로 폴백이 "정상 경로"가 됨 — 사실상 분 단위 보정 기능이 항상 누락.
3. `구성원등록.tsx:109-132`: insert 결과 검증은 있으나, `staff_members.employee_no`/`company`/`company_id` 가 정본에서 **NOT NULL**(schema 2000,2002 / company_id 는 nullable)인데 payload 에 `employee_no`·`company` 누락 가능(emp 공란 시 employee_no 미포함, company 아예 안 넣음) → INSERT 가 NOT NULL 제약으로 실패. (SEC/S 와도 연결)

### SEC — 보안(PII·권한)
1. `구성원등록.tsx:95-113`: `staff_members` INSERT 를 모바일에서 직접 수행. 주석(13행)은 "권한 정책상 PC에서만"이라 하나 실제로는 `enqueueSupabaseMutation` 으로 직접 insert. 권한 가드(role/permissions) 없음 — 누구나 폼 도달 시 직원 생성 시도 가능. (RLS 부재 환경에서 위험; 높음)
2. `구성원.tsx`/`발령탭.tsx`/`data-hooks useWelfareBundle`: company 필터가 `company && company !== '전체'` 일 때만 적용. `company` 가 undefined/'전체' 면 **전 회사 직원·면허·발령 PII 노출**. 모바일 일반 직원이 company 없이 진입 시 타 회사 데이터 조회 가능.
3. `data-hooks.ts:806-813` 등 `notifications.insert({ user_id: targetStaffId, ... read_at:null })`: 권한 체크는 `canMutateTeamAbnormal` 로 클라이언트 가드만 존재. 서버 측 검증 없음(D1 직접 mutate). 클라 가드 우회 시 임의 직원에게 알림 발송 가능.

### Q — 유사기능 (데스크톱 인사관리와 중복)
1. 근태이상 사유요청/정상처리 로직(`data-hooks.ts:781~968`)이 PC `AbnormalWorkcenter.tsx` + `resolveStaffAbnormalRecords` 정책을 모바일용으로 재구현(주석 명시). 동일 비즈니스 규칙 2벌 유지 → 한쪽 스키마 변경 시 동기화 누락 위험(이미 late_minutes 불일치 발생).
2. 급여 발송분 판정 `resolveIssuedPayrollRecords`(`lib/payroll-records.ts`)는 공유하나, 모바일 `usePayrollSlips` 의 notifications staff_id 쿼리가 PC 와 컬럼 다름.
3. `복지.tsx formatDate` 와 `data-hooks.formatDateShort`/`계약문서.formatDateShort` 등 날짜 포맷 함수가 파일마다 중복 정의(아래 U 참조).
