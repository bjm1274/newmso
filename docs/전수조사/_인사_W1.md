## 특별임무 결론

**(1) workcenter-common 추출 품질: 양호.** 6종 워크센터 모두 `WorkcenterShell` + `WorkcenterKpiRow` + (탭형은)`WorkcenterTabBar` + `WorkcenterEmbed`(ErrorBoundary)를 공통 사용. KPI/탭/배너/백버튼/섹션이 단일 파일에 응집. 중복(D)은 공통 컴포넌트 자체가 아니라 **각 워크센터의 보일러플레이트**에 잔존(아래 D항목).

**(2) 라우팅:** 인사관리.tsx는 한글 레거시 id를 `REMOVED_MENU_FALLBACKS`로 영문 7종(member/attend/leave/payroll/welfare/docs + 내부 abnormal)으로 정규화 → `HrWorkcenterRouter`로 일원화. abnormal은 사이드바 미노출(근태 워크센터 내부 탭). 정상.

**(3) 6종 공통 패턴 중복(D):** `daysUntil`(KST) 함수가 DocsWorkcenter(L121)·WelfareWorkcenter(L118)에 **동일 복붙**. KPI fetch+countsReady+'-' 폴백 패턴, AbortController/alive 패턴도 반복. workcenter-common에 `daysUntilKST`/`useWorkcenterCounts` 추출 여지.

## 분류별 발견

### SEC 보안 / 무음 실패 (인사정보·SQL)

- **[높음] DocsWorkcenter.tsx:195-197, 225-230 — `approvals` 테이블에 없는 `form_type` 컬럼 SELECT.**
  정본 approvals 컬럼: `type, doc_type, doc_number…` — `form_type` 없음(별도 `approval_form_types` 테이블의 컬럼명과 혼동 추정).
  ```ts
  supabase.from('approvals').select('status, form_type'),
  ...
  const isCert = String(r.form_type || '').includes('증명서') ...
  ```
  → D1에서 컬럼 없는 SELECT는 SQL 에러 → `if (approvalsRes.error) throw` → catch가 삼킴(L257 `console.error`만) → **"발급 대기 증명서" KPI 항상 0 또는 전체 폴백 '-'**. 무음 오작동.

- **[높음/의심] WelfareWorkcenter.tsx:179-182 — `congratulations_condolences` 테이블이 정본 schema.ts에 없음.**
  schema.ts·supabase 마이그레이션·D1 스키마 덤프 어디에도 정의 없음(grep 확인). 단 경조사관리.tsx/data-hooks.ts 등 7개 파일이 동일 테이블 사용 → 라이브 D1에만 존재하고 schema.ts 미반영일 가능성. 실재하지 않으면 "이번달 경조사" KPI 무음 0. **정본 D1 실물 확인 필요(의심).**

- **[중] LeaveWorkcenter.tsx:86-194 — 클라이언트에서 직접 `leave_requests`/`staff_members` UPDATE·DELETE.**
  결재 승인/반려/삭제 시 `staff_members.annual_leave_total`을 클라이언트 supabase로 직접 갱신. 권한 검사 없음(인사관리 메뉴 권한에만 의존). RLS/서버 검증이 없으면 권한 우회로 타인 연차 조작 가능(의심 — 서버 라우트 권한 확인 필요).

- **[중] 인사발령관리.tsx:251-275 — 발령 등록이 `staff_members`(부서/직급/role) 직접 UPDATE.**
  `after_role` → `staff_members.role` 직접 갱신. role 변경은 권한 상승 경로. 클라이언트 측 권한 가드 없음.
