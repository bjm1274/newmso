## 🔴 심각도 높음 (8건)

### [SEC] ✅ 회수(recall) API가 제거된 Supabase 스택 사용 → 모바일 회수 전면 불능
- **위치**: `app/api/approval/recall/route.ts:14-20`
- **확인**: `import { createClient } from '@supabase/supabase-js'` + `NEXT_PUBLIC_SUPABASE_URL`/`SUPABASE_SERVICE_ROLE_KEY` + `auth.getUser()`. 프로젝트는 D1 컷오버 완료([lib/supabase.ts](../../lib/supabase.ts) "Supabase 런타임 제거")로 해당 env/세션 부재 → 항상 401/500.
- 추가: 같은 라우트가 `staff_members.user_id` 조회(✅ 정본은 `auth_user_id`) → actor 매핑 불가. `notifications`를 `read`/`approval_id`(미존재 컬럼) 쿼리.
- **조치**: D1 세션(`readSessionFromRequest`) + D1 드라이즐로 재작성.

### [SEC/Q] ✅ 모바일 첨부가 미존재 `approval_attachments` 테이블에 insert
- **위치**: `모바일/결재/AttachmentPicker.tsx:124`
- **확인**: `approval_attachments` 테이블 **부재**. PC는 `approvals.meta_data.attachments`에 저장([useApprovalSubmit.ts:602](../../app/main/기능부품/전자결재서브/useApprovalSubmit.ts:602)). `연차신청폼`도 첨부를 `meta_data`에 안 넣음 → **모바일 결재 첨부 기능 완전 무효**.
- **조치**: PC와 동일하게 `meta_data.attachments` 방식으로 통일.

### [SEC] 공문발송 권한 검증 부재 (상신 가능)
- **위치**: `ApprovalComposerView.tsx`(배지는 표시 전용) + `useApprovalSubmit.ts:523`(페이로드 존재만 검사) — 공문발송 권한 없는 사용자도 상신 가능. **조치**: 제출 시 서버 권한 검증.

### [D] ✅ 출결정정 로직·UI 전면 중복 + orphan (~500줄 죽은 코드)
- `AttendanceCorrectionSummary.tsx`(170, **ref 0 死**) + `AttendanceCorrectionDateSection.tsx`(331, ref 1) — 라이브는 `출결정정양식.tsx`(681줄 monolith). `withAttendanceCorrectionsFallback`/`REASON_BADGE`/problemDates 산출 ~150줄+UI 통째 중복. 분할 리팩토링 후 배선 안 함.
- **조치**: monolith를 분할 컴포넌트로 배선하거나 死 파일 삭제.

### [D] 거대 훅 (단일책임 위반)
- `useApprovalSubmit.ts`(774) `submitApproval` 한 콜백에 양식검증·재고리뷰·문서번호·insert·알림·보관함동기화 집중. `useApprovalComposeDraft.ts`(575)도 비대. (G2)
