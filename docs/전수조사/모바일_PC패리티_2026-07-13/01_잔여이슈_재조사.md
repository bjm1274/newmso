## 2. Critical (데이터·딥링크)

### C1. 반차 used 집계에 연도 필터 없음 (SSOT 잔여 과소)

**파일:** `lib/annual-leave-ledger.ts` — `calculateApprovedAnnualLeaveUsage`

- 반차 분기는 **year clip 없이 전 기간 +0.5**
- 연차 풀데이만 당해 clip
- 서버 `syncAnnualLeaveUsedForStaff`는 반차도 year clip

→ `computeAnnualLeaveSummary`의 `used = max(balance, staff, ledger)` 때문에  
**과거 반차 이력**이 있으면 UI 잔여가 **DB leave_balances보다 작아짐**.

**수정:** 서버와 동일하게 반차도 `clipDateRangeToYear` 후 합산.

---

### C2. `leave_balances.remaining_days` 무시 + max(used) 재계산

**파일:** `lib/annual-leave-summary.ts`

- select에 `remaining_days` 있으나 **미사용**
- used를 3소스 max → remaining 재계산

balances가 정본일 때 UI가 더 보수적(잔여 과소)으로 갈 수 있음. C1과 결합 시 Critical.

**수정 방향:**  
(A) year-scoped ledger 수정 후 balances.used 우선, 또는  
(B) recalculate 직후 `remaining_days` 직독 + 불일치 로그만.

### C3. 알림 → 전자결재: 문서 상세 미진입

**파일:** `내정보/알림탭.tsx` ~162–165

- `target.approvalId` **버림**
- `approvalView`만 setSubView (기본 한글 `'결재함'`)
- 모바일 결재는 `detail:<id>` / `inbox` 등만 인식 (`결재/index.tsx`)

### C5. staffId resolve 미적용 (다수 모듈)

**이미 적용:** 내정보 홈·연차, PC 마이페이지 KPI, 출퇴근(라우터 경유)

**미적용 (raw `user.id`):**

| 영역 | 대표 파일 |
|------|-----------|
| 인사 허브 staffId | `인사관리/index.tsx:109` |
| 결재 전체 폼 | `결재/index.tsx`, `연차신청폼`, `연차계획폼`, `연장근무`, `출결정정`, `일반기안` |

| 계약 서명 대기 | `MobileShell.tsx` `.eq('staff_id', user.id)` |

`getStaffLikeId`는 **UUID면 DB 검증 없이 통과**. auth UUID ≠ staff UUID 이면 내정보만 맞고 **인사·결재·알림·채팅 빈 화면/오기록**.

## 3. Major

### M1. 연차 사용 내역 연도 미필터

`history` / `approvedHistory`에 **year clip 없음**.  
KPI used는 당해(반차 제외 시) → **합계 ≠ 목록 합**.

### M2. `calculateLeaveDays` UTC 파싱

`new Date('YYYY-MM-DD')` UTC → 비-KST·연말 clip 시 일수 off-by-one 가능.  
date-only 문자열 산술 권장.

### M3. 전사 연차 대장 / 관리자 화면 staff only

- `연차관리자.tsx` — total−used only, E/C 없음

→ 개인 SSOT와 **관리 화면 숫자 불일치**.
