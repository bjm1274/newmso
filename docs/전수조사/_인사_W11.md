### SEC / S (스키마 불일치 → 무음 실패, 정확성 버그) — **최우선**
- **미지급수당알림.tsx L59-61**:
  ```
  const totalOT = staffAttend.reduce((s,a)=>s+(a.overtime_hours||a.ot_hours||0),0);
  const totalNight = staffAttend.reduce((s,a)=>s+(a.night_hours||0),0);
  const totalHoliday = staffAttend.reduce((s,a)=>s+(a.holiday_hours||0),0);
  ```
  정본 `attendances` 테이블(schema L180)에는 `overtime_hours/ot_hours/night_hours/holiday_hours` **컬럼이 없음**(work_hours_minutes만 존재). → 세 값 항상 0 → 알림이 절대 생성되지 않음. 기능 사실상 동작 불가.
- **미지급수당알림.tsx L63**: `p.meta_data?.overtime_pay` — 정본 `payroll_records`(schema L1540)에 `meta_data` 컬럼 없음(`meta_data`는 approvals 전용). select('*')라 런타임 에러는 없지만 항상 undefined.

### D 집계 중복 / 불일치
- **인건비추이분석 vs 총인건비예측**: 둘 다 "월별 인건비 추이" 12개월 막대차트를 인사대시보드통합에 나란히 렌더. 그러나 집계 기준이 다름 —
  - 인건비추이분석(L35): `r.net_pay` (실지급액 합) 사용.
  - 총인건비예측(L41): `getPayrollGrossPay(r)` = total_taxable+total_taxfree (지급총액) 사용.
  - → 같은 화면에 다른 숫자의 동일 제목 차트 2개. 사용자 혼란.
- **인건비추이분석은 `filterNonInterimPayrollRecords` 적용**(L29)하나 **총인건비예측은 미적용**(L33) → 중도정산(interim) 레코드 포함되어 총인건비예측 수치가 과대 계상됨.
- **급여대장월별요약 vs 급여대장내보내기**: 둘 다 payroll_records를 yearMonth로 조회해 합계 표시(요약/내보내기). 요약은 0-importer 죽은코드라 실제 충돌은 아니나 기능 중복.

### P 성능
- **인건비추이분석.tsx L22-38**: 12개월을 `for`루프 내 `await supabase.from('payroll_records')` **순차 12회 호출**(N+1 워터폴). `.in('year_month', months)` 단일 쿼리로 대체 가능. (총인건비예측은 L31에서 `.in(months)` 단일쿼리로 올바르게 처리 → 같은 코드베이스 내 상반된 패턴.)

### E 에러처리

- **총인건비예측.tsx L52**: 의존성 `[selectedCo]`만, `staffs` 누락 → staffs 갱신 시 회사필터 stale.
- **연차종합대시보드.tsx L132 submitLeavePlan**: approvals insert 결과(error) 미확인. 실패해도 성공 토스트 노출 가능.

### T 타입
