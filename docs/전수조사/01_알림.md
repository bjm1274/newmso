## 🔴 심각도 높음 (3건 — 우선 처리 권장)

### [S-1] 모바일 벨/알림함의 읽음 컬럼이 정본과 불일치 → 읽음 처리 미반영
- **위치**: `app/components/GlobalNotificationBell.tsx:254`, `app/main/모바일/내정보/알림.tsx:131,138,196`
- **근거**:
  - `GlobalNotificationBell.tsx:254` → `supabase.from('notifications').update({ is_read: true })`
  - `모바일/내정보/알림.tsx:138` → `.update({ read: true, is_read: true }).or('read.is.null,read.eq.false')`, 읽음 판정 `n.read ?? n.is_read`
- **확인 결과**: D1 정본 `notifications` 테이블 컬럼은 `read_at`만 존재 ([lib/db/schema.ts:1306](../../lib/db/schema.ts:1306)). `is_read`/`read` 컬럼 없음. 서버 정본 라우트도 `read_at` 사용 ([app/api/notifications/mark-read/route.ts:39](../../app/api/notifications/mark-read/route.ts:39)). `supabase`는 D1 compat 프록시 ([lib/supabase.ts:23](../../lib/supabase.ts:23)).
- **영향**: 두 모바일 화면의 읽음 처리가 `read_at`에 반영되지 않아, 다른 화면(알림센터/인박스/알림시스템)과 안읽음 카운트 불일치. 모바일 알림함은 `read_at`만 채워진 항목을 영원히 "안읽음"으로 표시.
- **권장조치**: 두 곳 모두 `update({ read_at: new Date().toISOString() })` + 읽음 판정 `read_at != null`로 통일.

### [D-1] 푸시 로직(init/send/status/플랫폼판별)이 `알림푸시.ts` ↔ `알림시스템.tsx`에 통째 중복 + 아이콘 경로 분기
- **위치**: `알림푸시.ts` 전체 ↔ `알림시스템.tsx:81~721`
- **근거**: `getPushClientPlatform`(알림푸시.ts:101 ↔ 알림시스템.tsx:261), `sendNotification`(알림푸시.ts:530 ↔ 알림시스템.tsx:648) 등 동일 본문 재정의.
- **확인된 부작용 (아이콘 경로 갈림)**:
  - `알림시스템.tsx:667` → `icon: '/sy-logo.png'`, `badge: '/badge-72x72.png'`
  - `알림푸시.ts:549` → `icon: '/sy-icon-512x512.png'`, `badge: '/sy-badge-72x72.png'`
  - 네 파일 모두 `public/`에 실존하나 **서로 다른 이미지** → 동일 알림이 코드 경로에 따라 다른 아이콘 표시(브랜딩 불일치).
- **권장조치**: 푸시 유틸을 한 곳(서브모듈)으로 통합, `알림시스템.tsx`가 import. 아이콘 경로 상수 1벌로 통일.

### [P-1] `알림센터`가 단일 폴링 설계를 따르지 않고 독자 10초 폴링 유지
- **위치**: `app/main/기능부품/알림센터.tsx:158`
- **근거**: `window.setInterval(() => { ... void fetchNotifications(); }, 10000)` + line 153 `erp-new-notification` 리스너로 동일 함수 중복 호출.
- **영향**: `알림시스템.tsx`는 `NOTIFICATION_LIST_UPDATED_EVENT` 단일 폴링 통합(JM2)을 표방하나 `알림센터`는 미구독·독자 폴링 → 중복 API 호출.
- **권장조치**: `알림센터`도 통합 이벤트 구독으로 전환, 독자 폴링 제거.
