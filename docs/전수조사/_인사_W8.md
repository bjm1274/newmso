## ★특별임무 답변

### 1. 면허자격증관리(802) 단일책임 여부 — △ 부분 위반
`면허자격증관리.tsx`는 (a) 면허 CRUD, (b) 직종 필터(job_categories/staff_job_categories fetch), (c) 보수교육 이수일(lastCEMap) 조회, (d) 보수교육 검토 모달 진입+pending 카운트까지 4가지 관심사를 한 파일에 담음. CRUD가 핵심이고 나머지는 표시 보조라 치명적이진 않으나, 802줄로 프로젝트 jm 원칙(~500줄)을 초과. 직종 필터 로직과 보수교육 카운트 로직 분리 권장.

### 2. 교육관리 vs 교육내역명단 vs 교육이수현황 중복(D) — 중복 아님(역할 분리됨)
- `교육관리.tsx`(EducationMain): 컨테이너. 알림 계산·요약 계산 후 자식에 props 전달.
- `교육이수현황.tsx`(EducationStatus): summary props만 받아 카드 렌더하는 순수 프레젠테이션(81줄).
- `교육내역명단.tsx`(EducationList): MatrixTable 기반 직원별 이수 편집 그리드.
→ 세 파일은 컨테이너/요약뷰/편집뷰로 책임이 갈려 **D 중복 아님**. 단, 교육관리와 교육내역명단이 둘 다 `getApplicableEducationItems`(deprecated)에 의존하는 Q 유사로직 존재(아래 D-3).

### 3. staff_licenses/education 테이블 정합성 — 1건 심각
`교육자격인사이동패널.tsx`가 `staff_certifications` 테이블을 조회(L12). 이 그룹의 다른 모든 면허 화면은 `staff_licenses`를 정본으로 사용. 두 테이블이 병존하여 데이터 분기(아래 D-1).

### 4. 자격면허대시보드 vs 면허자격증관리 중복 — Q 유사(의도된 분리지만 로직 불일치)
둘 다 `staff_licenses`를 읽지만 만료 임박 임계값/산출식이 서로 다름(아래 Q-1). 대시보드는 읽기·CSV·알림 전용, 관리는 CRUD 전용으로 역할은 분리됨. 그러나 동일 면허가 두 화면에서 **다른 상태로 표시**될 수 있어 사용자 혼란 가능.

### D-1 (높음) `staff_certifications` vs `staff_licenses` 테이블 분기

- 이 그룹의 모든 면허 화면(면허자격증관리, 자격면허대시보드, 교육관리)은 `staff_licenses`를 사용. `staff_certifications`(schema.ts:1936, 컬럼: name/issuer/issue_date/expiry_date)는 별도 테이블로, 면허자격증관리에서 등록한 자격증은 이 패널에 **표시되지 않음**. 정본을 `staff_licenses`로 통일하거나 마이그레이션 필요.

### D-2 (중간) job_categories / staff_job_categories fetch 3중 중복

### D-3 (중간) `getApplicableEducationItems`(deprecated) 의존 중복

## [Q] 유사기능 (3)

### Q-1 (높음) 면허 만료 상태 산출식 불일치 — 동일 면허가 화면마다 다른 상태
- `자격면허대시보드.tsx:51-64` `getLicenseStatus()`: `expiry_date`만 사용, 임계값 **30일**, 30일내=경고. `license_type`/`renewed_date` 무시 → 자동산출(법정 갱신주기) 미반영.
- `면허자격증관리.tsx`는 `computeLicenseStatus`(license-renewal-policy.ts:187) 사용: expiry_date 없으면 renewed/issued+법정주기로 산출, 임계값 **60일**.
- `교육관리.tsx:188` 면허 알림: 임계값 **90일**, URGENT=30일.
→ 동일 `staff_licenses` 레코드가 대시보드(30일·만료일 미등록 시 "미등록"), 관리(60일·자동산출), 교육관리알림(90일)에서 서로 다르게 분류됨. 임계값/산출 로직을 license-renewal-policy로 통일 권장.

### Q-2 (중간) 교육 항목 정의 소스 이원화
- 정적 상수 `EDUCATION_ITEMS`(education-types.ts) 기반: 교육관리·교육내역명단·교육이수현황.
- DB 테이블 `job_category_required_trainings` 기반: JobCategoryTrainingMatrix(교육관리 안에서 동시 렌더).
→ 같은 "법정 의무교육" 탭에서 정적 상수 매트릭스와 DB 매트릭스가 나란히 표시되어 항목 집합이 불일치할 수 있음.

### Q-3 (낮음) 이수 완료 판정 문자열 매칭 중복
- `education-utils.ts:138-145` `isEducationRecordCompleted` (완료/수료/이수/complete...) 와 `JobCategoryTrainingMatrix.tsx:194-203` (완료/이수/complete/done) 가 별개 구현. 판정 키워드 집합도 미묘하게 다름(전자는 '수료' 포함, 후자는 미포함).
