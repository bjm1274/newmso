## 0. 핵심 결론 (먼저 읽으세요)

급여정산 파이프라인은 **통상시급 산정 → 일할계산 → 자동 가산수당 → 비과세/과세 분리 → 4대보험·소득세 공제 → 저장/확정** 순으로 동작한다. 전 구간 정독 결과 **실지급액에 직접 영향을 주는 치명 결함 8건**을 확인했다. 가장 중요한 4가지:

1. **🔴 중도입사·중도퇴사자의 통상시급이 "일할 감액된 급여"로 계산된다.** → 그 시급으로 산정하는 연장/야간/휴일 가산수당이 **과소 지급**. (사용자 최우선 관심사와 직결)
2. **🔴 야간근로 0.5배 가산·휴일 8시간 초과 2.0배가 자동수당에 빠져 있다.** → 근로기준법 제56조 위반, 가산수당 과소.
3. **🔴 `other_taxfree`·야간/당직수당이 한도 없이 전액 비과세** 처리된다. → 소득세·4대보험 과소공제(원천징수 의무 위반).
4. **🔴 마감잠금이 급여정산 저장/확정을 전혀 막지 못한다.** → 잠금은 사실상 UI 장식, 확정 데이터 덮어쓰기 가능.

**교차검증으로 기각한 거짓양성도 명시한다(§5):** "국민연금 4.75% 과다공제"와 "지각차감 완전 무력화"는 **실제로는 정상/이미 수정됨**이다.

## 1. 사용자 관심축별 정리

### 축 ① 근무유형별 "실제 근무일" 산정

| 항목 | 상태 | 비고 |
|---|---|---|
| 일할계산 분모 | 역일수(그 달 28~31일) 사용 | 취업규칙상 허용 범위(법규 위반 아님). 단 항상 `Math.floor` 절사 |
| `employment_type`(정규/계약/일용/단시간) | **급여 계산에 미반영** | 컬럼은 존재하나 일용직 일급경로·단시간 검증 없음 (B-4) |
| 격일제(24h 교대) 월 소정근로시간 | **공식·전달 불일치** | 화면마다 통상시급 다름 (B-1, B-2) |
| 근무표(shift_assignments) 연동 | 조건부 동작 | 배정 없으면 자동수당·지각차감 0 (C-3) |
| 간호 3교대(nurse_schedules) | **급여 미연동** | 야간(N) 수당 전액 수기 입력 의존 (B-6) |

→ **"근무유형"이 급여 산식의 분기 조건으로 거의 쓰이지 않는다.** 모든 직원이 사실상 월급제 + 역일수 일할로 처리되며, 일용·단시간·교대의 특수성은 수기 입력으로 메운다.

### 축 ② 중도입사

- 입사월 = 정산월이면 `effectiveStart = 입사일`, `employedDays = 입사일~말일`, `prorated = floor(월액 × employedDays / 역일수)` → **일할 자체는 정상 동작**.
- **그러나 결정적 문제:** 이 prorate된 기본급·수당으로 **통상시급을 재계산**한다(🔴 A-1). 중도입사자는 통상시급이 깎여 연장/야간/휴일 수당이 과소.
- 1일 입사자도 `isMidMonthEmployed=true`로 처리되어 불필요한 "중도입사 일할" 뱃지 생성(🟡, 금액은 정상).
- 근태차감 기준은 일할 전 마스터 `base_salary`를 써서 중도입사 달 결근·지각 차감이 과대(🟠 A-2).

### 축 ③ 중도퇴사

- 퇴사월 = 정산월이면 `effectiveEnd = 퇴사일`로 클램핑 → 일할 정상.
- 통상시급·근태차감 문제는 중도입사와 동일하게 적용(A-1, A-2).
- **중간정산(퇴사 정산) 시 퇴직금이 근로소득 과세표준에 합산되어 근로소득세가 과다 징수**된다(🔴 F-2).
- 퇴직금 추정액이 화면 경로마다 다른 공식(최대 수십 배 괴리, 🔴 F-1).

### 축 ④⑤ 계산 로직·버그 → §2~§4 전체

## 2. 🔴 치명 (실지급액 오류 / 법규 위반) — 즉시 조치

### 🔴 A-1. 중도입사/퇴사자 통상시급이 일할 prorate된 금액으로 산정
- **위치**: `급여정산.tsx:181-227`, `급여정산-utils.ts:90-136`
- **현상**: `baseSalary = resolveAmount('base_salary', …)`는 중도입사 시 일할 감액된 값이다(181). 이 값을 그대로 `draftEntryForHourlyRate`(217-225)에 담아 `getRegularHourlyRate()`로 통상시급을 낸다(227). 통상시급은 **소정근로에 대한 1개월분 임금 전액** 기준이어야 하나, 분자가 일할 감액되어 시급이 비례 축소된다.
- **영향**: 중도입사/퇴사 달의 연장·야간·휴일 **자동 가산수당 과소 지급**. 예) 월급 300만, 7/15 입사(17일) → 통상시급 7,872원 vs 정상 14,355원, 연장 2h당 약 19,449원 과소.
- **수정**: `getRegularHourlyRate`에는 일할 이전 마스터 원액(`staff.base_salary` 등)을 넘기거나, 통상시급 계산 경로를 prorate와 분리.

### 🔴 C-1. 야간근로 가산(0.5배) 미적용 — 연장+야간 중복가산 누락
- **위치**: `급여정산.tsx:230`
- **현상**: `autoOvertimePay = round((mins/60) × 시급 × 1.5)`. 22:00~06:00 시간대 연장근로에 야간 가산 0.5배(합 2.0배)가 더해지지 않는다. 야간/연장 분리 집계 코드 없음.
- **영향**: 야간 연장근로 시간당 통상시급 0.5배 **과소** (근기법 56조).
- **수정**: 분(分) 적산 루프(549~)에서 22~06시 구간을 별도 `nightOvertimeMins`로 누적, `×2.0` 적용.

### 🔴 C-2. 휴일근로 8시간 초과 2.0배 미적용
- **위치**: `급여정산.tsx:231`, `524-526`
- **현상**: `autoHolidayPay = round(holidayHours × 시급 × 1.5)`. 8h 초과분 2.0배 구분 없음. 게다가 `holidayHours`에 소정근로시간만 누적되어 실근무 초과분이 반영되지 않음.
- **영향**: 휴일 8h 초과 근무 **과소 지급**.
- **수정**: `holidayHours8`/`holidayHoursOver8` 분리, 실근무시간(out-in) 기준 8h 경계 분할.

### 🔴 D-1. `other_taxfree`·야간/당직수당 비과세 한도 미적용 (전액 비과세)
- **위치**: `급여정산.tsx:717-722, 726`, `중간정산.tsx:356,391,392`
- **현상**: 식대·차량·보육·연구비는 `Math.min(…, 한도)` + 초과분 과세전환(meal_taxable 등)이 있으나, `nightDuty`와 `other_taxfree`는 한도·과세전환 없이 `total_taxfree`에 **전액** 합산된다. `total_taxable`(726)에 이 둘의 과세분이 빠져 있다.
- **영향**: `other_taxfree`/야간당직수당에 큰 금액이 등록되면 과세표준이 부당 축소 → **소득세·4대보험 과소공제**(원천징수 의무 위반). 의료기관 특성상 야간당직 수당이 고액인 경우 다수.
- **수정**: `TAX_FREE_LIMITS`에 `other`/`nightDuty` 한도(법정: 생산직·의료직 야간수당 연 240만 요건 등) 추가, 초과분 과세전환. 한도 미설정 시 보수적으로 전액 과세.

### 🔴 D-2. 건강보험 보수월액 상한 미적용
- **위치**: `payroll-deductions.ts`(calcStatutoryDeductions), `payroll-insurance-rates.ts:87`
- **현상**: 국민연금은 `NP_INCOME_FLOOR/CEILING` 상·하한이 적용되나(`payroll-insurance-rates.ts:84`), 건강보험은 `floor(과세소득 × 요율)`로 상한 없이 전액 부과.
- **영향**: 월 보수 약 1,200만원 이상 고소득자(원장·임원) **건강보험 과다공제**.
- **수정**: 건강보험·장기요양에 2026년 보수월액 상한 `Math.min` 적용.

### 🔴 E-1. 마감잠금이 급여정산 저장/확정을 차단하지 않음
- **위치**: `급여정산.tsx` 전역 (`payroll_locks` 조회 0건 — grep 확인), `persistSettlement`(~820)
- **현상**: 급여정산 컴포넌트는 `payroll_locks`를 한 번도 조회하지 않는다. `handleDraftSave`/`handleFinalize` 모두 잠금 확인 없이 upsert.
- **영향**: 마감 잠근 월에도 임시저장/확정 버튼이 살아 있어 **확정 데이터 덮어쓰기 가능**. 백엔드 RLS에도 lock 정책 없음 → 잠금이 순수 UI 장식.
- **수정**: `persistSettlement` 진입 시 `payroll_locks(year_month, company_name)` 확인 후 차단 + RLS 정책 추가.

### 🔴 F-2. 중간정산: 퇴직금을 근로소득 과세표준에 합산
- **위치**: `중간정산.tsx:393-407`
- **현상**: `totalTaxable = Math.max(0, …근로소득…) + severance`. 퇴직금이 근로소득 간이세액·4대보험 대상에 포함된다.
- **영향**: 퇴직소득은 소득세법 제22조 **분류과세** 대상. 근로소득에 합산 시 **소득세 과다징수**(퇴직금 수백만 × 6~15%).
- **수정**: `severance`를 `totalTaxable`에서 제외, 필요 시 퇴직소득세 별도 계산.

### 🔴 F-1. 퇴직금 추정 공식 3경로 불일치
- **위치**: `인사관리워크센터/payroll/payroll-fetch.ts:326` vs `lib/severance-pay.ts:8-10` vs `중간정산.tsx:372-373`
- **현상**: ① `payroll-fetch`: `floor(sal × tenure)` (`sal`=`staff.salary` 단위 불명, `tenure`=float 365.25) ② `severance-pay`: `dailyAvg × 30 × (workDays/365)` ③ 중간정산 DC식: `monthlyAvg × (workDays/365)`, 계수 30 없음.
- **영향**: 퇴직자 목록·중간정산·법정계산기가 **서로 다른 금액** 표시. `salary` 단위에 따라 최대 수십 배 오류. 정산서 분쟁 직결.
- **수정**: 전 경로를 `severance-pay.ts` 공유 함수로 통일, 365/365.25 일원화.

### 🔴 B-2/B-1. 격일제(교대) 통상시급 공식 의심 + 화면 간 불일치
- **위치**: `payroll-working-hours.ts:76-82`, `급여정산-utils.ts:131-135`
- **현상**: ① 격일제 월시간 공식이 연장시간을 `× 4.345 × 1.5`로 **분모에 산입**해 통상시급이 희석된다. ② `getRegularHourlyRate`는 `isAlternateDayShift` 인자를 안 넘겨 급여정산은 일반식, 급여상세는 격일제식 → **같은 직원 시급이 화면마다 다름**.
- **영향**: 격일제(24h 교대) 직원 통상시급 산정 불안정, 연장수당 추천 과소 가능. 의료기관 당직에 광범위.
- **수정**: 격일제 분모는 (소정+주휴)시간만으로 단일화, `isAlternateDayShift` 판별을 전 화면 공통 헬퍼로.

## 6. 권고 조치 우선순위

**P0 (실지급액·세무 직접 오류 — 다음 정산 전 수정):**
1. D-1 비과세 한도(`other_taxfree`·야간당직) 적용 — 소득세·보험 과소공제, 원천징수 의무
2. F-2 중간정산 퇴직금 과세표준 분리 — 근로소득세 과다징수
3. A-1 통상시급을 일할 이전 원액 기준으로 — 중도입퇴사자 가산수당
4. C-1·C-2 야간 0.5배·휴일 8h초과 2.0배 — 근기법 56조

**P1 (정합성·법규):**
5. E-1 마감잠금 연동(+RLS) / E-2 확정 보호
6. D-2 건강보험 상한 / F-1 퇴직금 공식 통일
7. E-4·E-5 record_type 유니크·조회 필터

**P2 (구조·정확도):**
8. B-1/B-2 격일제 통상시급 일원화, B-4 employment_type 반영, A-2/B-5 근태차감 기준 정정

**권고:** 통상시급·일할·가산·비과세·공제가 한 함수에 얽혀 있어 한 곳 수정이 다른 곳에 파급된다. **`payroll-deductions.ts`(공제 SSOT)처럼 "통상시급 산정 SSOT"와 "비과세 한도 SSOT"를 단일화**하고, 중간정산·급여상세·시뮬레이터가 모두 이를 호출하도록 리팩토링하는 것이 근본 해결책이다.
