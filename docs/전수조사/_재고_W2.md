### 1. 재고현황뷰.tsx (834줄) 단일책임 위반 — 핵심
파일의 약 절반이 **영구 비표시(`<div className="hidden">`) 블록 6개**로 구성되어 있다.
화면에 절대 렌더되지 않는데도 상태/핸들러/JSX가 모두 살아있다.

- L328-425: 컨트롤 바(검색·회사·부서·카테고리 select·새로고침·상태필터·StatPill) 전체 `hidden`
- L429-464: 긴급 알림 배너 전체 `hidden`
- L468-571: 공급신청 워크플로우(ops) 전체 `hidden`
- L575-615: 처리완료 히스토리 전체 `hidden`
- L620-646: 테이블 헤더(일괄 토글·정렬 버튼) 전체 `hidden`
- L752-772: 유효기간 센터(`<ExpirationAlert/>` 포함) 전체 `hidden`

→ **X 죽은코드**: 위 6블록과 그에 종속된 prop/상태(`statusFilter, setStatusFilter, searchKeyword,
viewCompany, selectedDept, categoryFilter, sortBy, showCompleted, expandedApprovalId, alertDismissed,
showExpiryCenter, isOpsUser, pendingApprovals, completedApprovals, workflowActionKey,
highlightedApprovalId, onSupply*, onOpenLinkedOrder` 등)는 사실상 사용되지 않음.
실제 렌더 경로는 메트릭 카드(L320-325) → 테이블 Grid(L671-684) → 일괄 액션바(L688) → 페이지네이션(L699) → 수정 모달(L775)뿐.
**결론: 단일책임 심각 위반. hidden 블록과 죽은 prop을 제거하면 ~834줄 → ~350줄 수준으로 축소 가능.**

### 3. 부서별물품장비현황 중복 진입 — 실제로는 "중복 아님 + 죽은 라우팅"

  → 즉 버튼 라벨("부서별 재고")과 실제 도착 화면(소모기록)이 불일치. (아래 Q-1)

### 4. 재고 수량 계산 정확성 — 대체로 정확, 1건 주의
- 공통 헬퍼 `getItemQuantity = quantity ?? stock ?? 0`, `getItemMinQuantity = min_quantity ?? min_stock ?? 0`
  (inventory-utils.ts L66-72). inventory 테이블은 quantity/stock/min_quantity/min_stock/safety_stock를 모두 보유.
  쓰기 시 quantity·stock, min_quantity·min_stock를 **쌍으로 동시 갱신**(재고현황뷰 L198-201, 재고실사 L99, 재고이관 L265/276)
  → 정합성 유지됨. **정확**.
- 주의(P/정확성): 재고현황뷰 L393 정상 카운트 = `length - lowStockCount - expiryCount`.
  재고부족 ∩ 기한임박 품목은 **이중 차감**되어 정상 건수가 과소(음수 가능). 단 해당 블록이 hidden이라 영향 적음.

### 5. inventory 테이블 정합성 — 양호, 단 unit/safety_stock 미사용
- inventory 테이블에 **`unit` 컬럼 없음**. 그러나 재고현황뷰 수정모달(L196,791)·Grid(L127)은 `unit`을 읽고 쓴다.
  saveEditItem(L201)에서 `unit: editForm.unit.trim()`을 update 페이로드에 포함 → **존재하지 않는 컬럼 쓰기**.
  D1 compat 프록시가 미존재 컬럼을 무음 누락/실패시킬 수 있음(과업 경고 사항). (아래 T-2)
- `safety_stock`(L853) 컬럼은 스키마에 있으나 어느 화면에서도 읽지/쓰지 않음 → 사실상 죽은 컬럼(참고).
