## 분류별 발견

### D — 중복

**[D-1] useChatTypingD1 훅 이중 호출 (높음)**
- `useChatRealtimeBridge.ts:135` 에서 `useChatTypingD1({ selectedRoomId, effectiveChatUserId, userName, setTypingUsers, typingClearRef })` 호출 → `emitTypingState` 반환.
- `메신저.tsx:1149` 에서 **동일 훅을 같은 setTypingUsers/typingClearRef로 다시 호출** → `emitTyping, handleTypingInput` 반환.
```
// useChatRealtimeBridge.ts:135
const { emitTyping: emitTypingState } = useChatTypingD1({ selectedRoomId, effectiveChatUserId, userName, setTypingUsers, typingClearRef });
// 메신저.tsx:1149
const { emitTyping: emitTypingState, handleTypingInput } = useChatTypingD1({ selectedRoomId, effectiveChatUserId, userName: user?.name, setTypingUsers, typingClearRef });
```
- 결과: 한 화면에서 타이핑 GET 폴링(2.5s)이 **2개 동시 실행** → API 호출 2배, 동일 setTypingUsers를 두 인터벌이 경쟁적으로 갱신. bridge가 반환한 `emitTypingState`는 실사용 안 됨(메신저.tsx가 자체 호출분 사용).
- 근거: Grep `handleTypingInput` → useChatTypingD1.ts + 메신저.tsx만. bridge의 emitTypingState는 useChatRealtimeBridge 반환값에 포함되나(589) 메신저.tsx는 자체 훅 사용.
- 심각도: **높음** | 조치: bridge의 useChatTypingD1 호출 제거하고 emit 함수를 메신저.tsx 단일 호출로 일원화하거나, 반대로 메신저.tsx가 bridge 반환 emit을 쓰도록 통합. 타이핑 폴링은 화면당 1개여야 함.

**[D-2] 읽음 관련 훅 2종 — 책임 분리되어 진성 중복 아님 (정보)**
- 특별임무가 지목한 `메신저읽음상태훅(useChatReadStateSync)` vs `useChatReadSync`는 이름만 유사. 전자=안읽음 카운트 계산, 후자=커서쓰기+알림read+멘션인박스. 기능 중복 아님 → Q로 재분류(아래 Q-1).
- 심각도: 정보

### P — 성능 (폴링/중복API/의존성)

**[P-1] 타이핑 폴링 2배 (높음)** — D-1과 동일 원인. 화면당 typing GET이 2.5s마다 2회.

**[P-2] 전역+활성방 messages 폴링 동시 가동 (중간)**
- `메신저구독훅.ts:246` 전역 `chat-global-messages` 폴링 4000ms (`{ table: 'messages' }`).
- `메신저구독훅.ts:296` 활성 방 `chat-realtime-${roomId}` 배치 폴링 1500ms 에도 `{ table: 'messages' }` 포함.
- 방 선택 시 messages 테이블을 1.5s/4s 두 채널이 동시 감지. 주석(291)대로 tail이 room filter 미지원이라 전역 폴링이 사실상 활성방 변경도 커버 → 활성방 선택 중 전역 4s 폴링은 잉여 트래픽.
- 심각도: 중간 | 조치: 활성 방 선택 시 전역 messages 폴링을 일시중지하거나 간격을 늘려 중복 tail 조회 축소. (poke 트리거가 있어 주기 의존도는 낮음)

**[P-3] 구독훅 room useEffect 의존성 과다 (중간)**
- `메신저구독훅.ts:349-358` deps: selectedRoomId, roomRealtimeRetryToken, effectiveTodoUserId, userId, scheduleRealtimeReconnect, effectiveChatUserId, setRoomRealtimeState, chatRoomsRef.
- 본문은 selectedRoomId/retryToken만 실제 사용(나머지 콜백은 ref경유). effectiveTodoUserId/effectiveChatUserId/chatRoomsRef 변경 시 방 폴링 구독이 불필요하게 teardown→재구독되어 폴링이 끊겼다 재시작.
- 심각도: 중간 | 조치: 불필요 deps 제거(ref로 이미 안정화됨).

**[P-4] fetchUnreadCounts 8초 throttle vs 폴링 1.5s 불일치 (낮음·의심)**
- `메신저읽음상태훅.ts:38` `UNREAD_REFRESH_MIN_INTERVAL_MS=8000`. 방 폴링은 1.5s. 다른 방 신규 메시지 배지 갱신이 최대 8초 지연될 수 있음(전역 폴링 4s와도 어긋남).
- 심각도: 낮음(의심) | 조치: 의도된 throttle인지 확인. 배지 지연 체감 시 4s로 정렬 검토.

### E — 에러처리
