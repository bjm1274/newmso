## 0. 재조사가 새로 밝힌 것 (1차와의 차이)

심화 재조사의 3대 기여:

1. **데이터 흐름 확정** — "계산이 틀렸다"가 실제 **지급액에 저장되는지** vs 화면 표시용인지를 `persistSettlement` 저장 페이로드까지 추적해 판별. → 치명도 재산정.
2. **수치 검산** — 모든 치명 항목을 샘플 직원으로 손계산해 **과소/과다 금액을 원 단위로** 제시.
3. **1차 오판 3건 정정** — A-3(지급액 버그 아님), E-4(인덱스 실재), 국민연금(정상) 재확정.

**가장 중요한 데이터흐름 결론:**
> 중도입사·격일제로 **잘못 산정된 통상시급 → 연장수당(`overtime_pay`)이 `recommendedOvertimePay`로 pre-fill되어, 사용자가 안 건드리면 그대로 DB에 저장·확정된다.** 즉 A-1·B-1·C-1·C-2는 "화면 표시 오류"가 아니라 **실지급액 오류**다.

## 1. 급여정산 데이터 흐름 지도 (심화 신규)

`persistSettlement`(급여정산.tsx:820-911)가 `payroll_records`에 쓰는 값의 성격:

| 분류 | 항목 | 비고 |
|---|---|---|
| **① 지급액 컬럼(저장+지급)** | base_salary, 각종 수당, **overtime_pay**, bonus, extra_allowance, attendance_deduction, total_taxable, total_taxfree, total_deduction, net_pay, advance_pay | overtime_pay에 자동수당이 pre-fill되어 저장 → 가산수당 버그가 지급액에 직결 |
| **② deduction_detail JSON에만 저장** | national_pension, health_insurance, …, income_tax, local_tax, **auto_overtime_pay, calculated_hourly_rate, salary_change_proration, taxable_allowance_breakdown** | top-level 보험/세금 컬럼은 **미저장** → JSON 손상 시 fallback 재계산 divergence |
| **③ 미저장** | **gross_pay**(컬럼 존재하나 페이로드 누락) | `getPayrollGrossPay`가 항상 fallback(taxable+taxfree) |
| **④ 표시 전용(지급 무관)** | salary_change segment별 prorated_amount | A-3 — 합계가 최종액과 1원 달라도 지급 영향 없음 |

## 2. 🔴 확정 치명 (수치 검산 포함)

### A-1 [확정🔴·저장됨] 중도입사/퇴사자 통상시급이 일할 감액분으로 산정
- **경로**: `급여정산.tsx:181`(baseSalary=일할분) → `:217-227`(draftEntry) → `getRegularHourlyRate`(utils:91) → `/209h`
- **검산**(월급 300만, 주40h, 7/15입사=17/31일, 연장 2h):
  | | 통상시급 | 연장수당(2h×1.5) |
  |---|---|---|
  | 정상 | 3,000,000/209 = **14,355** | 43,065원 |
  | 코드 | floor(3,000,000×17/31)=1,645,161 → /209 = **7,871** | 23,613원 |
  | **차액** | | **19,452원 과소(45%)** |
- **데이터흐름**: `overtime_pay`로 저장됨 → **실지급액 영향**.
- **수정**: `getRegularHourlyRate`에 일할 전 마스터 원액 전달.

### B-2 [확정🔴·격상] 격일제 통상시급 분모에 연장시간 ×1.5 이중 산입
- **위치**: `payroll-working-hours.ts:81` `hOver = weeklyOvertime * 4.345 * 1.5`
- **현상**: 분모(월 근로시간)에 연장분을 1.5배로 부풀려 통상시급이 과소.
- **검산**(격일제 24h, 주 84h): 코드 분모 511.3h → 5,868원 vs 올바른 389.6h → 7,700원 = **1,832원/시간 과소**.
- **주의**: B-1(아래) 때문에 **급여정산 화면에선 이 경로가 실행되지 않음**(isAlt 미전달→일반식). 급여상세 등 isAlt=true를 넘기는 화면에서 활성. 공식 자체가 오류.

### B-1 [확정🔴·저장됨] `getRegularHourlyRate`가 `isAlternateDayShift` 미전달 → 화면 간 시급 불일치
- **위치**: `급여정산-utils.ts:131-135`(4번째 인자 생략)
- **검산**(격일제 84h): 급여정산 isAlt=false → 분모 438.9h → **6,836원**, 급여상세 isAlt=true → 511.3h → **5,868원**. 같은 직원 시급이 화면마다 **968원/시간** 차이. 월 연장 40h면 약 58,080원/월 차이.
- **주의**: B-1(과대)과 B-2(과소)는 **반대 방향**. 격일제 시급 계산을 단일 SSOT로 통일해야 둘 다 해소.

### C-1 [확정🔴·저장됨] 야간근로(22~06시) 0.5배 가산 전무
- **위치**: `급여정산.tsx:230`(`×1.5` 고정), 적산 루프 504-559에 야간대 판정 코드 **부재**(Opus 직접 확인). `isNightShift`(542)는 교대 일자보정용.
- **검산**(야간조 22-06 8h, 시급 2만): 야간가산 8h×20,000×0.5 = **80,000원 과소**.
- **수정**: 분 적산 시 22~06 구간 별도 누적 후 ×2.0(연장+야간) 또는 ×0.5 추가.

### C-2 [확정🔴·저장됨] 휴일 8시간 초과 2.0배 미적용 + 소정시간만 누적
- **위치**: `급여정산.tsx:231, 525`(holidayHours += scheduledHours, 8h 경계 분기 없음)
- **검산**(일요일 11h 근무, 시급 2만): 8h초과 2h가 연장(1.5배)으로만 처리 → 2h×20,000×(2.0-1.5) = **20,000원 과소**.

### D-1 [확정🔴] `other_taxfree`·야간/당직수당 한도 없이 전액 비과세
- **위치**: `급여정산.tsx:717,722`(nightDuty·other에 `Math.min` 없음), `:726` total_taxable에 과세전환분 누락. `중간정산.tsx:391-392` 동일.

- **영향**: 비과세 근거 없는 금액이 과세표준에서 빠져 **소득세·4대보험 과소공제**(원천징수 의무 위반). 의료기관 야간당직 수당이 고액일수록 확대.

### D-2 [확정🔴] 건강보험 보수월액 상한 미적용 (Opus 직접 확인)

- **급여대장월별요약**: record_type 필터 없이 전체 조회(중복집계). (worktree 경로)

메인 트리에서 검증 권장 모듈: **통상임금계산기**(주40h 고정, 개별 근로시간 미반영), **최저임금체크 vs buildMinWageRows**(주35h 직원에 상반된 준수/미달 결론).

## 7. 권고 우선순위 (수정 난이도·영향 종합)

**P0 — 다음 정산 전 필수(실지급액·세무 직접):**
1. **D-1** 비과세 한도(other/야간당직) — 과세전환 추가 (소득세·보험 과소공제)
2. **F-2** 중간정산 severance를 과세표준에서 분리 (퇴직소득세 과다)
3. **A-1 + B-1 + B-2** 통상시급을 **마스터 원액 기준 단일 SSOT**로 (중도입사·격일제 가산수당)
4. **C-1 + C-2** 야간 0.5배·휴일 8h초과 2.0배 적산 추가
5. **D-2** 건강보험 보수월액 상한 적용

**P1 — 정합성·데이터 무결성:**
6. **E-1** 마감잠금 연동(+RLS) / **E-2** 확정 보호 / **E-3** 확정본 breakdown 고정
7. **E-5** record_type 조회 필터 / **G-9** 상여 입력 분리
8. **F-1** 퇴직금 공식 통일(+`salary` 컬럼 의미 확정)

**P2 — 정확도·구조:**
9. A-2·B-5 근태차감 기준(통상임금·일할), B-3 토요일 판정, B-4 employment_type
10. C-3 silent 실패 경고, C-4 DB값 우선, D-3 두루누리 만료

**근본 처방:** `calcStatutoryDeductions`(공제 SSOT)는 잘 통일돼 있다. 같은 방식으로 **「통상시급 산정 SSOT」와 「비과세 한도 SSOT」**를 단일 함수로 빼고, 급여정산·중간정산·급여상세·통상임금계산기·시뮬레이터가 모두 호출하도록 하면 A-1/B-1/B-2/D-1과 화면 간 불일치가 한 번에 해소된다.
