# 03. 추가기능 전수조사 (7차, 2026-07-27)

감사관 A3 · 담당 주메뉴: **추가기능** (PC + 모바일)
조사 방식: 소스 직접 읽기(읽기 전용). 모든 지적에 `파일:라인` 부여. 근거 등급 `확인`/`의심`.

---

## 요약

- **최대 위험은 카드 UI가 아니라 데이터 정책층에 있습니다.** `lib/db/auth/policies.ts:892-897` 의 fallback 루프가 주석(“PUBLIC_ALL 일괄 등록”)과 반대로 **`ADMIN_ONLY_ALL`** 을 부여합니다. 그 결과 `handover_notes`·`discharge_reviews`·`discharge_templates`·`surgery_templates`·`op_consultations`·`virtual_account_deposits`·`shift_assignments`·`org_teams`·`mri_templates` 가 전부 관리자 전용이 되어, **일반 직원에게 인계노트·퇴원심사·근무현황(월간)·모바일 입금조회·모바일 수술상담이 “에러 없이 빈 화면”으로 동작합니다** (SELECT 는 200 + `data:[]`, INSERT 는 403).
- 반대로 `daily_closures`/`daily_closure_items`/`daily_checks`/`staff_evaluations`/`board_posts` 는 `PUBLIC_ALL` 이라 **로그인만 하면 타 회사 마감보고(환자명+수납금액)·전 직원 평가·타 회사 수술일정(환자명·차트번호)을 읽고 지우는 것이 API 레벨에서 허용**됩니다. 프론트 게이팅만 존재합니다. OP체크의 수술일정 조회(`OP체크.tsx:477`)는 쿼리에도 회사 필터가 없습니다.
- **PC 수술상담은 PHI(수술상담 AI 분석 결과)를 브라우저 `localStorage` 에만 저장**하고(`수술상담-types.ts:109`, `수술상담.tsx:54/69/77`), 모바일 수술상담은 `op_consultations` 테이블에 저장합니다. 같은 메뉴가 서로 다른 저장소를 쓰며 데이터가 전혀 공유되지 않습니다.
- **알림은 사실상 미연결**입니다. PC 추가기능 12개 카드 전체에 `notifications` 생성 코드가 0건(PC OP체크 병동메시지만 채팅 DM 으로 우회 전달)이고, 모바일 OP체크만 in-app row 를 직접 insert 하지만 `type:'op_check'`/`'op_message'` 가 `REPUSH_ELIGIBLE_TYPES`(`lib/notification-repush.ts:44`)에 없어 **즉시 푸시도, 재푸시도 영원히 발생하지 않습니다.** 인계노트 등록·퇴원심사 요청·마감보고 제출은 알림 자체가 미구현입니다.
- 외부 링크는 PC(하드코딩 `http://` + `redirectTo=undefined`)와 모바일(`NEXT_PUBLIC_*` 미설정 → 영구 비활성)이 정반대로 깨져 있습니다.
- 부서별재고 PC 카드는 “재고관리로 통합됨” 묘비 화면만 남은 죽은 카드이며, 모바일 부서재고는 조회만 되고 하단 액션 버튼 2개가 `onClick` 없는 미완성입니다.
