# 10. 재무회계 · 조직도 · 공통 권한/라우팅 전수조사 (7차, 2026-07-27)

감사관: A12 · 범위: 재무회계(10뷰) / 조직도 / 공통 권한·라우팅 기반(`/api/d1/*`, `access-control.ts`, 4중 레거시 매핑)
방법: 읽기 전용 코드 직독. 모든 지적에 `파일:라인` 표기. 근거등급 `확인`(코드로 단정) / `의심`(런타임 확인 필요).

## 요약

1. **`/api/d1/mutate` 의 UPDATE 정책 검사가 `set` 값으로 위조 가능**하다. 정책은 실제 대상 행이 아니라 `where(eq) + set` 으로 만든 가짜 row 로 판정하고(`enrichRowProxyForPolicy` 는 `where` 에 `id eq` 가 있을 때만 DB 정본을 읽음), WHERE 절 자체는 정책과 무관하게 그대로 SQL 로 나간다. 로그인만 하면 `attendances`·`notifications` 등 SELF 스코프 테이블 **전 행을 자기 것으로 UPDATE** 할 수 있다 → **A12-01 (P0)**.
2. **`staff_members` 는 `select: 'PUBLIC'`** 이고 응답에서만 PII 컬럼을 지운다(`stripStaffSecrets`). WHERE/ORDER 는 필터링 대상이 아니므로 `where password like '$2a$10$a%'` 식 **prefix oracle 로 비밀번호 해시·주민번호를 문자 단위 추출** 가능 → **A12-02 (P0)**.
3. 반대 방향의 사고도 있다. `ADDITIONAL_PUBLIC_TABLES` 루프가 주석과 달리 **`ADMIN_ONLY_ALL` 을 부여**(policies.ts:892-897)해, `journal_entries`·`fixed_assets`·`bank_accounts_sync`·`org_teams`·`todos`·`document_repository`·`polls` 등 **80여 테이블이 비관리자에게 무음으로 빈 배열/403** 이 된다. **재무회계 메뉴는 관리자 외에는 전혀 동작하지 않는다** → A12-03/04 (P0/P1).
4. 재무회계 10뷰 중 **실제 DB 왕복은 3뷰(복식부기 등록/조회, 감가상각 자산 등록/조회, 자금흐름 계좌목록)뿐**이고 나머지 7뷰는 빈 목록 + 안내 토스트다. 차변/대변 균형검증 없음(같은 금액을 양쪽에 더해 **항상 "대차 일치"** 표시), 부가세 세율 계산 자체가 없음, 정률법 상각률 0.451 하드코딩, **결산 마감 후 소급 수정 차단 없음**.
5. 4중 레거시 매핑 레이어에서 **대상이 실재하지 않는 매핑 2건**(`비품대여설정`), **서로 모순되는 매핑 2건**(`udi`, `문서양식`)을 확인했다. `SIDEBAR_NAV_LABELS`(9) 는 `MAIN_MENUS`(10) 의 중복 SSOT 이며 공유캘린더 누락으로 tooltip 만 빠지고 재무회계는 라벨이 덮어써진다.
6. 조직도는 **권한 게이트가 사실상 없다**(`canAccessExtraFeature` 가 `'조직도'` 를 무조건 true 로 조기반환 — 권한관리 UI 의 `extra_조직도` 키가 무력화). 노출 항목은 이름/직급/회사/부서/사번/내선/사진/당일 출퇴근시각이며 연락처·주민번호는 서버에서 제거된다.
