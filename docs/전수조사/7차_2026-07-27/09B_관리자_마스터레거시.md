# 09B. 관리자 — 시스템마스터·레거시 경로·미연결 리프 전수조사 (7차, 2026-07-27)

감사관 A11 / 담당: 시스템마스터센터 + 레거시 한글 경로(Path B) + 사이드바 미연결 리프
(영문 워크센터 6종 exec/company/roles/ops/forms/audit 본체는 타 감사관 담당 — 리프 도달성 판정에 필요한 범위만 인용)

## 요약

- **Path B(레거시 한글 분기, `관리자전용.tsx:313-365`)는 사실상 죽은 코드다.** `ADMIN_TAB_ALIASES`(`admin-menu-config.ts:106-118`)가 8개 한글 outer id를 전부 영문 워크센터로 치환하므로 `activeTab`이 `경영분석/운영설정/감사센터/직원권한/데이터백업/데이터초기화` 값을 가질 수 없다. 예외는 `양식빌더`·`문서서식` alias가 **영문이 아닌 한글 `문서양식`을 가리켜** 313-365 블록 중 line 365만 살아 있는 것과, alias 대상이 없는 `시스템마스터센터`(line 366)뿐이다.
- 그 결과 **데이터초기화(456줄)·데이터백업(808줄) 화면은 UI로 도달 불가**인데, **서버 API `POST /api/admin/data-reset` 은 살아 있고 비밀번호 검증이 전혀 없다.** 클라이언트의 2단계 확인·문구 입력·bcrypt 잠금해제는 전부 우회 가능하며, `isAdminSession` 만 통과하면 채팅·재고·게시판·**감사로그 전체**·**전 직원 연차원장**을 삭제할 수 있다. → **A11-01 P0**.
- `데이터초기화`/`데이터백업` 즐겨찾기·북마크는 alias에 의해 `audit` 워크센터로 리다이렉트되는데, AuditWorkcenter에는 초기화 UI가 아예 없다 → 사용자 입장에서 "메뉴가 사라짐". 백업 탭도 `AuditBackupTab`(별도 신규 UI)이라 두 벌 구현이 병존한다.
- **권한 불일치의 실체는 "탭 단위 게이트 소실"이다.** Path B는 `visibleOperationsTabs`/`visibleAuditTabs`로 내부 탭마다 `canAccessAdminSection`을 걸었으나(`관리자전용.tsx:147-154`), Path A 워크센터 4종은 내부 탭에 권한 검사가 **한 줄도 없다**. 게다가 `canAccessAdminSection(user,'audit')`는 7개 세부키의 OR 합집합이라 `admin_데이터백업` 하나만 있어도 급여·인사 감사로그 전문을 열람하게 된다.
- 시스템마스터센터는 서버 게이트(`isNamedSystemMasterAccount`)가 견고하나, 화면 게이트는 `hasSystemMasterPermission`(계정 id 미확인)이라 **권한 플래그만 있고 계정 id가 다른 사용자에게는 UI는 열리고 전 패널이 401로 죽는다**. 또한 채팅방 캐스케이드 삭제·푸시구독 정리 등 파괴적 액션에 **감사 로그가 전무**하다.

## H. 미확인 항목

1. **DB 즐겨찾기/북마크 실데이터** — `양식빌더`·`문서서식`·`데이터초기화` 같은 레거시 subview 문자열이 실제 사용자 레코드에 남아 있는지 확인 못 함(운영 D1 조회 필요). 이 값들의 존재 여부가 A11-09/A11-16 의 실제 영향 범위를 결정한다.
2. **`isAdminSession` 의 `permissions.admin` 부여 범위** — `access-control.ts:234` `menu_관리자` alias가 `'admin'` 을 포함하므로 관리자 메뉴 접근권만으로 `permissions.admin` 이 참이 되는 계정이 있는지 실데이터 확인 필요. 참이라면 A11-01 의 공격 표면이 "role=admin" 을 넘어 크게 넓어진다.
3. **`staff_members` 의 주민번호/계좌 컬럼 실존 여부** — A11-15 는 `시스템마스터센터.tsx` 의 `maskResidentNo`/`maskAccount` 사용으로 추정한 것으로, 스키마 컬럼 확인은 못 했다.
4. **`/api/admin/audit/summary`·`/api/admin/audit/payroll-outliers`·`/api/admin/audit/backups`** 의 내부 구현 — AuditWorkcenter 본체가 타 감사관 담당이라 라우트 내용은 열지 않았다. A11-13/A11-14 의 "실데이터 여부"는 그쪽 확인 필요.
5. **`submitLeaveRequest`(`인사관리워크센터/LeaveWorkcenter/data`)의 서버 권한 검사** — 연차수동부여가 이 함수에 위임하는데 함수 내부는 인사관리 감사관 영역이라 미확인. 클라이언트 `isNamedSystemMasterAccount` 가 유일한 게이트일 가능성 있음.
6. **`transaction` 미사용** — `data-reset`·`reset-staff`·`delete-chat` 모두 다중 delete 를 순차 실행하며 D1 트랜잭션/batch 를 쓰지 않는다. 중간 실패 시 부분 삭제 상태가 남는데, D1 바인딩에서 `batch()` 사용 가능 여부를 확인하지 못해 지적으로 올리지 않았다.
