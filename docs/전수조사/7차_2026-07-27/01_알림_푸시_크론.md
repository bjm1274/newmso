## 요약

- **P0 3건, P1 8건, P2 12건, P3 7건.**
- 최대 결함: **앱 내 알림 생산 지점 30여 곳 중 절반 이상이 푸시를 전혀 발송하지 않는다.** 클라이언트에서 `d1.from('notifications').insert(...)`(→ `/api/d1/mutate`) 또는 `POST /api/notifications` 로 끝나는 경로는 **in-app + 실시간만** 나가고 FCM/WebPush 는 코드상 호출되지 않는다. 전자결재 상신·결재요청, 계약서 서명요청, 급여명세 발송, 재고 승인/반려, OP 메시지, 근태 알림 등 실사용 알림 대부분이 여기에 해당한다.
- 서버 경로(`insertNotificationsOrThrow`)조차 푸시를 `void (async(){...})()` 로 던지고 `ctx.waitUntil` 을 쓰지 않는다. 같은 레포의 `/api/d1/mutate` 는 채팅 푸시에 대해 명시적으로 `waitUntil` 을 쓰고 있어 **동일 런타임 제약을 이미 인지하고 있음에도** 일반 알림 푸시만 누락됐다.
- 크론 배선 결함: `/api/cron/absent-auto-create` 는 worker 라우팅에는 있으나 `wrangler.toml` 트리거가 없어 **영구 미실행**. `/api/cron/auto-report`, `/api/cron/todo-reminders` 는 어디에도 스케줄이 없다(자동보고서 기능 전체 사문화). 시스템마스터 UI 는 실제와 다른 스케줄을 표기한다.
- SW 딥링크: 서버는 `data.notification_type` 을 넣는데 SW 는 `data.type` 을 읽는다. metadata 에 `type` 을 직접 넣지 않은 알림(예: 게시판 공지 브로드캐스트)은 푸시 클릭 시 목적 화면이 아니라 `/main` 으로 떨어진다. 또한 push data 에 `notification_id` 가 없어 **푸시 클릭 시 읽음 처리가 되지 않는다**(repush 경로만 예외).

## A. 알림 도달 매트릭스

판정 기준
- **in-app**: `notifications` 행이 생성되어 인박스/벨/알림탭에 노출되는가
- **웹푸시/FCM**: 그 경로에서 `dispatchPushForNotificationRows` / `sendFcmBatch` / `sendWebPushNotification` 이 호출되는가
- **실시간**: `emitRealtimeSignal('notifications*')` 이 발생해 15초 폴링 이전에 토스트/배지가 갱신되는가

## F. 미확인 항목

정직하게 확인하지 못한 것들:

1. **런타임 실측 부재** — `void` 로 던진 푸시 promise 가 실제 Cloudflare Workers 에서 얼마나 자주 취소되는지(A1-06), KST 09:00 8개 순차 크론의 실제 소요 시간(A1-23)은 배포 로그/`audit_logs` 조회 없이는 단정 불가. 코드 구조만으로 위험을 지적했다.
2. **`push_subscriptions` 실데이터 분포** — Electron/iOS/PC 구독 비율, `fcm_token IS NULL` 행 비율을 확인하지 못해 A1-19(토큰 덮어쓰기)의 실제 영향 범위를 산정하지 못했다.
3. **`chat-push-dispatch.ts` 1188줄 전체** — 큐 클레임/재시도/앨범 배치/뮤트룸 로직(`:97-530`)은 푸시 전송 경로(`:860-1188`) 위주로만 읽었다. 스티커/이모티콘 라벨 매핑, 스레드 루트 해석 등 미열람 구간이 있다.
4. **`알림인박스.tsx`(1330줄) / `알림시스템.tsx`(2153줄) UI 세부** — 필터·정렬·스와이프 액션·설정 저장 로직은 읽지 않았다. 배지/읽음/푸시 관련 지점만 추적했다.
5. **`electron-app/main.js`** — `Notification` 생성부(`:108-216`)만 확인했고 트레이 폴백·클릭 IPC 라운드트립은 미검증.
6. **알림 자동화 설정(`관리자전용서브/알림자동화설정.tsx`)** 과 `lib/notification-automation-settings.ts` 의 설정값이 실제 푸시 발송 경로에서 존중되는지는 `annual-leave-promotion-dispatch` / `payroll-notice-dispatch` 두 소비자만 확인했다. 다른 알림 타입은 설정을 무시할 가능성이 있으나 미확인.
7. **VAPID 키 회전 시나리오** — `알림시스템.tsx:643-660` 의 mismatch 감지·재구독 로직은 읽었으나, `NEXT_PUBLIC_VAPID_PUBLIC_KEY`(`wrangler.toml:38`)와 서버 `VAPID_PRIVATE_KEY`(secret) 의 쌍이 실제로 일치하는지는 secret 접근 불가로 미검증.
