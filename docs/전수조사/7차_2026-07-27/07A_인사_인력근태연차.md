# 07A. 인사관리 — 인력·근태·연차 전수조사 (7차, 2026-07-27)

감사관 A7 / 읽기 전용 / 담당: 인력(member)·근태(attend)·연차(leave)·근태이상(abnormal) — PC + 모바일
(급여·복지·계약문서는 A8 담당, 미조사)

## 요약

- **연차 계산에 SSOT가 3개 공존한다.** 서버 정본 `lib/unified-leave-ledger.ts`(입사일 응당일 사이클), 클라이언트 정본을 자칭하는 `lib/annual-leave-summary.ts`(회계연도/당해연도), 그리고 `staff_members.annual_leave_total/used` 직접 쓰기. **PC 연차 워크센터는 서버 SSOT를 호출하지 않고**, 모바일 연차는 서버 SSOT를 호출한다 → 같은 사람의 잔여 연차가 PC와 모바일에서 다르게 보인다.
- **P0 3건**: ① `/api/admin/annual-leave/export-csv` 인증 없음 — 전 테넌트 전 직원 명단·입사일·연차가 무인증 GET으로 전량 유출. ② `/api/annual-leave/summary` 는 로그인만 검사하고 staffId 소유권을 검사하지 않음 — 일반 직원이 남의 연차 원장 전체 조회 가능. ③ PC 근태이상 감지 탭은 존재하지 않는 컬럼(`late_minutes`/`early_leave_minutes`)을 SELECT 하여 항상 빈 화면(모바일 코드에는 "정본 attendances 에는 없다"는 주석까지 있는데 PC만 안 고쳐짐).
- **연차 소멸이 자동으로 되돌려진다.** `lib/annual-leave-expiry.ts` 는 `leave_balances` 만 0으로 만들고 `leave_ledger` 에 `expire` 항목을 쓰지 않는다. 이후 `getUnifiedAnnualLeaveSummary` 가 원장 기준으로 `leave_balances.remaining_days` 를 다시 덮어써 소멸분이 부활한다. `expired_at` 은 남아 재처리도 안 된다.
- **근태 이중 테이블(`attendance` 단수 / `attendances` 복수)이 여전히 살아 있고**, 모바일 개인 근태는 단수를, PC 근태 워크센터·근태이상은 복수를 읽는다. 동기화는 `lib/attendance-sync.ts` 의 warn-only try/catch 라 실패해도 조용히 갈라진다.
- **`disciplinary_committees`(징계), `staff_evaluations`(인사평가), `work_shifts`(근무유형)가 `PUBLIC_ALL` 정책** — 로그인한 아무 직원이나 SELECT/INSERT/UPDATE/DELETE 가능.
- **결근 자동생성 cron 이 등록되어 있지 않다.** `cloudflare-worker.ts` 는 `30 15 * * *` 슬롯에 `absent-auto-create` 를 매핑했지만 `wrangler.toml [triggers] crons` 에 해당 스케줄이 없다.
- 인사관리 사이드바에서 **연차 원장·연차촉진시스템·연차소멸알림·공휴일달력에 도달할 수 없다.** 이들은 `관리자워크센터/CompanyWorkcenter.tsx` 를 통해서만 열린다.
- 연차 소멸/촉진/근태이상/교육/자격 알림은 전부 **인앱 row 만 생성, 푸시 미발송**. 푸시까지 가는 정상 경로(`insertNotificationsOrThrow`)를 쓰는 인사 기능은 `/api/roster/approval-request` 하나뿐인데, **그 API를 호출하는 화면이 없다**(죽은 API).

### D-2. 발생(accrual)

- `lib/annual-leave-accrual.ts:5-7, 99, 306` — 1년 미만 월차 최대 11일, 1년 이상 `min(25, 15+floor((N-1)/2))`. **입사일 기준. 법정 계산 자체는 정확.** cron 등록도 정상(`0 0 * * *`).
- 그러나 `휴가신청/휴가관리메인.tsx:398-408` 이 **같은 계산을 다시 구현**해 `staff_members` 에 직접 쓴다(A7-15). 1년 미만 계산이 `Math.floor(경과ms / 30일)` 이라 30일 고정 월 근사 → 법정 월차와 어긋난다.

### D-3. 사용(use)

- 정본: `syncApprovedLeaveRequestsToLedger`(`unified-leave-ledger.ts:507-573`) 가 승인된 `leave_requests` 를 `USE`(음수)로 원장에 기록. `period_key = request:{id}` 로 멱등.
- 우회 경로: `휴가관리메인.tsx:196-199 / :263-266 / :330-333` 이 `annual_leave_used` 를 직접 UPDATE (A7-16).
- 일수 계산: `leaveDays`(:152-162)가 `days` 컬럼이 없으면 **달력일 전체**를 세어 주말·공휴일을 차감 (A7-26).

### D-4. 소멸(expire)

- **원장에 기록되지 않는다.** `annual-leave-expiry.ts` 는 `leave_balances` 만 갱신 → `getUnifiedAnnualLeaveSummary` 가 덮어써 소멸 부활 (A7-07).
- 소멸 전제 조건인 촉진 이행 검사(`hasCompletedBothPromotions`, `:188`)는 올바르게 구현되어 있음.

### D-5. 촉진(promotion)

- `lib/annual-leave-promotion.ts:98-124` — 만료 6개월 전 1차, 2개월 전 2차, **입사일 응당일 기준**. 멱등키(`:37-43`) 정상.
- 알림이 푸시로 안 감 (A7-18) → 법정 통지 실효성 문제.
- PC UI 는 인사관리에서 도달 불가 (A7-19).

### D-6. 이월(carryover)

- **이월 처리 코드가 존재하지 않는다.** `getUnifiedAnnualLeaveSummary` 는 사이클 밖 `AUTO_*`/`USE` 항목을 필터로 배제(`:324`)하므로, 사이클이 넘어가면 이전 사이클 잔여가 **자동으로 사라진다**(원장에도 소멸/보상 흔적 없음). 이월도 정산도 아닌 조용한 증발. 반면 `MANUAL_*` 은 반대로 영구 누적(A7-25).

### D-7. 회계연도 vs 입사일 혼재 정리

## I. 미확인 항목

1. **`late_minutes`/`early_leave_minutes` 의 운영 D1 실제 존재 여부** — 스키마 파일·마이그레이션 어디에도 없으나 운영 DB 가 수동 ALTER 로 드리프트했을 가능성. A7-03 의 "항상 빈 화면" 판정은 이 전제 위에 있음. 운영 D1 에 `PRAGMA table_info(attendances)` 확인 필요. (모바일 코드 주석이 "없다"고 단정하므로 확률은 높음)
2. **`void Promise.all` 부작용의 Workers 런타임 취소 여부**(A7-27) — `ctx.waitUntil` 미사용 프라미스가 실제로 완료되는지는 런타임 관찰 필요.
3. **`/api/d1/mutate` 의 update/delete 시 `where` 만으로 행을 특정할 때 정책 판정에 쓰는 row 재구성 정확도** — `route.ts:187` "eq 조건만 field=value 로 사용" 이라 `in`/`gte` 만 있는 mutate 에서 정책이 어떻게 판정되는지 미검증. A7-28 의 실제 악용 가능성 폭에 영향.
4. **`구성원현황.tsx`(2986줄) 전체** — 직원 등록/수정 폼. `annual_leave_total/used` 직접 쓰기(:1318-1319, :1344-1350) 확인했으나 나머지 로직 미독파.
5. **`근무형태관리.tsx`(1384줄), `근무형태관리-break-plans.ts`** — 인사관리 메뉴에서 도달 불가(A7-19)로 판정하고 내부 로직 미조사.
6. **`교육내역/` 6파일, `인사발령관리.tsx`, `징계` 상세 흐름** — 정책이 ADMIN_ONLY 로 막혀 있다는 구조적 결함(A7-13)을 확인했고 화면 내부 로직은 미조사.
7. **모바일 `근태조정신청.tsx`, `근태이상카드.tsx`, `발령필터.tsx`** — 파일 목록만 확인, 내용 미독파.
8. **`emitRealtimeSignal` / `lib/realtime/allowed-tables.ts:21-22`** 로 근태 실시간 갱신이 실제 도달하는지 미검증.
