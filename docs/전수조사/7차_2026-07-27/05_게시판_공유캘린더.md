# 05. 게시판 · 공유캘린더 전수조사 (7차, 2026-07-27)

감사관 A5 / 범위: PC `기능부품/게시판.tsx`+`게시판서브/*`+`게시판/*`, `기능부품/공유캘린더.tsx`, 모바일 `모바일/게시판/*`, `모바일/추가기능/공유캘린더.tsx`, 서버 `app/api/board/*`, `app/api/d1/*`, `app/api/calendar/*`, `lib/access-control.ts`, `lib/db/auth/policies.ts`

## 요약

- **최악의 결함은 서버 권한이다.** `lib/db/auth/policies.ts:405,428`에서 `board_posts` / `board_post_reads` 가 `PUBLIC_ALL`(select·insert·update·delete 전부 PUBLIC)로 등록돼 있고, `policies.ts:1008`이 `PUBLIC` 을 무조건 통과시킨다. 즉 로그인만 하면 `/api/d1/mutate` 로 **타인의 공지 수정·삭제, 임의 board_type 글 작성, 타 회사 글 열람**이 가능하다. `canAccessBoard` 는 프론트와 `app/api/board/upload/route.ts` 단 한 곳에만 있다 (A5-01, P0).
- **회사 격리가 데이터 경로 어디에도 없다.** PC 목록(`게시판.tsx:478-491`)·모바일 목록(`data-hooks.ts:182-201`)·공지 broadcast 수신자(`notice-broadcast/route.ts:211-218`)·읽음현황 대상자(`게시판.tsx:362-368`) 모두 company 필터가 없다 (A5-02·A5-06·A5-08).
- **알림은 공지사항·경조사만** 발송되고(`create-board-post.ts:154`), 그마저 in-app 행이 **2중 생성 + 푸시 2회** 발송된다(`notice-broadcast/route.ts:225,236`). 자유게시판/수술/MRI/업무가이드 등록·모든 댓글은 알림이 **전혀 없다** (A5-09·A5-10).
- **읽음현황은 구조적으로 동작하지 않을 가능성이 높다.** `board_post_reads(post_id,user_id)` 에 UNIQUE 인덱스가 없는데(`0000_lovely_alice.sql:238-249`) 클라이언트는 `onConflict:'post_id,user_id'` upsert 를 쓴다 (A5-04).
- 서브메뉴 SSOT 는 **id 드리프트 없음**(전 소스 6개 동일), 그러나 **라벨이 3벌**이고 실제 렌더는 `SUB_MENUS.게시판` 쪽이라 `게시판메뉴.ts` 전체가 사실상 죽은 코드다 (D절·G절).
- **공유캘린더의 「게시판일정」 기능은 작동하지 않는다.** `board_posts.category` 컬럼 자체가 스키마에 없고, 렌더 필터가 `e.day != null` 이라 게시판 이벤트는 절대 표시되지 않는다 (A5-14).

## D. 서브메뉴 SSOT 드리프트

**결론: id 드리프트는 없다. 라벨/아이콘 드리프트와 "렌더되지 않는 SSOT"가 문제다.**

- 실제 렌더되는 것은 **`조직도서브/조직도측면창.tsx:53-60` 의 `SUB_MENUS.게시판`** 이다. `Sidebar` 컴포넌트 자체는 `MAIN_MENUS` 만 그리고(`조직도측면창.tsx:782-785`), 2열 서브메뉴는 **`app/main/page.tsx:1368-1448`** 이 `SUB_MENUS[mainMenu]` 를 읽어 그린다(`page.tsx:949-981` 에서 `canAccessBoard(...,'read')` 필터, `:1391` 에서 `sub.group` 기준 그룹핑).

1. **런타임 검증 미실시** — 본 조사는 전량 정적 코드 판독이다. A5-04(읽음 upsert 실패 여부), A5-15/A5-16(`staff_id ≠ id` 가 실제 데이터에 존재하는지)는 프로덕션 D1 조회가 필요하다.

4. `업무가이드.tsx` 는 1674줄 중 데이터 로드·권한·삭제 경로 위주로 읽었다. 팀 할일 완료 처리(`:790`)·`GuideDetailPanel.tsx`(264줄)의 세부 렌더는 미검증.
5. `BoardComposePanel.tsx`(907줄)의 폼 유효성 세부, `PostTableView.tsx`(479줄)의 정렬·태그 카탈로그, `board-poll-prize.ts` 추첨 알고리즘의 공정성은 미검증.
6. 푸시 실제 도달(웹푸시 구독 유효성, iOS PWA)은 코드 경로만 추적했고 실기기 확인은 하지 않았다.
7. 오프라인 큐 경로(`글작성.tsx:206-217` `enqueueD1Mutation`, `enqueueUpload`)의 재시도·중복 방지 로직은 미검증 — 공지 중복 방송 가능성이 있다.
