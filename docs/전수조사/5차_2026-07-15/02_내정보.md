## 2. Critical

### C1. `mypage_급여조회=false` 우회 — PC KPI·localStorage / 모바일 상시 노출

| 항목 | 내용 |
|------|------|
| **파일:라인** | PC `마이페이지/index.tsx:801–822` (KPI onClick), `:365–420` (localStorage `MYPAGE_TAB_KEY` 복구), `:879` (탭만 권한 검사) · 모바일 `홈.tsx:158,279–282` · `내정보/index.tsx:52–64` |
| **증상** | 관리자가 `mypage_급여조회`를 명시 false 로 꺼도 (1) PC 홈 KPI「급여명세서/증명서」클릭으로 `records` 진입 가능, (2) 이전에 본 탭이 localStorage에 있으면 복구, (3) 모바일 퀵메뉴「급여·증명서」는 권한 검사 없이 항상 노출·비밀번호만 통과하면 `SalarySlipContainer`가 `payroll_records` 조회 |
| **원인** | 탭 버튼만 `canAccessMyPageTab` 적용. KPI·초기탭 복구·모바일 라우트에 동일 게이트 없음. 서버 API 권한 재검증 없이 D1 정책(STAFF_IN_SCOPE)만으로 본인 행 조회 가능 → **기능 권한 플래그와 데이터 접근 불일치** |
| **수정** | (1) KPI/즐겨찾기/initial tab 적용 전 `canAccessMyPageTab(user,'salary'|'certificates')` 필수 (2) 모바일 퀵메뉴 `records` visible 조건 동일 (3) `SalarySlipContainer` 마운트 시 권한 false면 조기 return (4) 장기: 조회 API에서 세션+권한 재확인 |
