## 수신 파이프라인 추적 (receive → toast → system popup → mark read → deep link)

```
[발송 소스]
  채팅: chat-push-dispatch → notifications INSERT + FCM/WebPush
  인앱 잡: inapp-notification-jobs/* → insertNotificationsChunked → push dispatch
  기타: payroll-notice, annual-leave-*, contract, 클라이언트 insert 등
        │
        ▼
[저장] notifications (user_id, type, title, body, metadata, read_at)
        │
        ├─► 서버 푸시: FCM 우선 / WebPush 폴백 (quiet hours 시 non-chat 스킵)
        │         └─ SW showNotification / FCM background
        │
        └─► 클라: subscribeRealtime(notifications, 3s)
                  └─ fetchUnreadNotificationsSince
                        └─ emitIncomingNotification
                              ├─ type/keyword 필터
                              ├─ 방 mute / 활성 방 suppress
                              ├─ Toast (인앱) ─ Electron 강제
                              ├─ erp-chat-notification / erp-alert
                              ├─ 소리·진동 (DND/주말 시 스킵만)
                              └─ sendNotification (시스템 팝업 / Electron IPC)
        │
[읽음]
  인박스/센터/탭: PUT /api/notifications  (id | ids | all)
  SW 클릭: POST /api/notifications/mark-read (+ retry queue)
  인박스: 오픈 1.5초 후 markAll (자동)
        │
[딥링크]
  resolveNotificationTarget → router.push / setMainMenu·setSubView
  SW: erpBuildTargetUrl → same-origin /main?... → PwaBootstrap erp-push-deep-link
  Electron: onNotificationClick → erp-chat-notification (채팅 위주)
```

## Critical

### C1. `POST /api/notifications` — 임의 사용자 알림 삽입 + 관리자 일괄 발송 무권한

| 항목 | 내용 |
|------|------|
| 위치 | `app/api/notifications/route.ts` 약 66–150행 (`POST`) |
| 증상 | 로그인 직원이 `user_id`에 타 직원 ID를 넣어 알림·스팸 푸시 가능. `send_to_admins: true`면 행정/원무/경영지원 **전 회사** 직원에게 일괄 INSERT |
| 원인 | 인증만 검사, **본인 스코프·역할·회사** 미검증. `targetUserId = item.user_id \|\| uid` 허용 |
| 영향 | 스팸, 피싱성 딥링크 메타데이터, 타 법인 직원 교란 (멀티테넌트) |
| 수정 제안 | (1) 기본: `user_id` 강제 `session.user.id` (2) 관리자 발송은 별도 admin API + 권한 + `company_id` 필터 (3) rate limit (4) 허용 type 화이트리스트 |

### C2. 인앱 알림 cron 주기와 lookback 불일치 — 근태·급여·금지어 등 상시 누락

| 항목 | 내용 |
|------|------|
| 위치 | `app/api/cron/inapp-notifications/route.ts` 주석 9–18; `push-subscription-cleanup` 피기백; `check-attendance.ts` LOOKBACK 5분; `check-payroll.ts` 60분; `check-word-filter.ts` 5분 |
| 증상 | 결재 대기는 전체 스캔+dedupe로 비교적 생존. **근태/급여발행/금지어**는 “최근 N분”만 보는데 실행이 **KST 12:00 1회**면 거의 항상 empty |
| 원인 | CF Free cron 한도 → 피기백 설계. lookback은 5분 주기 전제 |
| 영향 | 인앱 보강 채널이 “있는 척”만 하고 실무 알림 미생성 |
| 수정 제안 | 외부 5분 cron 또는 Paid cron 등록; lookback을 “마지막 성공 실행 시각” watermark로 변경; 급여는 정산 이벤트 시점 직접 insert 유지 |

### C3. 채팅 알림 `type`이 멘션이어도 항상 `message`

| 항목 | 내용 |
|------|------|
| 위치 | `lib/chat-push-dispatch.ts` 약 756–770, 927–930 (`notificationType: 'message'` 고정) |
| 증상 | 방 설정 `mention_only` / 키워드 모드 / UI 멘션 탭·아이콘이 **멘션을 일반 메시지로 처리**. `resolveChatRoomSurfaceSuppression`의 `type !== 'mention'` 분기가 멘션도 suppress |
| 원인 | `mentionedIds`는 뮤트 우회 수신 대상에만 쓰고, row.type·metadata.type 기록은 안 함 |
| 영향 | “멘션만 받기” 방 설정 **사실상 고장** (멘션도 숨김 또는 반대로 멘션 배지 불가) |
| 수정 제안 | 대상 user가 `mentionedIds`에 있으면 `type: 'mention'`, `notificationType: 'mention'`으로 insert/푸시 |

### C4. 재고 부족 인앱 알림 — 회사(`company_id`) 미격리
