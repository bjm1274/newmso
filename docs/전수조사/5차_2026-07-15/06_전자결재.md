## 3. 결재함 / 기안함 / 참조 / 작성하기 맵

## 5. 플로우 추적: 상신 → 승인 → 최종 → 연차/출결 사이드이펙트

### 5.1 상신

| 단계 | PC | 모바일 |
|------|-----|--------|
| 검증 | useApprovalSubmit (연차/물품/공문/보고 등) | 폼별 canSubmit + 스키마 required |
| doc_number | createStructuredDocNumber 계열 | generateMobileDocNumber (count+1, 동시성 m) |
| insert | approvals + optional company_id | enqueueD1Mutation insert |
| 첨부 | meta.attachments | 동일 (done URL만) |
| 알림 | 결재자/참조 알림 insert | 공통 훅·폼 경로에 따라 상이 |
| 연차 특수 | 메타만 (leave_requests는 최종 시 ensure) | **대기 leave_requests 선 insert** |

### 5.2 중간 승인

- `transitionApprovals`: actor === effective current_approver **또는** isAdmin.
- 다음 결재자 `current_approver_id` 갱신 + history + 「결재 차례」알림.
- status 유지 `대기`.

### 5.3 최종 승인 → `processFinalApprovalEffects`

| 조건 (type / meta) | 효과 | 멱등 |
|--------------------|------|------|
| 공통 | document_repository 동기화 | server_processing completed 마커 |
| `물품신청` + items | inventory_workflow pending + 지원팀/기안자 알림 | |
| `인사명령` + orderTargetId | staff 부서/직책 + transfer_history | |
| `연차/휴가` \| `휴가신청` | ensureApproved leave_requests · attendance/attendances · sync used · recalculateLeaveBalance · 즉시 연차공지 | 기존 승인 leave 매칭 시 skip insert |
| `출결정정` 또는 form_slug=attendance_fix | attendance_corrections upsert + 출결 status | unique (staff_id, attendance_date) |
| `양식요청` + auto_issue | certificate_issuances | |
| `근무표` + assignments | shift_assignments 삭제 후 insert | unique 우회 |
| 공문 메타 | official_document_log | |
| type ≠ `물품요청` | 기안자 「최종 승인」알림 | 주석 type과 실제 `물품신청` 불일치(m) |

**미처리 타입:** 연장근무, 연차계획, 수리, 보고서, 사직/평가 등 → 문서보관·알림 위주. 급여/OT 수당 자동 반영 없음.

### 5.4 연차 잔여 사이드이펙트 상세

```
최종 승인
  → extractLeaveRequestMeta(meta)  // leaveType, start/end, days, delegate
  → ensureApprovedAnnualLeaveRequest(...)  // leave_requests status=승인
  → (부여/과거사용 제외) attendance + attendances 일자 루프 upsert
  → isAnnualLeaveType 이면 syncAnnualLeaveUsedForStaff
  → recalculateLeaveBalance(staffId)
  → announceLeaveApprovalIfNeeded (당일 시작 시)
```

**모바일 연차 리스크 (M-LEAVE):**

1. 상신 시 `leave_requests.leave_type` = `'연차'|'반차'` (kind).
2. approvals meta `leaveType` = `'연차 (1.0)'` / `'반차 (0.5)'`.
3. ensureApproved 조회 키가 **leave_type 문자열 완전 일치** → 대기 row 미매칭 → **승인 row 추가 insert**.
4. 원 대기 leave_requests **잔존(고아)** · 집계 화면이 대기+승인 혼재 시 왜곡 가능.
5. approvals insert 실패 시 leave_requests만 남는 경로 toast로 안내 (의도적) — 사용자 재상신 필요.

### 5.5 출결정정

```
작성: meta.correction_dates / correction_type / reason
     + (PC·모바일) attendance_corrections status=대기 insert (이중 기록)
최종: upsertAttendanceCorrectionRows(status=승인) + attendance/attendances status 반영
```

- 스키마: `status` 만 존재. 읽기 경로는 여전히 `approval_status` 폴백 키 참조.
- `onConflictDoUpdate` 대상: **unique index 존재** (`idx_attendance_corrections_staff_date_unique`) — 3차 S-3 **스키마 측 해소**.
- PC `applyCorrectionToAttendance` 함수: **호출 0 (죽은 코드)** — 실제 반영은 서버 final만.

## 12. 권장 수정 우선순위

7. **M4–M5** 상신 트랜잭션/보상 트랜잭션 (leave ↔ approval).

## 13. 핵심 결론

1. **승인 메인 파이프라인(서버 transition + final effects + 연차 잔여 재계산)** 은 성숙. 회수·첨부·참조 알림 등 **2026-05/06 Critical 다수 해소**.  
2. **신뢰 경계 구멍**은 여전히 **PC 반려 클라 폴백**과 **멀티테넌트 목록 미격리**.  
3. **모바일은 “작성 가능” 범위가 넓어졌으나** type/메타/물품·연장근무·연차 선insert 로 **최종 사이드이펙트 패리티가 깨질 수 있음**.  
4. **출결정정**은 unique·서버 반영은 개선됐으나 **대기 이중기록·레거시 폴백·죽은 apply 함수** 정리 필요.  
5. **권한**: PC 함 단위 OK / 모바일 세부 키·공문 제출 권한·강제반려 비대칭 잔존.
