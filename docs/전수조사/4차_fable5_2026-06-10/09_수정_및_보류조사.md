### A-2. 조사로 "수정 불필요" 확정 (오진/무효 정정)
- **lib-02 중첩 `.or()` contains** — 실호출 0. 실제 `.contains()`는 WhereSchema 경로(이미 수정됨)로만 가고, PostgREST `.or()` 문자열에 `contains`를 쓰는 코드가 없음 → `filter.ts` 확장은 **미사용 코드 추가**라 안 함.
- **admin-06 flagged 채팅 필터** — 원 보고의 "미구현" 전제가 **오진**. 필터는 서버(`flaggedRoomsOnly`)+클라(`includesBannedWord`) 양단으로 **이미 동작**. `시스템마스터센터.tsx:463` `visibleChatRooms`는 현 상태가 정답이며, 추가 구현 시 이중 필터로 **회귀 위험** → 코드 변경 없음(검증은 `tests/e2e/system-master-chat-filter.desktop.spec.ts`).

## B. 보류 항목 심층 조사 (제품 결정 대기)

> 6개 토픽을 Fable5가 코드/스키마로 검증. 각 **현황·근본원인·옵션(공수/리스크)·권장안**. 결정해 주시면 바로 구현 가능.

### B-1. 가짜 대시보드 (admin-03 ExecDashboard / admin-04 FormsWorkcenter)
- **현황**: 두 워크센터의 **'개요' 탭만** 전량 하드코딩 더미(매출 182.4M·방문환자 1,284명·양식 사용 142회·법인손익 +38M 등). 정작 하위 전용 탭은 이미 실데이터/`'집계 준비중'` 처리(재무대시보드=`daily_closures`, 법인손익현황=`payroll_records`, 경영대시보드=`fetchPendingApprovalCount`) → **개요만 거짓 숫자**.
- **근본원인**: 개요 탭이 데모용으로 먼저 만들어진 뒤 실연동이 하위 탭에만 구현됨. 데이터별로 (A)**즉시 실연동 가능**(미결재건수·현금잔고·법인 인건비/직원수·양식 종수·`approvals` 월별 사용집계 — 기존 쿼리 재사용) (B)**데이터 자체 부재**(정식 '월매출'·영업이익·미수금·예산집행률 소스 없음 — 그래서 경영대시보드가 '준비중' 표기).
- **옵션**: ①실연동(가능항목)+불가항목 '준비중' 표기[대/중] ②'샘플' 라벨만 부착[소/저] ③더미카드 제거+하위탭 CTA[중/중].
- **권장**: **①(단계적)**. 검증된 기존 경로 재사용이라 신규 인프라 0. 1단계 Forms 개요(`approval_form_types` 종수 + `approvals` 사용집계)부터, 2단계 Exec 개요(미결재·현금잔고·법인 인건비) 실연동 + 매출계열은 '준비중'. 성능은 탭 진입 시 `Promise.all` 1회 배치. 더미 회사명(`수연의원`/`지점 A`)은 `companies` 실데이터로 대체. **모바일 동일 화면 병행 확인 필요**.

### B-2. localStorage 전용 관리데이터 (admin-01 알림자동화 / admin-02 예산)
- **admin-01 핵심 발견**: '연차촉진' 자동발송은 **이미 서버 cron으로 동작 중**(`wrangler.toml [triggers]`→`/api/cron/annual-leave-promotion`→`dispatchAnnualLeavePromotions`, 멱등). 진짜 결함은 (1) **토글이 무력** — dispatch가 `enabled/step1/step2` 설정을 안 읽어, 관리자가 화면에서 꺼도 cron은 무조건 발송 (2) **급여 자동발송은 트리거 cron 자체가 없음**(100% 장식).
- **admin-02**: 예산 설정·집행이 `localStorage` 전용(서버 테이블 전무). 자동발송 요건 없는 순수 CRUD.
- **권장(2단계 분리 발주)**:
  - **1단계[소/저, 즉시]** — admin-01 설정 5종을 기존 `system_settings`(key=`notification_automation_v1`)로 이관(`lib/leave-policy-settings.ts` 패턴 복제, 신규 테이블 불필요) + `annual-leave-promotion-dispatch.ts`에 설정 load 가드 추가(기본값 '켜짐'으로 회귀 방지). → 이미 도는 연차 cron이 토글을 존중하게 됨(비용 대비 효과 최대).
  - **2단계[중/저]** — admin-02 예산: `budget_settings`·`budget_executions` 테이블 신설(마이그레이션) + `supabase.from()` CRUD. MSO 설계상 `company` 컬럼 추가 검토.
  - **별건[중/중]** — 급여 '매월 N일 자동발송'은 신규 cron(`/api/cron/payroll-notice`+dispatch+멱등 테이블) 설계 필요 → 1단계에 끼우지 말고 별도 과제.

## C. 필수 후속 (deploy/결정 단계)

1. **마이그레이션 적용(wrangler)**: `0013_missing_feature_tables.sql`(미존재 테이블 5종) + `0014_room_read_cursors_unique.sql`(read-cursor 유니크) — `npx wrangler d1 execute <DB> --remote --file=…`. **미적용 시**: 0013은 5개 기능 여전히 무음실패, 0014는 `onConflict`가 'no matching constraint' 오류. (기존 `0007` 선례와 동일하게 배포와 함께 적용)
