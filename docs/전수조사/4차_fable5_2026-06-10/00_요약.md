## 검증자가 기각/강등한 항목 (Fable5 자가 교정)

- **기각** `lib-06`(오프라인 큐 네트워크 분류 오류, 감사자 major) — 검증자: 전제 오류. 실제 브라우저 fetch 실패는 `Failed to fetch`/`NetworkError`/`Load failed`로 reject되어 `isNetworkError`가 정상 매칭. 리터럴 `'Network error'`는 비-Error throw 폴백일 뿐. 큐잉 정상 동작. → 감사자≠검증자 분리가 자기 오탐을 잡은 사례.
- **강등** `lib-04`(매 요청 DDL, major→minor) — `IF NOT EXISTS`는 존재 시 저렴한 no-op이라 round-trip 1회 수준. 단 동일 사안을 sql-01/api-3은 major 유지(아키텍처상 잘못된 위치).

## Sonnet(4차) 대비 차이 — Fable5가 더 잡거나 바로잡은 것

**Fable5가 critical로 정정(Sonnet은 minor로 과소평가):**
- 모바일 조직도/근무현황 `company='전체'` — Sonnet 4차에서는 m-5/m-6 **minor**. Fable5는 정책 PUBLIC_ALL과 연결해 **테넌트 PII 유출 critical**로 격상. (정확)

**Fable5 신규(Sonnet 4차 미검출):**
- `stock-consume` db.transaction 프로덕션 실패(lib-01) — Sonnet은 inventory transaction을 major lib로만 언급, 실라우트 연결·critical 격상 못 함
- `contains` op 400으로 .contains() 쿼리 전부 실패(lib-02)
- count 전 행 로드 잠재 DoS(lib-03/sql-06), rate-limit TOCTOU(lib-05), limit+range 중복 LIMIT(sql-05), filterByPolicy N+1(sql-02)
- 경조사 위장 저장(hr-02), 조기퇴근 회사필터 없음(hr-03)
- 알림자동화 localStorage 미동작(admin-01), 감사 심야판정 UTC/KST 오류(sql-10), APPROVAL_SCOPE 프록시 검사(admin-09), system master UUID claim 비활성(lib-11)

**Sonnet에 있었고 이번 완주본 Fable5가 직접 재현 안 함(여전히 유효):**
- GlobalSearch 모지바케 `'?쒕ぉ ?놁쓬'`(Sonnet C-1) — 이번 common 패스는 다른 파일에 집중해 미재현. 별도 보고서 [05_PC_공통기타.md](../4차_2026-06-10/05_PC_공통기타.md) 유효.
- 미존재 테이블 5종(education_completions·email_queue·leave_policies·nurse_schedules·work_type_change_history) — 완주본은 nurse_schedules(hr-01)만 명시. 나머지는 1차 Fable5 sql 패스 + Sonnet + Opus 직접 검증으로 확정. **테이블 신설/기능제거 결정 필요(미해결)**.
- 한글 컴포넌트명 lint 사각지대(222건 오탐) — tsc/eslint는 모델 무관이라 재실행 안 함. [05](../4차_2026-06-10/05_PC_공통기타.md) 유효.

**결론**: 두 모델이 헤드라인 critical(연차 sync 인증·nurse_schedules·매요청 DDL)에 일치. 그 위에 **Fable5는 정책-클라이언트 결합(테넌트 격리), D1 트랜잭션 실패, 쿼리 라우트 잠복버그**를 더 깊게 잡았고, 모바일 테넌트 유출의 심각도를 바로잡았다. Sonnet 보고서의 UI/표면 항목(모지바케·lint)과 상호보완.
