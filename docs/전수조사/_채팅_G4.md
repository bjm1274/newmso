### SEC 보안 (업로드 검증·파일타입)

**SEC-1 [높음] 서버 업로드에 MIME/확장자 화이트리스트 없음 — 임의 파일타입 업로드 허용**
- 코드: `app/api/chat/upload/route.ts` L103-125 `validateUploadTarget` 은 파일명 공백·크기만 검사, 타입 제한 없음. `normalizeUploadMimeType`(L68)은 미지 확장자를 `application/octet-stream` 으로 통과.
- 근거: 클라이언트 `<input accept=...>`(`메신저컴포저.tsx` L411)은 UI 힌트일 뿐 우회 가능. `.html/.svg/.exe` 등이 R2에 저장되고 공개 URL로 서빙되면 stored-XSS/멀웨어 배포 위험.
- 조치: 서버에서 허용 MIME/확장자 allowlist 강제(거부 시 415). SVG는 특히 차단 또는 sanitize.

**SEC-2 [중간] R2 저장 URL이 inline 서빙되면 HTML/SVG stored-XSS 가능**
- 근거: SEC-1 와 연계. 업로드 응답 `url` 을 그대로 `<a target=_blank>`/iframe(`메신저첨부미리보기.tsx` L495 pdf iframe, L500 새창)으로 연다. Content-Disposition/Content-Type 강제 없으면 브라우저가 HTML 실행.
- 조치: R2 오브젝트에 `Content-Type` 고정 + 다운로드는 `Content-Disposition: attachment` 강제(이미 buildStorageDownloadUrl 경유 다운로드 존재, 미리보기 inline 경로 점검 필요).

**SEC-3 [낮음/의심] 멀티파트 폴백 경로 크기 한도 불일치**
- 코드: route L172 `contentLength > 52_428_800`(50MB) 으로 멀티파트 거부하지만, 동영상 한도는 200MB(L116). 즉 동영상 직접업로드 실패→서버폴백(`uploadViaAppServer`, 업로드훅 L242) 시 50MB 초과 동영상은 413으로 막힘.
- 조치: 폴백 한도를 video 한도와 정합화하거나, 폴백은 이미지/문서 전용임을 명시.
