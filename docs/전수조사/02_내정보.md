- **확인**: `approval_documents` 테이블은 D1 스키마에 **없음**(정본은 `approvals`). `notifications`에는 `staff_id`/`read` 컬럼 **없음**(정본 `user_id`/`read_at`).
- **영향**: 모바일 홈 "미결재"·"안 읽은 알림" 카운트가 항상 0(또는 silent catch).
- **조치**: `approval_documents→approvals`, `status 'pending'→'대기'`(한글 상태 확인), `notifications`: `staff_id→user_id`, `.eq('read',false)→.is('read_at',null)`.

### [S-2] ✅ 계약 서명 완료 알림 insert가 미존재 컬럼/무효 FK 사용
- **위치**: `app/main/기능부품/마이페이지/index.tsx:318-324`
- **확인**: `notifications` 정본 컬럼은 `body`인데 `message`에 insert. `user_id:'system_admin'`은 `staff_members` FK에 해당 행 없음(위반 가능). `read_at:null`은 정상.
- **영향**: insert 실패 또는 알림 본문 누락. 모바일 알림목록은 `body` 기준이라 내용 안 보임.
- **조치**: `message→body`, `user_id`를 실제 HR 담당자 staff id로.

### [S-3] ✅ 출퇴근 근무상태 토글: 읽기/쓰기 테이블 불일치
- **위치**: `출퇴근기록/index.tsx` — 읽기 `:380 from('attendance').eq('date',...)` vs 쓰기 `:746 from('attendances').eq('work_date',...)`
- **확인**: `attendance`와 `attendances`는 **서로 다른 별개 테이블**(둘 다 존재, 컬럼 상이: date vs work_date). 토글 결과는 `attendances`에 쓰지만 화면 복원은 `attendance.current_status`를 읽음.
- **영향**: 휴게/점심/외근 토글이 새로고침 시 항상 '근무중'으로 리셋. `attendances` 행은 퇴근 시점에야 생성되어 매칭 행 부재 가능.
- **조치**: 읽기/쓰기 테이블 일치.
