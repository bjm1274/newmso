## ★특별임무: 세금/보험 계산식 중복(D)

### D-1 [높음] 소득세 누진세표 4중 정의 — 값까지 분기
동일한 소득세 누진세표가 서로 다른 형식/값으로 4곳에 존재한다.

1. **정본** `lib/use-tax-insurance-rates.ts:33-42` `DEFAULT_INCOME_TAX_BRACKET`
   - `deduction`(누진공제) 모델: `{min,max,rate,deduction}`
2. **중복A** `lib/salary-compliance.ts:105-116` `calculateTaxesAndInsurance`
   - `base_tax`(누적세액) 모델 하드코딩: `840_000 / 6_240_000 / 15_360_000 / 37_060_000 …`
   - DB 회사별 `tax_insurance_rates` 테이블을 **완전히 무시** → 회사가 세율표를 커스텀해도 반영 안 됨
3. **중복B** `app/.../급여명세/급여시뮬레이터.tsx:32-46` `calcIncomeTax`
   - 중복A와 **글자 단위로 동일한** 하드코딩 누적세액표. (LIVE 컴포넌트, 급여관리.tsx에서 렌더됨)
4. (정본의 DB연동 경로) `fetchTaxInsuranceRates` → `calculateMonthlyIncomeTax`

→ 세율이 바뀌면 4곳을 따로 고쳐야 하며, 현재도 모델이 달라 **결과가 미세하게 갈릴 수 있음**.
**권고:** `salary-compliance.ts`와 `급여시뮬레이터`는 `calculateAnnualIncomeTax(taxable, rates)` 호출로 대체.

## DBG/SEC D1 정본 컬럼 무음실패 의심

### DBG-1 [높음] 잘못된 컬럼 읽기 — `meta_data` vs `deduction_detail`
`payroll_records` 테이블 정본 컬럼은 `deduction_detail`(schema:1566) 및 비과세 항목 개별 컬럼 `meal_allowance / vehicle_allowance / childcare_allowance / research_allowance`(schema:1545-1549). 그러나:
- `세전세후비교.tsx:81` `const meta = record?.meta_data || {}` → `meta_data`는 payroll_records에 **없는 컬럼**(schema:100의 `meta_data`는 다른 테이블). 항상 `{}` → 항상 `insuranceFallback`(추정값)로 대체. 실제 확정 공제액이 표시 안 됨.
- `비과세한도체크.tsx:87` `record?.meta_data` 동일 문제. 비과세 금액이 항상 0으로 읽혀 **초과 탐지가 영구히 작동 불가**. (게다가 죽은코드)
- 두 파일 모두 `try/catch`로 에러를 삼켜(`setRecords([])`) D1 무음실패를 가림.

### DBG-2 [중간] 세금자동신고 회사 필터
`세금자동신고.tsx:30` `selectedCo = '전체'` 기본값으로 `tax_reports`를 `.eq('company_name', selectedCo)` 조회/저장(L114,L246). 실제 회사명으로 저장된 신고건은 '전체' 조회 시 안 잡힘(현재는 죽은코드라 영향 제한적).
