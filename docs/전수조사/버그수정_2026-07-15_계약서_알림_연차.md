# 버그 전수조사·수정 (2026-07-15)

## 보고된 증상

1. 직원에게 근로계약서 서명 요청을 보내도 직원 화면에 안 보임
2. Windows 설치형(Electron)에서 알림/메시지 팝업이 안 뜸
3. 직원 연차 잔여 일수가 화면마다 다르게 보임

---

## 1. 근로계약서 미표시 — **수정 완료**

### 원인

`lib/db/auth/policies.ts` 에서 `employment_contracts` 가 **ADMIN_ONLY** 로 등록되어 있었음.

| 역할 | 발송(insert) | 조회(select) | 서명(update) |
|------|--------------|--------------|--------------|
| 관리자 | ✅ | ✅ | ✅ |
| **일반 직원** | ❌ | **❌ (빈 결과)** | **❌ 403** |

직원이 로그인해도 `status = '서명대기'` 조회가 정책 필터로 전부 걸러져 **서명 모달이 절대 뜨지 않음**.  
서명 시도도 update 거부.  
추가로 `onboarding_checklists` 도 ADMIN_ONLY 라 서명 후 체크리스트 동기화도 실패 가능.

### 수정

- `employment_contracts`
  - select/update: `SELF_OR_SAME_COMPANY` (본인 + 같은 회사 매니저)
  - insert: `ADMIN_OR_MANAGER`
  - delete: `ADMIN_ONLY`
- `onboarding_checklists`: 본인/같은 회사 매니저 select·insert·update 허용
- 발송 알림 type `INFO` → `인사` (기본 알림 설정 키와 정합)

### 배포 후 확인

1. 관리자: 계약 현황에서 직원 선택 → 서명 요청 발송
2. 해당 직원 계정 로그인 → 즉시 전자서명 모달 또는 마이페이지 서류 탭에 “서명대기”
3. 서명 완료 → 상태 `서명완료`, 문서보관함/급여·증명서에서 확인

## 2. Windows 설치형 알림 팝업 — **수정 완료 (클라이언트 재빌드 필요)**

### 원인

| 이슈 | 설명 |
|------|------|
| AppUserModelId 시점 | `app.setAppUserModelId` 가 `ready` **이후**에만 호출 → Windows 토스트가 안 뜨거나 익명 앱으로 뜸 |
| 아이콘 실패 | 아이콘 경로 오류 시 토스트 자체가 실패하는 경우 |
| 트레이 숨김 | 창 hide 시 인앱 토스트는 안 보이고 OS 토스트만 의존 |
| 폴백 부재 | 네이티브 Notification 실패 시 트레이 balloon 미사용 |

웹 쪽 알림 파이프라인(IPC `allerpDesktop.showNotification`) 자체는 이미 구현되어 있었음.

### 수정

- `electron-app/main.js`
  - AppUserModelId 를 **ready 이전**에 설정
  - 아이콘 존재 시에만 지정
  - show/failed 로그, 실패·창 숨김 시 **트레이 balloon 폴백**
- `알림시스템.tsx`
  - Electron 에서는 인앱 토스트 강제 표시
  - Electron 네이티브 팝업 재시도 경로

### 배포

```bash
cd electron-app
npm run build
```

직원 PC에 **AllERP Setup 1.1.0+** 재설치 필요.  
웹만 배포해도 인앱 토스트 개선은 반영되나, OS 토스트 수정은 설치형 재빌드 필수.

## 3. 연차 잔여 불일치 — **수정 완료 (잔액 재계산 권장)**

### 원인

`leave_balances` 재계산 로직이 문서 SSOT 와 불일치.

| 항목 | 문서 SSOT | 버그 구현 | 결과 |
|------|-----------|-----------|------|
| 발생 일수 | 1년+ → **최신 annual:N 만** | **모든 annual 합** (15+15=30) | 총 연차 과다 |
| 사용 일수 | **당해 연도** 승인분 | **전 기간** 합 | 사용 과다 → 잔여 과소 |
| 화면 | 직원 `useAnnualLeaveSummary` vs 관리자 `remaining_days` vs 대시보드 `?? 15` | 서로 다른 소스 | 숫자 제각각 |

### 수정

- `resolveGrantedDaysFromAccruals`: 최신 `annual:N` 또는 monthly 합
- `recalculateLeaveBalance`: `syncAnnualLeaveUsedForStaff(..., { year })` 당해만
- 클라이언트 원장 집계: DB `days` 우선, `연차(부여)` 제외 (서버와 동일)
- `useAnnualLeaveSummary`: `remaining_days` 정합 사용, `days` 컬럼 select
- 관리자 대시보드/알림자동화: `?? 15` 폴백 제거 → `0`
- 모바일 연차관리자: KST 연도

### 기존 데이터 재계산

코드 배포 후 관리자 또는 서버에서 일괄 재계산:

- API: `POST /api/admin/annual-leave/diagnose?rebalance=1` (또는 기존 diagnose rebalance)
- 스크립트: `scripts/rebalance-leave-balances.mjs`

재계산 전에는 DB 에 잘못된 total/used 가 남아 있을 수 있음.
