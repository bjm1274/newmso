## 0. 가장 중요한 발견 — 실데이터로 확인된 거액 과소 원천징수

코드 추론이 아니라 **실제 저장된 2026-02 확정 급여 레코드**(`backups/payroll_delete_20260326_173546/...json`)를 분석한 결과:

### 🔴🔴 [실증] 소득세가 `total_taxable × 3%` 단일세율로 저장됨 → 누진세 대비 거액 과소

| 레코드 | 과세소득 | 저장 소득세 | 검산 | 정상 누진세 | 월 과소액 |
|---|---|---|---|---|---|
| A (원장급, base 5,000만) | 50,000,000 | **1,500,000** | =50,000,000×3% ✓ | 15,122,880 | **−13,622,880원** |
| B (직원, base 400만) | 4,000,000 | **120,000** | =4,000,000×3% ✓ | 295,150 | **−175,150원** |

- 레코드 A는 연 6억 소득(42% 구간)인데 **3%만 원천징수** → 연 환산 약 **1.6억원** 과소 징수.
- 지방소득세도 소득세×10%로 함께 과소.
- **개발팀도 이미 인지**: `scripts/audit_payroll_records.js`가 `looks_like_legacy_three_percent_tax` 플래그로 이 패턴을 탐지하고, `repair_payroll_records.js`가 간이세액표로 재계산하는 도구를 만들어 둠(단 dry-run 기본, 미적용 상태로 추정).

### 🔴 [실증] 국민연금 보수월액 상한 미적용이 실데이터에 발현
- 레코드 A 저장 NP = **2,250,000원** = 50,000,000 × 4.5%(상한 미적용 + 구 요율). recheck 재계산도 2,375,000원(50,000,000 × 4.75%)으로 **여전히 상한 미적용**. 정상은 상한 6,370,000 × 4.75% ≈ 302,575원.
- 2차 D-2(건보 상한 없음)에 더해, **국민연금 상한도 저장 당시 미적용**됐음이 실증(현재 코드 `payroll-deductions.ts:50`은 NP 상한 적용으로 고쳐졌으나, 2월 데이터는 미적용 코드로 저장됨).

### 🔴 [실증] top-level 보험/세금 컬럼 미저장 (2차 추론 확인)
- 두 레코드 모두 `national_pension`/`health_insurance`/`income_tax`/`local_tax` top-level 컬럼이 **없고 `deduction_detail` JSON에만** 존재. → 명세서·EDI가 fallback 재계산 시 divergence(2차 E-신규 확인).

### [실증] net_pay 공식은 맞으나 advance_pay 미차감 (audit/repair 공통 결함)
- 검산: A 50,000,000+0−6,352,037 = 43,647,963 ✓ / B 4,000,000+400,000−508,163 = 3,891,837 ✓.
- 단 `audit.js:74`·`repair.js`가 `net = taxable+taxfree−deduction`만 쓰고 **advance_pay를 빼지 않음** → 선지급 있는 레코드 수리 시 실수령액 과다.

### [실데이터 한계] 통상시급·비과세 버그는 이번 2건에선 미발현
- 2건 모두 정상 입사자(중도입사 proration 없음), 비과세 20만 이내, overtime 0 → 2차 A-1/D-1 버그를 **실증할 케이스가 이 2건엔 없음**(버그 부재가 아니라 표본 부족).

> **메타 결론**: 실제 운영 데이터에 **소득세 3% flat·연금 상한 미적용**이라는 거액 오류가 박혀 있고, 개발팀이 audit/repair 도구까지 만들었으나 **정산 코드 근본 수정·데이터 일괄 보정은 미완**으로 보인다. 이게 가장 시급하다.

### N-1 [확정🔴] 간이세액표 미등록 시 소득세 0원 확정 저장
- **위치**: `payroll-deductions.ts:65-71` — `hasExactIncomeTaxBracket(rates)`가 false면 `income_tax=0`. `DEFAULT_INCOME_TAX_BRACKET`(누진 폴백)은 `official:false`라 이 분기를 **절대 통과 못 함**. 세율보험요율관리의 "기본 누진세율 불러오기"도 `official_confirmed:false`로 저장.
