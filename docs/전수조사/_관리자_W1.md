### 2. 대시보드 간 집계 중복 (D)
- 연차 사용률 집계가 `경영대시보드`(line 34-36)와 `커스텀대시보드 leave_usage`(line 67-74)에 중복 구현, 반올림 단위만 다름 (D-2).
- 재고 부족(low stock) 판정이 `경영대시보드`(`<=`)와 `커스텀대시보드`(`<`)로 임계 불일치 (D-3, Q-1).
- 법인 인건비 집계가 `법인손익현황`과 `통합보고서 급여요약`에서 각각 다른 소스(payroll_records vs staffs.base_salary)로 산출 → 수치 불일치 가능 (Q-2).

### 3. admin-menu-config 라우팅/alias 정합
- `ADMIN_TAB_ALIASES`, `ADMIN_PARENT_SUBVIEW_MAP`, `normalizeAdminEntry` 로직은 정합. 한글 id ↔ 영문 워크센터는 별도 라우팅(`isAdminWorkcenterId`)으로 분리되어 충돌 없음.
- 단 `admin-types.ts`의 `ADMIN_WORKCENTER_ALIAS`(한글→영문 매핑 테이블)는 **어디서도 import되지 않는 죽은 코드** (X-1).

### 4. 관리자 권한 게이팅 (isSystemMaster)

- **주의(SEC-1)**: 영문 워크센터 라우팅(line 231 `isAdminWorkcenterId`)은 `hasAdminMenuAccess`만 통과하면 진입. 6 워크센터 내부의 세부 탭(감사·급여이상치·회사관리 등)은 `canAccessAdminSection` 세부 권한 검증 없이 전부 노출됨. 기존 한글 흐름은 `visibleOperationsTabs`/`visibleAuditTabs`로 탭 단위 게이팅하나, 워크센터 흐름엔 그 게이팅이 없음.

## 발견 상세 (파일:줄 + 코드 인용)

### D 집계중복

**D-1 [높음] 법인손익 인건비: interim 미필터 + gross_pay 미조회 → 이중/과소 집계**
`app/main/기능부품/관리자전용서브/법인손익현황.tsx:55-57`
```ts
supabase.from('payroll_records').select('staff_id, total_taxable, total_taxfree').eq('year_month', yearMonth),
```
- `payroll_records`에는 `gross_pay`, `record_type` 컬럼 존재(schema.ts:1540~). `getPayrollGrossPay`(lib/payroll-records.ts:1-8)는 `gross_pay` 우선 사용하나, 여기선 `gross_pay`를 select하지 않아 항상 taxable+taxfree fallback 경로만 탐.
- 더 심각: `record_type='interim'`(중간정산) 레코드를 `filterNonInterimPayrollRecords`로 거르지 않음. 동일 (staff_id, year_month)에 interim+정규 레코드가 있으면 `reduce`가 둘 다 더해 **인건비 이중 집계**. (uniqueIndex가 record_type 포함이므로 공존 가능 — schema.ts:1577)
- 조치: select에 `gross_pay, record_type` 추가 후 `filterNonInterimPayrollRecords` 적용.

**D-2 연차 사용률 집계 중복**
`관리자전용서브/경영대시보드.tsx:34-36` vs `커스텀대시보드.tsx:67-74` — 동일 `annual_leave_total/used` 합산·비율 계산 로직 중복. 공통 유틸로 추출 권장.

**D-3 재고 부족 판정 임계 불일치**
`경영대시보드.tsx:32` `quantity <= minimum` vs `커스텀대시보드.tsx:52` `(i.quantity ?? 0) < (i.min_quantity ?? 0)`. 같은 "재고 이상" 지표가 화면마다 다른 결과.

### SEC 보안(권한·접근제어)

**SEC-1 [중] 워크센터 경로 세부 탭 권한 게이팅 부재**
`관리자전용.tsx:231-243` 영문 워크센터는 `hasAdminMenuAccess`(메뉴 진입권)만으로 렌더. 내부 감사로그/급여이상치/회사관리/직원권한 탭이 `canAccessAdminSection`(세부 권한) 검증 없이 전부 열림. 기존 한글 흐름(line 137-144 `visibleOperationsTabs`/`visibleAuditTabs`)에 있던 탭 단위 게이팅이 워크센터엔 없음.

**SEC-2 [중] RolesWorkcenter/AuditWorkcenter user=null 전달**
`RolesWorkcenter.tsx:40` `<StaffPermissionManager onRefresh={undefined}/>`, `AuditWorkcenter.tsx:208` `<AccessAuditLog user={null}/>`, `FormsWorkcenter.tsx:133` `<ApprovalFormTypesManager user={null}/>` — 하위 컴포넌트가 user로 회사 스코프/권한 분기 시 null이면 전사 데이터 노출 또는 오동작 가능. 워크센터 시그니처에 user prop 자체가 없음(OpsWorkcenter만 user 받음).

`CompanyBasicTab.tsx:157-187` `companies.delete().eq('id', id)` — companies는 staff_members·approvals·board_posts 등 다수 테이블의 참조 대상(schema FK). D1에서 FK 미설정 시 고아 레코드, 설정 시 삭제 실패가 catch로 무음 처리되어 로컬 state만 제거(실 DB와 불일치). 삭제 전 참조 카운트 확인 필요.
