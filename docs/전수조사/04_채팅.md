## 🔴 기타 심각도 높음

### [Q] `메신저방데이터훅.ts`(1797줄) God Object — 단일책임 위반
- 목록·요약·unread·메타·페이지네이션·점프를 한 훅에 응집. 분리 의도였던 `메신저방목록훅`은 死 메신저메시지조회훅만 참조해 사장(G2). → 책임 분리 재설계 필요.

### [D] 방 요약/영속화 6개 함수 바이트 단위 중복
- `메신저방데이터훅` ↔ `메신저방목록훅`(死) 간 요약빌드/영속화 중복(G2 D-1).

### [P] 폴링 중복·과도
- **타이핑 폴링 2중 실행**(✅): `useChatTypingD1`이 `useChatRealtimeBridge.ts:135`와 `메신저.tsx:1149` 양쪽에서 호출 → 2.5s GET 폴링 화면당 2개. bridge의 `emitTypingState`는 미사용 죽은 반환(G5 D-1/P-1).
- **메시지 폴링 동시 가동**: 전역 4s + 활성방 1.5s 동시(G5 P-2).
- `fetchData`(방데이터훅:1430)가 `.limit()` 없이 방 메시지 전량 로드(G2 P-1) + 매 호출 `fetchAllChatRooms({force:true})`로 전체 방+멤버repair+unread 배치 연쇄(per-room HEAD 폭발, G2 P-2).

### [SEC] 첨부 업로드 MIME 화이트리스트 부재 (✅ 확인)
- `app/api/chat/upload/route.ts` — MIME 정규화(`MIME_BY_EXTENSION`)는 있으나 **위험 타입 차단/거부 없음**. 크기만 검증. 클라 `<input accept>`는 우회 가능 → `.html/.svg` 등 R2 저장·공개 서빙 시 stored-XSS 위험. inline 서빙 + 폴백 50MB vs 동영상 200MB 한도 불일치(G4 SEC-1~3).

### [SEC] ✅ 모바일 오프라인 첨부가 legacy `chat_messages` 테이블 타겟
- `모바일/채팅/업로드.ts:183` `table: 'chat_messages'` — 정본은 `messages`. `chat_messages`(schema.ts:328)는 file 컬럼 없는 레거시 → 오프라인 전송 파일 메시지 영구 유실(G8 SEC-1). ※ 주석(line 5,144)은 "messages insert"라 코드-주석 불일치.

### [E] ✅ audit_logs `details`에 raw 객체 전달 → 감사로그 손실
- `메신저액션훅.ts:237`, `메신저상태훅.ts:217` — 정본 패턴은 `JSON.stringify`([lib/audit.ts:182](../../lib/audit.ts:182)). `details: text()` 컬럼에 객체 전달 시 `"[object Object]"` 저장/무음 실패(G7 E-1).

### [T] `MessengerModalHost.tsx:19` `controller as any` (50여 prop 타입검증 전무) — 죽은코드라 삭제로 해소(G7 T-1).
