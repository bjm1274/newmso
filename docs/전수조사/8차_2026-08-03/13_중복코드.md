## 요약

정량 지표는 뚜렷하게 개선됐다. jscpd 4.2.5 동일 조건 재스캔 결과 **중복률 3.35% → 2.44%(−0.91%p)**, 클론 476 → 390(−18.1%), 중복 라인 9,902 → 7,025(−2,877). 7월 로드맵 Phase C 의 고아 파일 삭제(`대시보드통합뷰.tsx`·`감사로그뷰어.tsx`·`시스템마스터서브.tsx` 등)가 실제로 반영돼 48개 파일쌍이 소멸했다.

그러나 **수치 개선과 결함 감소는 별개다.** 이번 라운드에서 확정된 P1 6건은 전부 "중복이 이미 갈라진(drift) 결과 생긴 실동작 버그"다. 급여 명세서의 지급−공제≠실지급(D12-007), 인사탭으로 낸 연차가 행정팀 참조함에 영원히 안 뜨는 문제(D12-005), 모바일 출결정정의 유령 신청(D12-004), 마스터 계정이 13개 API 에서 401(D12-002) — 모두 "SSOT 가 있는데 위성 사본이 그 개선을 못 받은" 형태다.

핵심 구조는 하나다. **SSOT 를 만들어도 기존 사본을 회수하지 않으면 SSOT 는 다섯 번째 사본일 뿐이다.** `lib/d1-api-helpers.userId` 는 정본인데 13개 route 가 로컬 재정의를 유지하고, `lib/upload-mime.ts` 는 정본인데 board 가 통째로 복사해 갖고 있고, `canMutateTeamAbnormal` 은 같은 디렉터리에 export 돼 있는데 4개 탭이 인라인으로 재구현한다.

## A. drift 가 이미 발생한 중복 (= 버그)

두 사본의 동작이 **현재 시점에 실제로 다른** 항목이다. 통합은 리팩터링이 아니라 버그 수정이다.

### D12-002 · P1 · userId() SSOT 의 시스템마스터 분기가 13개 위성 사본에 없다 — 마스터 세션이 13개 API 에서 401

- **근본원인 축**: S4 세션 스냅샷·권한 압축으로 서버측 권한 판정 붕괴
- **위치**: `lib/d1-api-helpers.ts:10-18`(정본), `app/api/realtime/stream/route.ts:12-17`, `app/api/realtime/tail/route.ts:31-36`, `app/api/chat-rooms/route.ts:42-47`, `app/api/inventory/po-receive/route.ts:35-38`, `app/api/auth/master-login/route.ts:178-196` (+ `chat-rooms/[id]:40`, `inventory/{po-inspect:31, closing:35, stock-post:66, stock-update:26, stock-transfer:76, stock-consume:31}`, `d1/rpc/{register-staff:100, increment-post-views:28}`)
- **결함**: 정본은 시스템마스터 분기를 갖는다.

  ```ts
  // lib/d1-api-helpers.ts:12
  if (user.is_system_master === true || user.login_id === '9999' …) return '9999';
  ```

  13개 route 의 로컬 `userId` 사본에는 이 분기가 없고 `user.id ?? user.user_id` 만 본다. 반면 `master-login` 의 마스터/관리자 fallback 세션은 `:178-196`·`:301-317`·`:397-415` 세 곳 모두 `id: null, employee_no: '0', is_system_master: true` 다(마스터 로그인은 staff row 조회 자체를 하지 않아 예외 없이 `id:null`). 게이트가 로컬 `userId` 결과에 직결된다 — `stream:37` `if (!userId(session?.user)) return 401`, `chat-rooms:103-105`, `po-receive:85-87` 동일 패턴.
- **도달 경로**: env 마스터 계정으로 로그인 → 세션 `user.id=null, is_system_master=true` → 실시간 스트림/tail·채팅방 목록·재고 7종 route 전부 401. **동일 세션이 `/api/d1/query|mutate` 는 정상 통과한다**(`d1/query:270`·`d1/mutate:388` 이 SSOT 를 import) — 경로별로 인증 결과가 갈린다.
- **영향**: 시스템 마스터가 실시간 스트림·채팅방·재고 수불·직원등록 API 를 쓰면 기능 전면 불능 + 감사 로그 actor id 불일치가 동시에 성립.
- **검증**: falsifier(세션 저장 레이어가 id 를 보충) 소진 — `normalizeSessionUser`(`server-session.ts:163`)는 `id: normalizedProfile?.id ?? null` 로 null 을 그대로 유지하고 `createSessionUserSnapshot`(`:309`)도 `login_id` 를 `id` 로 복사하지 않는다. `readSessionFromRequest` 는 staffId 가 빈 문자열이면 force-logout 검사만 건너뛰고 세션을 그대로 반환하므로 마스터 세션이 살아서 13개 route 에 도달한다. `grep -L '9999'` 로 13개 사본 전량 실측. **권한 우회(더 열림)가 아니라 과차단이므로 P0 아닌 P1.**
- **수정 방향**: 13개 route 의 로컬 `userId` 를 삭제하고 `import { userId } from '@/lib/d1-api-helpers'` 로 교체(시그니처 동일, 기계적 치환). (난이도 S · 회귀위험 중 · 묶음 FB3 세션 권한 복원 · **선행 없음 — 최우선 착수 가능**)

  `record.net_pay` 는 기타공제·가불까지 반영된 값인데 표시용 `totalDeduction` 은 그 항목들을 빠뜨리므로 등식이 깨진다.
- **도달 경로**: 기타 공제가 입력된 직원이 모바일 마이페이지 > 급여명세서를 열면 즉시 재현. 공유 텍스트의 '지급/공제/실지급' 3값에도 그대로 반영된다.

### D12-001 · P1 · 업로드 파일명 정규식이 공백~'<' 범위를 삭제 — 숫자·점·괄호가 사라지고 제어문자는 통과 (→ D07-013 병합)

- **근본원인 축**: S13 중복 구현 drift · **병합**: → D07-013(재고·게시판 문서 소관)

  ```
  chat:73 · approvals:38   [ -<>:"/\|?*]+     ← 0x20-0x3C range (hex dump 확인: 5B 20 2D 3C …)
  board:92                 [\x00-\x1f<>:"/\|?*]+   ← 정상
  ```

  결과: 숫자 0-9, 마침표, 하이픈, 괄호, 쉼표 등 인쇄가능 문자 전부가 공백으로 치환되고 **정작 막아야 할 제어문자(0x00-0x1F)는 통과**한다. node 실측: `'결산 2026-07.pdf'` → `'결산 pdf'`, `'report_2026.pdf'` → `'report_ pdf'`, `'a\x01b.txt'` → `'a\x01b txt'`(제어문자 잔존).

- **영향**: 결재 첨부의 표시 파일명에서 확장자·날짜·버전 표기가 소실된다('보고서 pdf' 만 남음).

- **수정 방향**: 세 route 의 `normalizeUploadFileName` 을 `lib/upload-mime.ts`(또는 신규 `lib/upload-filename.ts`)로 추출하고 board 의 올바른 정규식으로 통일. (난이도 L · 회귀위험 중 · 묶음 FB12)
