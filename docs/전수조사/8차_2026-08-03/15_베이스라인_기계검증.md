### 4-6. 실측 — mutate 판정 대상 = 실제 SQL 대상 (7차 A12-01 의 현재 구현)

`loadPolicyRowsForMutation`(`app/api/d1/mutate/route.ts:246-291`):

```ts
// UPDATE/DELETE 정책 판정 대상 행을 클라이언트 WHERE 로 실제 조회해서 돌려준다.
const result = await db.run(
  sql`SELECT * FROM ${sql.identifier(table)} WHERE ${sql.join(whereParts, sql` AND `)} LIMIT ${
    MAX_POLICY_ROWS_PER_MUTATION + 1
  }`,
);
if (existing.length === 0) return { rows: [], ... };              // no-op
if (existing.length > MAX_POLICY_ROWS_PER_MUTATION) return { tooMany: true };
return { rows: existing, ... };  // DB 정본 그대로 — set 병합 금지
```

- 판정 대상 = 클라이언트 WHERE 가 실제로 잡는 행 전부(DB 정본). `set` 을 병합하지 않아 소유권 위조가 차단됨
- 컬럼 단위 가드는 `changedKeys`(= set 키)로만 판정(`touchesColumn`, `policies.ts:190-197`)
- 한 번의 mutation 정책 검사 상한 `MAX_POLICY_ROWS_PER_MUTATION = 200`, 초과 시 `TOO_MANY_ROWS` 400

**남은 폴백 위험**: 조회 실패·미허용 시 `fallback = { rows: [{ ...whereProxy, ...setProxy }] }` 로 **합성 가상 행 1개**로 되돌아간다(`:255`, `:257-258`, `:267`, `:287-290`). 발동 조건은 (1) 테이블 미허용 (2) WHERE 없음 (3) **행 무관 패턴(PUBLIC/AUTHENTICATED) + 가드 없음** (4) SELECT 예외.

> ⚠ **베이스라인이 "실질 무해"로 평가한 (3)번 조건이 R2 에서 뒤집혔다.** `daily_closure_items` 처럼 AUTHENTICATED×4 + 가드 없음인 테이블은 이 단축 경로로 인해 **201행 상한조차 적용되지 않는다**(`D01-D03` V11 확인). 9차는 (3)번 조건을 무해로 분류하지 말 것.
