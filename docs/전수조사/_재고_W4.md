## ★ 미존재 테이블/컬럼 목록 (무음 기능불능)

### 1. [치명] `inventory_transactions` 테이블 자체가 정본에 없음 — 모바일 입출고 기록 전면 불능
- 파일: `app/main/모바일/재고/입출고-form.tsx:67-72`
```ts
const { queued, error } = await enqueueSupabaseMutation({
  kind: 'insert',
  table: 'inventory_transactions',   // ← 정본 스키마·POLICY_REGISTRY 어디에도 없음
  payload, ...
```
- 정본: 입출고 이력 테이블은 `inventory_logs` (schema.ts:965). `inventory_transactions`는 코드베이스 전체에서 이 파일에만 등장(Grep 확인).
- 결과: `ALLOWED_TABLES`(=POLICY_REGISTRY 키)에 없어 `app/api/d1/mutate/route.ts:249-253`에서 **403 "Table not allowed"** 반환 → toast "저장 실패"만. **입출고 등록 버튼이 항상 실패.**
- payload 컬럼도 불일치: `transaction_type`, `staff_id`, `reason`은 `inventory_logs`에 없음(정본은 `change_type`/`type`, `actor_id`, `notes`). 테이블명만 고쳐도 컬럼 매핑 재작업 필요.

### 2. [치명] `inventory.unit` 컬럼 없음 — 모바일 물품등록 insert 실패
- 파일: `app/main/모바일/재고/물품등록.tsx:87, 143`
```ts
type InventoryInsertPayload = { ...; unit: 'EA' | 'BOX'; ... }
const payload = { ...; unit: UNIT_TO_DB[v.unit], ... };
await enqueueSupabaseMutation({ kind:'insert', table:'inventory', payload });
```
- 정본 `inventory`(schema.ts:832-868)에 `unit` 컬럼 **없음**.
- `enqueueSupabaseMutation`(`lib/offline-queue-supabase.ts:81-103`)은 payload를 그대로 `supabase.from('inventory').insert()`로 전달 → mutate route가 `INSERT INTO inventory (..., unit, ...)` 생성 → SQLite "no column named unit" → 500 → toast "저장 실패". **모바일 물품 등록 항상 실패.**
- 대조: **자산등록.tsx:187-191**과 **데스크톱 물품등록.tsx:177-179**는 `withMissingColumnsFallback(..., ['department','unit','serial_number'])`로 `unit`을 드롭해 정상 동작. 모바일 물품등록만 이 가드 누락.

### 3. [치명] `inventory_logs.amount` 컬럼 없음 — 재고현황 부서별 사용량 TOP5 항상 빈값
- 파일: `app/main/기능부품/재고관리워크센터/use-status-data.ts:85`
```ts
.select('actor_name,department,amount,change_type,created_at')   // ← amount 없음
```
- 정본 `inventory_logs`(schema.ts:965-989)에 `amount` 없음(수량 컬럼은 `quantity`).
- query route(`app/api/d1/query/route.ts:245-247`)가 요청 컬럼을 그대로 SELECT identifier로 방출 → `SELECT ..., "amount", ... FROM inventory_logs` → "no such column: amount" → 500.
- compat 레이어(`lib/d1-compat/mutation-builders.ts:30-37`)는 throw하지 않고 `{data:null, error}` 반환. hook이 `const { data } = ...`로 **error를 확인하지 않음** → `Array.isArray(null)` → `[]` → `deptUsageTop5` **항상 빈 배열**(무음). 모바일 재고현황에서 사용량 TOP5 표시 부분이 비어있음.
- 참고: 같은 파일 `pickNumber(r, ['amount','qty','quantity'], 1)` 같은 *읽기* 폴백은 `amount` 부재 시 `quantity`로 넘어가 안전하나, 위 *명시 select*가 SQL 자체를 깨뜨림. → `amount` 제거하고 `quantity`로 교체하면 해결.

> 그 외 `use-io-data`/`use-analyze-data`/`use-item-data`는 `select('*')`라 컬럼 오류 없음(읽기 폴백만 사용 — 무해).

## D — 데스크톱·모바일 중복 (3)

1. **입출고/발주 로직 이중 구현**: PC `재고관리서브/스캔모듈완성.tsx`·`발주관리.tsx`가 `inventory_logs`/`purchase_orders` insert를 직접 수행. 모바일 `입출고-form.tsx`(깨진 테이블)·`발주등록.tsx`가 별도 재구현. 입출고는 정본 불일치로 모바일만 불능, 발주는 양쪽 모두 `purchase_orders`로 정상.
2. **UDI 관리**: PC `UDI관리.tsx`(is_udi 필터+CSV) vs 모바일 `물품자산.tsx` UdiPane(`useItemData`로 `udi_code`/`barcode` 필터). 데이터 소스는 같은 `inventory`지만 UI·집계 별도.
3. **수요예측**: PC `재고수요예측.tsx`(90일 로그 기반 자동발주) vs 모바일 `분석마감.tsx` ForecastPane(`useAnalyzeData` 30일). 산식·기간 상이 → 같은 화면에서 다른 예측값.
