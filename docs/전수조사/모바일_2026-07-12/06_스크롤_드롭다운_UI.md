# 06. 모바일 UI 레이아웃 전수조사 — 스크롤 · 드롭다운 · 가림 · 키보드

> 기준일: 2026-07-12  
> 범위: `app/main/모바일/**` + `tokens.css` + `MobileShell` + 관련 훅  
> 초점: **스크롤 불가**, **드롭다운/셀렉트 가림**, **탭바·키보드·z-index 충돌**, 기타 터치 UX

---

## 0. 아키텍처 요약 (왜 스크롤이 깨지기 쉬운가)

```
.mso-mobile          position:fixed; inset:0; overflow:hidden; z-index:1
 └ absolute inset:0 flex column
    ├ .m-screen      height:100%; overflow:hidden; flex column   ← 스크롤 금지 레이어
    │   └ 화면 루트  .m-screen (중첩)
    │       ├ header (sticky)
    │       ├ .m-scroll  flex:1; overflow-y:auto; padding-bottom:88px  ← 유일한 스크롤 의도
    │       └ .m-sticky-foot (선택)
    └ MobileBottomTab  position:fixed; bottom:16px; z-index:999
```

**핵심 규칙**

1. 본문 스크롤은 반드시 **`.m-scroll` (또는 동등한 `overflow-y:auto` + `flex:1; min-height:0`)** 에서만 일어난다.  
2. 조상 `overflow:hidden` + 자식에 `m-scroll` 누락 = **스크롤 완전 불가**.  
3. 플로팅 탭바가 content flow 밖 → **하단 padding 없으면 마지막 항목이 탭에 가림**.  
4. `position:fixed` 오버레이 z-index가 탭(999)보다 낮으면 **탭이 모달을 덮음**.

## 1. Critical — 스크롤 불가 / 내용 절단

### UX-S1. 공유캘린더에 `m-scroll` 없음 (스크롤 불가)

| 항목 | 내용 |
|------|------|
| **파일** | `추가기능/공유캘린더.tsx:79–154` |
| **증상** | 한 달 근무 카드가 많으면 하단이 잘리고 **드래그 스크롤이 안 됨** |
| **원인** | `m-screen`(`overflow:hidden`) 안에 헤더+리스트만 두고 **`m-scroll` 래퍼 없음** |
| **수정** | 헤더 아래를 `<div className="m-scroll">…</div>` 로 감싸기 |

### UX-S2. 내정보 계열 `paddingBottom: 24`가 탭 여백(88px)을 **덮어씀**

| 항목 | 내용 |
|------|------|
| **파일** | `홈.tsx:344`, `연차.tsx:36`, `출퇴근체크인.tsx:541`, `정보수정.tsx:242`, `증명서.tsx:62`, `급여명세.tsx:24` |
| **증상** | 스크롤은 되지만 **맨 아래 버튼/리스트가 플로팅 탭바에 가려짐**. “더 스크롤이 안 되는 것 같다”로 체감 |
| **원인** | CSS `.m-scroll { padding-bottom: 88px }` 인데 인라인 `paddingBottom: 24` / `padding: '16px', paddingBottom: 24`가 **캐스케이드에서 우선** → 88px 무력화 |
| **수정** | 인라인 paddingBottom 제거 또는 `calc(88px + …)` / `var(--m-scroll-pad-bottom)` 사용. 탭 높이 SSOT 토큰화 |

### UX-S3. 나의 할 일 — 이중 스크롤 + `height:100%` 트랩

| 항목 | 내용 |
|------|------|
| **파일** | `나의할일.tsx` + `MFeatureScreen` (`m-scroll` 안에 `height:100%` 컨테이너 + 내부 `.macos-todo-items-scroll { overflow-y:auto }`) |
| **증상** | 목록 스크롤이 먹통이거나 바깥/안쪽이 싸우며 튕김. iOS에서 특히 심함 |
| **원인** | 외곽 `m-scroll` + 자식 `height:100%` + 내부 또 `overflow-y:auto` → flex 높이 확정 실패 시 **내부 스크롤 영역 높이 0 또는 무한 확장** |
| **수정** | (A) 외곽만 스크롤하고 내부 overflow 제거, 또는 (B) 외곽 m-scroll 제거하고 컨테이너 `flex:1; minHeight:0` + 내부 한 곳만 스크롤 |

### UX-S4. 모바일 전역에 **키보드(visualViewport) 보정 없음**

| 항목 | 내용 |
|------|------|
| **파일** | 훅 `app/hooks/useVisualViewportOffset.ts` 존재하나 **`app/main/모바일/**` 에서 import 0건** |
| **증상** | 채팅 입력, 게시판 댓글, 결재/인사 폼 sticky 푸터, select 포커스 시 **소프트 키보드에 입력창·하단 버튼이 가림** |
| **원인** | PC용 `CommentComposerSticky` / `StickyFormFooter` 는 훅 사용. 모바일 채팅 컴포저·`댓글입력.tsx` m-sticky-foot 은 미사용 |
| **수정** | 채팅 컴포저·댓글바·m-sticky-foot에 `translateY(-offset)` 또는 `bottom: offset` 적용. iOS `visualViewport` 필수 |

### UX-S5. 결재 상세 iframe 고정 높이로 내부 문서 스크롤 혼란

| 항목 | 내용 |
|------|------|
| **파일** | `결재/결재상세.tsx:587` `height: calc(100dvh - 210px)`, `minHeight: 480px` |
| **증상** | 바깥 m-scroll + iframe 내부 문서 → **이중 스크롤**, 좁은 화면에서 하단 액션(승인) 도달 어려움 |
| **수정** | 모바일은 요약 카드 + “원문 전체보기” 시트, 또는 iframe 높이를 콘텐츠 연동 / 탭 전환 시 단일 스크롤 영역 |

## 2. Critical / Major — 드롭다운·셀렉트·시트 가림

### UX-D1. 플로팅 탭바(z=999)가 비밀번호 모달(z=50)을 덮음

| 항목 | 내용 |
|------|------|
| **파일** | `MobileBottomTab.tsx:116–131` `zIndex: 999` / `홈.tsx:901–906` 모달 `zIndex: 50`, `position: absolute` |
| **증상** | 급여·증명서 보안 확인 모달이 떠 있어도 **하단 탭이 위에 떠 있음**. 탭 터치로 모달 이탈·가림 |
| **원인** | 모달이 화면 내부 absolute + 낮은 z. 탭은 shell 레벨 fixed + 999 |
| **수정** | 모달 `position:fixed; z-index ≥ 1200` 또는 `createPortal` to body. 열릴 때 탭 숨김 |

### UX-D2. `overflow: hidden` 카드 안의 `<select>` / date — 하단 근처에서 가림

| 항목 | 내용 |
|------|------|
| **대표** | `연차신청폼.tsx:265–308` (card `overflow:hidden` + select), `문서조회.tsx:115–138` select, `입출고-form.tsx` select, `업무가이드.tsx` select, `나의할일.tsx` select×3, `form-helpers` `type=date` |
| **증상** | Android 등에서 네이티브 드롭다운이 **아래로 펼쳐질 때 탭바·카드 clip·화면 하단에 가림**. 날짜 피커가 입력 필드 뒤로 밀림 |
| **원인** | (1) 카드 `overflow:hidden` (2) 페이지 하단 고정 탭 (3) 키보드 미보정으로 포커스 필드가 가시영역 밖 |
| **수정** | 폼 하단 여백 충분히; 긴 폼은 포커스 시 `scrollIntoView`; 가능하면 네이티브 select 대신 **MSheet 피커** (결재선피커 패턴). date는 시트 달력 통일 |

### UX-D3. MSheet는 z=1500으로 탭 위 — 구조는 양호, 단 portal 미사용

| 항목 | 내용 |
|------|------|
| **파일** | `공통/MSheet.tsx:37` `zIndex: 1500` |
| **양호** | 바텀시트·필터시트·상세메뉴는 탭(999) 위에 뜸 |
| **리스크** | `createPortal` 없음. 조상에 `transform`/`filter`가 생기면 fixed 기준점이 깨질 수 있음 (현재 `.mso-mobile`에 transform 없음 → 당장 OK). `backdrop-filter`만 있는 macos-glass 조상은 대부분 문제 없음 |
| **권장** | 장기적으로 `document.body` portal + body scroll lock |

### UX-D4. 가짜 드롭다운 UI (클릭해도 안 열림)

| 위치 | 증상 |
|------|------|
| `재고/index.tsx:161–164` `m-company-sel` | chevron 있어 회사 선택 드롭다운처럼 보이나 **button/onClick 없음** |
| `인사관리` 일부 회사 선택 | 시트는 있으나 재고는 더미 |

→ “드롭다운이 안 열린다/가려진다”로 오인 가능. **데드 컨트롤 제거 또는 실구현**.

### UX-D5. 바텀탭 mask fade로 끝 탭 터치·시인성 저하

| 항목 | 내용 |
|------|------|
| **파일** | `MobileBottomTab.tsx:132–133` `maskImage: linear-gradient(... transparent ...)` |
| **증상** | 양끝 메뉴(알림·관리자)가 흐려지고 탭 영역이 줄어든 것처럼 느껴짐. 가로 스크롤 필요 인지 어려움 |
| **수정** | fade 완화 또는 스크롤 힌트 점·스냅; 활성 탭 `scrollIntoView` |

## 3. Major — 스크롤 관련 부가 이슈

### UX-S6. Pull-to-refresh가 상단 스크롤과 경쟁

| 항목 | 내용 |
|------|------|
| **파일** | `usePullToRefresh.ts:109–110` scrollTop===0 에서 `touchmove` **`preventDefault()`** |
| **증상** | 목록 맨 위에서 살짝 당기면 스크롤 대신 PTR만 잡히거나, 바운스 후 스크롤이 둔해짐 |
| **수정** | 수평 제스처 무시 조건 강화, threshold 이전엔 preventDefault 최소화, iOS `overscroll-behavior-y: contain`과 조율 |

### UX-S7. 채팅 메시지 영역 padding 오버라이드로 하단 잘림 가능

| 항목 | 내용 |
|------|------|
| **파일** | `채팅방.tsx:874` `style={{ padding: '12px 12px 6px' }}` on `m-scroll` |
| **증상** | 클래스의 `padding-bottom: 88px`가 인라인 shorthand `padding`으로 **전부 리셋**. 채팅방은 탭이 숨겨지므로 88 불필요할 수 있으나, **composer 높이만큼 bottom padding 부족 시 마지막 메시지 가림** (기존 E2E 이슈와 연관) |
| **수정** | composer 높이를 재는 `padding-bottom` 또는 spacer div |

### UX-S8. sticky 헤더가 **스크롤 컨테이너 밖**에 있는 패턴 vs 안

- `MobileHeader`에 `position:sticky` 지정 (`MobileHeader.tsx:24`) 하지만 대부분 **m-scroll 형제**로 배치 → sticky 무의미(동작은 flex 고정으로 OK).
- 일부 화면(게시판상세·채팅방)은 커스텀 헤더 sticky + m-scroll 형제 — 동일.
- sticky를 m-scroll **안**에 두면 overflow 조상에서 sticky 깨짐 — 현재 구조는 대체로 형제 배치라 안전.

### UX-S9. m-sticky-foot + 플로팅 탭 이중 하단 점유

| 항목 | 내용 |
|------|------|
| **파일** | `tokens.css` `--m-sticky-foot-pb: 80px`, `m-sticky-foot` padding에 합산 |
| **증상** | 댓글바·발주·재고 하단 버튼이 탭 위에 올라오도록 설계됐으나, **탭이 플로팅(16px inset)** 이라 계산 오차 시 겹침 또는 과도한 공백 |
| **수정** | 탭 실측 높이(64+16 bottom + safe) 토큰 1개로 통일. 채팅방처럼 탭 숨김 화면은 foot-pb 0 |

### UX-S10. 근무현황 KPI/칩은 스크롤 밖 — 리스트만 스크롤 (의도)

- 구조상 정상. 다만 작은 화면에서 KPI+칩이 세로를 많이 먹으면 리스트 뷰포트가 줄어듦 → UX 답답함 (버그 아님, 개선 여지).

### UX-S11. 관리자/급여/문서함 — PC 임베드 (`MFeatureScreen` + 데스크톱 컴포넌트)

| 증상 | 가로 스크롤 강제, 테이블 헤더 고정 깨짐, 내부 overflow와 m-scroll 이중화 |
| 수정 | 핵심 액션만 모바일 리스트 UI, 또는 iframe-like 단일 overflow 규칙 |

## 7. 검증 시나리오 (수동 / Playwright)

1. **공유캘린더** — 근무 카드 20+ 일 → 끝까지 스크롤  
2. **내정보 홈** — 로그아웃 버튼이 탭 **위**에 완전히 보이는지  
3. **급여 보안 모달** — 모달 중 탭이 모달 위에 안 뜨는지  
4. **채팅방** — 키보드 올린 채 입력창·전송 버튼 가시  
5. **게시판 상세** — 댓글 입력 포커스 시 키보드 위 배치  
6. **연차 신청** — 화면 하단 근처 select/date 조작  
7. **나의 할 일** — 목록 20건+ 스크롤 부드러움  
8. **결재 상세 원문 탭** — 승인 버튼 도달  

기기: iOS Safari, Android Chrome, 360×740 / 390×844.
