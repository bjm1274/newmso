## 1. 한 줄 결론

1. **중복이 가장 비싼 곳**: 채팅 전송, 게시판 create/list, 결재 상신, 추가기능 data-hooks — PC/모바일이 비즈니스 로직까지 따로 짜여 **버그가 양쪽에 따로 생김**.  
2. **잘못된 호출 핵심**: `attendance` vs `attendances` 이중 경로, raw `user.id` 쓰기, API에 `canAccess*` 미적용.  
3. **PC/모바일 분기는 셸·UI 프리미티브는 정당**하지만, **도메인 로직 분기는 과다**. 재고 re-export·관리자 임베드·연차 SSOT는 모범 사례.  
4. **API**: broken(라우트 없음)은 0, **dead API 14+**, 알림 mark-read 이중 엔드포인트.

## 3. 잘못된 호출 · 이중 경로

| # | 문제 | 심각도 |
|---|------|--------|
| 1 | **`attendance` / `attendances` 이중 테이블** — 체크인·관리자·정정·근무현황이 서로 다른 테이블 조회 | **C** |
| 2 | **raw `user.id`** — 알림설정, 게시판 쓰기, OP, 일부 결재 폼 (PC 출결정정 등) | **C** |
| 3 | **`canAccess*`가 API에 0건** — 권한은 클라 UI만, 서버 mutate는 로그인/조악 체크 | **C** |
| 4 | **`chat_messages` 스키마 잔존** — 앱은 `messages`만 사용 | **C** (혼선) |
| 5 | **알림 클라 직접 insert** vs 정책/서버 전용 경로 | **C/M** |
| 6 | **dead API 14+** 호출 0 (stock-consume, og-preview, chart-ocr, push-health 등) | **M** |
| 7 | **company vs company_id** 혼용 (재고·게시판·조직도) | **M** |
| 8 | 스키마 없는 컬럼 조회 잔존 가능 경로 (`early_leave_minutes` 등) | **M** |

## 4. PC vs 모바일 — 불필요하게 많은가?

### 정당 분기 (유지)
- `page.tsx` → 모바일 `MobileShell` / PC 사이드바
- Bottom tab, M* 컴포넌트, 시트·키보드·터치
- 재무·Gemini/ESL PC 전용 (의도적)

### 과다 분기 (줄여야 함)

| 등급 | 영역 | 판정 |
|------|------|------|
| **높음** | 채팅, 게시판 create, 결재 상신, 추가기능 data-hooks, 인사 일부 fetch | **불필요 비즈니스 이중 구현** |
| **중** | 내정보 홈 KPI, 알림 목록 UI, 결재 함 분류, 계약 목록 | 훅 공유 가능 |
| **낮음** | 재고 data re-export, 관리자 Workcenter 임베드, 연차 SSOT, 급여 임베드 | **모범 — 유지** |

**답:** 셸·UI 분기는 필요함. **비즈니스 로직 분기는 불필요하게 많음** (특히 채팅·게시판·결재·추가기능).

## 5. 통합 권장 아키텍처 (우선순위)
