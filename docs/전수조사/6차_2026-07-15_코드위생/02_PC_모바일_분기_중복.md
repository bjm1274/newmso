## 0. 한 줄 결론

**셸은 정당 분기**(`page.tsx` → `isMobile`이면 `MobileShell`, 아니면 PC 사이드바+`조직도본문`)지만, **핵심 비즈니스 도메인(채팅·게시판·결재 작성·추가기능·인사 일부)은 UI뿐 아니라 fetch/submit/권한까지 이중 트리**로 갈라져 있다.  
**재고 data-hooks·관리자 Workcenter 임베드·연차 SSOT(`lib/annual-leave-summary`)·일부 알림/증명서 API**는 이미 공유 쪽으로 수렴 중이며, **가장 비싼 중복은 메신저/게시판 create·결재 상신·추가기능 data-hooks**다.  
5차 Critical(모바일 세부 권한 미배선, 결재 type/meta, company 미격리)의 **상당수는 “PC 로직 미공유 + 모바일 단독 재구현”에서 재발**한다.

## 1. 셸·진입 아키텍처

```
app/main/page.tsx
  useIsMobile()  // max-width: 767px
  ├─ true  → MobileShell (9탭: notif/mypage/addon/chat/board/approval/hr/stock/admin)
  └─ false → PC shell
               ├─ 조직도측면창 (MAIN_MENUS 사이드바)
               └─ 조직도본문 MainContent
                    dynamic: 마이페이지|알림인박스|메신저|게시판|전자결재|
                             인사관리|재고관리통합|관리자전용|추가기능|
                             공유캘린더|재무회계|OrgChart
```

| 축 | PC | 모바일 | 판정 |
|----|----|--------|------|
| 진입 분기 | `page.tsx` PC 트리 | `MobileShell` | **정당** (뷰포트 전용 셸) |
| 메뉴 키 | 한글 `mainMenu` (`내정보`…) | `MTab` + `NavigationContext` 매핑 | **정당** (어댑터) |
| 공통 컨텍스트 | `AppData` / `Company` / `Navigation` | 동일 Provider | **공유 양호** |
| 알림 배너·NotificationSystem | page 상단 공용 | 모바일 분기 안에서도 동일 마운트 | **공유 양호** |
| 재무회계 | MainContent 전용 | **탭 없음** | 의도적 PC 전용 가능 — 문서화 필요 |
| 공유캘린더 | 메인 메뉴 독립 | 추가기능 하위 | **IA 차이 (정당에 가깝)** |
| Gemini / ESL | 추가기능 카드 | 허브에 `(PC)` 표기 + toast | **의도적 축소** |

**중복도 기준**

- **높음**: 비즈니스 규칙·DB write/read가 양쪽 독립 구현

- **낮음**: 한쪽 임베드/re-export 또는 순수 레이아웃 차이

## 3. 완전 복제·고중복 모듈 상세

### 3.1 채팅 (중복도: 높음) — 최우선 통합 후보

| 레이어 | PC | 모바일 | 공유 여부 |
|--------|----|--------|-----------|
| 컨테이너 | `메신저.tsx` (초대형) | `채팅/index.tsx` | 분리 |
| 방 목록 fetch | 메신저 훅 + `chatQueryService` | `useChatRoomsForMobile` | query 일부 공유, 래퍼 이중 |
| 메시지 fetch | 메신저 구독/파생 훅 | `useChatMessagesForRoom` | 유틸 공유, 훅 이중 |
| 텍스트 전송 | `메신저전송훅` | `sendMobileTextMessage` | insert 유틸 공유, 오케스트레이션 이중 |
| 파일 업로드 | `메신저업로드훅` | `채팅/업로드.ts` | `/api/chat/upload` 공유, 클라 이중 |
| 푸시 트리거 | `triggerChatPush` (메신저 내부) | `푸시트리거.ts` `triggerMobileChatPush` | **사실상 복제** (keepalive 차이만) |
| 렌더 | `메신저메시지렌더` | 버블에서 import | **공유** |
| 이모지 | `메신저액션서브/*` | 래퍼 import | **공유** |
| 투표/스레드 | PC 전용 패널 | 시트 재구현 | 부분 공유 |

**버그 교차 (5차):** messages INSERT 멤버십 미강제, chat_* 서버 미배선은 **양 트리 공통**. 이중 전송 가드·읽음 커서 멤버십은 수정 시 **두 곳 패치 필요** → 회귀 비용 2배.

### 3.2 게시판 (중복도: 높음)

| 레이어 | PC | 모바일 |
|--------|----|--------|
| 목록/상세 UI | `게시판.tsx` 단일 거대 파일 | `게시판목록`/`상세`/`글작성` 분리 |
| 정규화 | `게시판공통` | import 공유 |
| 업로드 | `게시판업로드` | `첨부업로드` → 동일 API |
| **create** | `게시판.tsx` insert 인라인 | `createBoardPost` in `data-hooks.ts` |
| 공지 방송 | `/api/board/notice-broadcast` | data-hooks + 글작성 **패리티 반영됨** |

**잔존:** 목록 필터·company·PUBLIC 정책이 양쪽에 흩어지면 한쪽만 고치는 회귀 지속.

### 3.3 전자결재 (중복도: 높음 — 상신 경로)

```
승인/반려/회수  →  /api/approvals/*   ← PC·모바일 공용 (양호)
상신(insert)    →  PC: useApprovalSubmit
                →  모바일: useApprovalFormBase + submitApprovalDraft + generateMobileDocNumber
양식 UI         →  PC: 양식별 대형 폼
                →  모바일: 전용 4폼 + 일반기안폼(스키마 축약)
```

| 이슈 | 원인 | 5차 교차 |
|------|------|----------|
| type / form_slug 불일치 | 모바일 `type: formName`(표시명), PC는 formType 한글 상수 | 물품·연차 final 분기 실패 가능 |
| meta.items 스키마 | 모바일 `양식필드.tsx`에서 수동 정합 주석 | 서버 inventory_workflow 의존 |
| 세부 함 권한 | 모바일 탭 단위만 `canAccessMainMenu` | `approval_*` 미배선 |
| doc_number | `generateMobileDocNumber` ≈ `buildApprovalDocNumber` 래퍼 | 거의 동일 — lib로 완전 이전 가능 |
| 연차 leave_requests 선행 insert | 모바일 전용 경로 고아 가능 | 5차 잔존 |

### 3.4 추가기능 (중복도: 높음 — data-hooks)

`모바일/추가기능/data-hooks.ts` 단독으로:

- 조직도, 부서재고, 근무현황, 인계, 평가, 퇴원, MRI, 업무공유/가이드, OP보드, 입금, 마감

| 근무현황 | `기능부품/근무현황.tsx` | `추가기능/근무현황` + `useWorkNow` | 07-12 unknown 수정 모바일 쪽 |

## 7. 통합 권장 아키텍처

### 7.1 목표 구조

```text
lib/ 또는 features/
  chat/       rooms, messages, send, read, pushTrigger
  board/      list, detail, create, comment, broadcast
  approval/   list/classify, submit, docNumber (transition은 이미 API)
  hr/         staffList, attendanceMonth, welfare, abnormal actions
  extra/      workNow, handover, opBoard, discharge (기존 PC에서 추출)
  mypage/     todayCounts, monthlyAttendance (leave는 annual-leave-summary 유지)

app/main/기능부품/**     → PC 레이아웃 + domain hooks 소비
app/main/모바일/**       → M* UI + 동일 domain hooks 소비
app/main/page.tsx        → 셸 분기만 유지
```

> 현재 레포에 `features/` 디렉터리는 없음. 신설 시 `lib/` 비대화 방지용으로 도메인 단위 권장.  
> 이미 성공한 패턴: `lib/annual-leave-summary.ts`, `lib/use-resolved-staff-id.ts`, `재고 data-hooks re-export`, 관리자 Workcenter 임베드.

### 7.2 우선순위

| 순위 | 작업 | 효과 | 공수 |
|------|------|------|------|
| **P0-1** | 결재 **submitApproval 단일 모듈** (type/slug/meta 정규화 포함) — PC `useApprovalSubmit`·모바일 form base가 호출만 | type 불일치·원장 고아 제거 | M |
| **P0-2** | 채팅 **send + pushTrigger + room list query** 단일화 | 푸시/전송 회귀 비용 반감 | M~L |
| **P0-3** | 게시판 **createBoardPost**를 PC가 호출하도록 역통합 + company 필터 SSOT | 공지/권한/회사 패리티 | M |
| **P1-1** | 추가기능 허브 **`canAccessExtraFeature` 공유** + data-hooks를 PC에서 extract | 5차 권한 C 해소 | M |
| **P1-2** | 모바일 결재 **`canAccessApprovalSection`** 함/작성 게이트 | 권한 패리티 | S |
| **P1-3** | 인사 모바일 query hooks → lib (attendance KST·dual table 정리와 함께) | 숫자/목록 불일치 방지 | L |

| **유지** | 재고 re-export, 관리자/급여/오프보딩 임베드, 연차 SSOT, 셸 분기, M* UI | 모범 패턴 확산 | — |

### 7.3 안티패턴 / 권장 패턴

| 금지 | 권장 |
|------|------|

1. **정당 분기**: 셸, 네비, M* UI, 시트/키보드, PC 전용 고밀도 관리 화면.  
2. **불필요 이중 구현**: 채팅 오케스트레이션, 게시판 create/list, 결재 상신, 추가기능 data-hooks, 인사 다수 query.  
3. **이미 잘된 통합**: 재고 data re-export, 관리자/급여 임베드, 연차 SSOT, 결재 transition API, 알림 API.  
4. **다음 스프린트**: **결재 submit 단일화 → 채팅 send/push 단일화 → 게시판 create 역통합 → 추가기능 권한+hooks**.  
5. 원칙: **「모바일 = 다른 UI 트리」가 아니라 「같은 domain, 다른 presentation」.** 비즈니스 규칙은 `lib/`·`features/`에 한 번만.
