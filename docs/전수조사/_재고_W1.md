### ★특별임무 1 — 워크센터 4종 + use-*-data hook 중복(D)

**구조적 중복(D, 중):** 4개 hook(`use-status/io/item/analyze-data.ts`)이 동일 패턴 반복 — `EMPTY` 상수 + `useState(EMPTY)` + `useEffect`(cancelled 플래그 + Promise.all + try/catch + `setState({...EMPTY,loading:false,error})`). 4종 합쳐 ~720줄이 거의 동일 보일러플레이트. 공통 `useWorkcenterFetch<T>(loader)` 추출 가능. 4 워크센터 컴포넌트(Status/IO/Item/Analyze)도 동일 골격(KpiRow + StockTabs/FilterChips + grid + WorkcenterNotes).

**컬럼 불일치 상세(S 높음):**

### ★특별임무 4 — 재고관리통합이 무엇을 라우팅하는가

`재고관리통합.tsx`(IntegratedInventoryManagement)는 **두 라우팅 체계 병존**:
1. **영문 워크센터 id**(`status`/`io`/`item`/`analyze`): `initialView`가 이 4개면 모든 hook 호출 후 early-return으로 `getStockWorkcenter(initialView)` 위임(310-317) → 읽기전용 대시보드 워크센터 렌더. **단, `isStockWorkcenterEnglishId`는 `window.navigator.webdriver`면 false 반환(54-59)** → E2E/봇 환경에선 워크센터 비활성, 한글 뷰로 폴백(U/테스트 회피용 가드, 의도적이나 특이).
2. **한글 뷰**(현황/등록/발주/자산/이력/UDI/스캔/거래처/재고실사/이관/카테고리/소모품통계/월마감/납품확인서/수요예측/내부서재고/비품대여설정/AS반품): `activeView` 조건부로 lazy 서브뷰 렌더(327-424). 실제 CRUD·모달·워크플로우는 전부 이 경로.
- `resolveInventoryView`(62-82)가 레거시/영문 id → 한글 뷰 매핑. 영문 4종은 한글로도 매핑되나(status→현황 등) 실제 위임은 #1 가드가 우선.

**Q(중) — 기능 중복:** 워크센터 4종은 `inventory`/`inventory_logs`/`purchase_orders`를 자체 fetch해 **읽기전용 대시보드**를 그림(액션 버튼 전부 더미). 동일 데이터를 한글 뷰(현황뷰/발주관리/품목 등)가 **실동작**으로 이미 제공. 워크센터는 별도 fetch 경로 + 별도(깨진) 매핑이라 **두 진실원**이 됨. 통합 권장.
