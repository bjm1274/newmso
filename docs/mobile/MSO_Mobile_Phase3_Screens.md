## 1. OP체크 실시간 보드 (5장 → 1장)

**우선도**: 🔴 매우 높음 — 수술실/시술실 현장에서 모바일이 주 사용처.
**현행**: `#08~12` 5장이 상태전이만 다른 동일 화면.
**목표**: 단일 화면 + 카드 상태 토글. 페이지 이동 없이 인라인 액션.

### 1-1. 정보 구조

```
┌────────────────────────────────────────┐
│ PageHeader: 오늘 · 7건 · 진행중 2     │  ← count + status
├────────────────────────────────────────┤
│ [필터칩] 전체 · 진행중 · 완료 · 대기  │  ← 가로 스크롤 칩
├────────────────────────────────────────┤
│ ◆ 카드 (방번호 · 환자 · 시술명)        │
│   상태칩 · 의사 · 시작시각              │
│   ─────────────                          │
│   [상태전환 버튼 1] [버튼 2]            │  ← 인라인 액션 (시트 X)
├────────────────────────────────────────┤
│ ◆ 카드 ...                              │
└────────────────────────────────────────┘
```

### 1-2. 카드 상태 전이 (5장 → 카드 토글)

| 상태 | 칩 색 | 인라인 액션 |
|---|---|---|
| 대기 | `--muted-2` | [시작] |
| 진행중 | `--accent` | [완료] [중단] |
| 완료 | `--success` | [상세] |
| 보류 | `--warning` | [재개] [취소] |
| 취소 | `--danger` | (액션 없음) |

**구현 키 포인트**
- 카드 자체가 상태머신. 상태 변경은 **낙관적 업데이트** (UI 먼저, API 실패 시 토스트로 롤백).
- 액션 버튼은 카드 우측 하단 fixed, 44px 강제.
- 상태 전환 시 카드 자체 색·테두리만 바뀜 — 페이지 리로드 0.

### 1-3. 모바일 전용 패턴

- **실시간 갱신**: WebSocket 또는 30초 폴링. 상단에 "마지막 업데이트: 12초 전" 마이크로 카피.
- **풀-투-리프레시**: `PullToRefresh.tsx` 신규 컴포넌트.
- **현장 노이즈 대응**: 모든 상태 변경 시 햅틱 (`navigator.vibrate(15)`) — 지원 기기만.
- **잠금화면 위젯 후보**: 진행중 시술 수 (Phase 4).

### 1-4. 산출 파일

- `app/main/OP체크/모바일보드.tsx` (신규)
- `app/components/PullToRefresh.tsx` (신규)
- `app/hooks/useOpCheckBoardStream.ts` (신규, WebSocket/폴링 추상화)

### 1-5. 검수 기준

- [ ] 5장의 PC 화면이 단일 모바일 화면 + 카드 상태 토글로 통합.
- [ ] 상태 변경 시 페이지 이동 0.
- [ ] iPhone SE(320)에서 카드 한 장이 단일 컬럼으로 fit.
- [ ] 30초 동안 다른 사용자의 상태 변경이 자동 반영.

## 2. 퇴원심사 워크플로우 (6장 → 2장)

**우선도**: 🟡 중 — 심사 작업 자체는 데스크톱, 모바일은 **목록 확인 + 코멘트 + 승인 액션**.
**현행**: `#17~22` 6장이 한 흐름 (대기 → 1차 → 2차 → 보완요청 → 승인 → 반려).

### 2-1. 모바일 정보 구조 (2화면)

**화면 A — 심사 목록**
- 필터 칩: 내 차례 · 보완요청 · 전체
- 카드: 환자명·진료과·요청일·현재 단계 칩
- 우측 끝: 미리보기 아이콘 + 채팅 아이콘(코멘트 수)

**화면 B — 심사 상세 (시트 + 풀스크린)**
```
┌──────────────────────────────────────┐
│ ← 뒤로  · 환자 · 진료과              │
├──────────────────────────────────────┤
│ [요약 · 진료기록 · 코멘트] 탭         │  ← 3개 (패턴 A)
├──────────────────────────────────────┤
│ (탭 내용 — 스크롤)                   │
│                                      │
├──────────────────────────────────────┤
│ Sticky 푸터:                         │
│ [보완요청]  [반려]  [승인]           │  ← 위험순 좌→우
└──────────────────────────────────────┘
```

### 2-2. 모바일 우선 결정

- **워크플로우 단계 자체는 데스크톱**. 모바일은 **이미 만들어진 심사를 다음 단계로 넘기는 액션**만.
- 보완요청은 BottomSheet 모달 — 사유 텍스트필드 + 빠른 사유 칩(누락서류·코딩오류·진단불일치 등).
- 진료기록은 PDF/이미지 — 풀스크린 뷰어 (핀치 줌, 페이지 스와이프).

### 2-3. 산출 파일

- `app/main/퇴원심사/모바일목록.tsx`
- `app/main/퇴원심사/모바일상세.tsx`
- `app/main/퇴원심사/보완요청시트.tsx`
- `app/components/PdfViewer.tsx` (있다면 재활용)

### 2-4. 검수 기준

- [ ] 모바일에서 신규 심사 생성 진입 시 "데스크톱에서 작성해주세요" 안내.
- [ ] 승인/반려/보완 액션은 모바일 단독 완결.
- [ ] 진료기록 PDF 핀치 줌, 페이지 스와이프 동작.

## 3. 근태 통합 (10장 → 3장)

**우선도**: 🔴 매우 높음 — 출퇴근 체크인은 모바일이 주 사용처.
**현행**: `#30~40` 10장 (대시보드·체크인·근무표·연차·이상감지 등).
**목표**: 모바일 3화면 — **체크인** · **내 근무표** · **연차/이상**.

### 3-1. 화면 A — 출퇴근 체크인 (모바일 메인)

```
┌────────────────────────────────────────┐
│ 오늘 2026-05-14 (수) · 09:14:23         │  ← 큰 시계
├────────────────────────────────────────┤
│                                        │
│    [ 출근 체크 ]                       │  ← 풀폭 큰 버튼 (200px)
│                                        │
│  · 위치 확인 중...                     │
│  · 박철홍정형외과 · 1F 데스크          │
│                                        │
├────────────────────────────────────────┤
│ 오늘 기록                               │
│  09:01 출근  ·  12:00 외출  ·  ...     │
└────────────────────────────────────────┘
```

**핵심 결정**
- **체크인 버튼은 화면의 60% 차지**. 손가락 한 번에 누르게.
- 위치(GPS·Wi-Fi)·시각이 일치하지 않으면 버튼 비활성 + 사유 표시.
- 외출/복귀/퇴근은 같은 버튼이 컨텍스트에 따라 라벨만 변경.

### 3-2. 화면 B — 내 근무표

- 달력 뷰 (월) + 스와이프로 월 이동.
- 오늘 셀 하이라이트 + 휴무 표시.
- 셀 탭 → 시트로 상세 (시작/종료/근무지/메모).
- **편집은 모바일 X** — "근무표 편성은 데스크톱에서" 안내 (관리자만).

### 3-3. 화면 C — 연차/이상감지 (탭 2개)

- **연차 탭**: 잔여 일수 큰 숫자 + 신청 내역 카드 리스트 + Sticky [신청] 버튼.
- **이상감지 탭**: 본인 한정 카드 리스트 (지각·조퇴·미체크 등) + 사유 입력 시트.

### 3-4. 산출 파일

- `app/main/근태/모바일체크인.tsx`
- `app/main/근태/모바일근무표.tsx`
- `app/main/근태/모바일연차.tsx`
- `app/hooks/useGeolocationCheckin.ts`

### 3-5. 검수 기준

- [ ] 체크인 버튼 최소 200×200 (실제 측정).
- [ ] GPS 거부 시 사유 + 사유 입력 fallback.
- [ ] 키보드 올라와도 체크인 버튼이 가려지지 않음.
- [ ] 오프라인 시 큐에 저장, 온라인 복귀 시 자동 전송 (선택 — Phase 4).

### 7-2. 모바일 우선 결정

- **3분할 PC 레이아웃을 모바일에 그대로 두지 않는다**. 마스터-디테일 라우팅.
- 자료·인수인계는 첨부 카드(파일 타입 아이콘 + 미리보기 + 다운로드).
- 댓글 입력은 페이지 최하단 sticky, 키보드 올라오면 visualViewport 따라 이동.
- 새 글 작성은 풀스크린 모달 (BottomSheet X — 폼이 길어짐).
