§ 00 DIAGNOSIS

PC 그대로 모바일에 띄울 때, 4가지가 동시에 깨집니다.

현재 코드베이스는 `--touch-target: 44px`, `--mobile-padding-x: 16px` 같은 모바일 토큰을 이미 정의하고 있지만 실제 컴포넌트에는 거의 적용되지 않았습니다. 결과적으로 다음 4가지가 모든 화면에서 반복됩니다.

① 글자가 작다 (body 13px)

데스크톱에서 정보 밀도를 위해 `body { font-size: 13px }`로 잡아 두었는데, 모바일 폭에서는 일반 본문 18–22자 한 줄에 들어가 가독성이 급격히 떨어집니다. 입력 필드만 iOS 줌 방지를 위해 16px로 올라가 있어, 카드 본문(13)과 인풋(16)이 한 화면에 섞이면서 위계가 더 어색해집니다.

→ 모바일은 body 15px, 보조 12px, 숫자 17–20px로 한 단 위로 올린다.

② 박스/탭이 작다 (high‑height < 36px)

`.tab-item { padding: 5px 11px }`, `.menu-item { padding: 6px 10px }`, `.erp-action-tile { min-height: 64px }` 등 PC 기준 컴포넌트가 그대로 적용되어 탭/메뉴/체크박스가 모두 손가락보다 작습니다. WCAG 2.5.5(44 × 44)를 위반합니다.

→ 모바일에서 인터랙티브 요소 최소 44 × 44px, 컴팩트는 40px 까지만.

③ 가로 레이아웃이 그대로 (사이드+서브+본문)

PC는 사이드바(72px) + 서브메뉴(192px) + 본문 3컬럼 구조인데, 이게 모바일에서도 같은 가로 흐름으로 들어가서 본문 폭이 200–240px밖에 안 남습니다. 특히 인사관리 → 근태/급여 같은 하위 8개 탭은 가로 스크롤이 필수인데도 시각적 힌트가 없습니다.

→ 사이드바 → 바텀탭(5개), 서브메뉴 → 드로어/풀스크린 탭 시트, 본문 단일 컬럼.

④ 표·폼이 그대로 (5+ 컬럼 그리드)

계약서 자동생성 화면은 6칸 그리드, 직원권한 설정은 토글 7개가 한 줄로 들어 있습니다. 모바일에서는 옆으로 잘리거나 한 칸이 30–40px로 짜부라집니다. 게시판/근태/급여대장도 동일. 이미 만들어 둔 ``이 있지만 실제 적용은 일부뿐입니다.

→ md:< 768 에서 표 → 카드, 5+컬럼 폼 → 1컬럼 + 섹션 분리.
핵심. 이미 토큰(`--touch-target`, `--mobile-padding-x`, `--mobile-bottomtab-height`)과 컴포넌트(`BottomTab`, `BottomSheet`, `ResponsiveTable`)는 만들어져 있습니다. 본 문서는 새 디자인을 만드는 게 아니라, 흩어진 토큰을 모든 화면에 강제 적용하는 표준을 정의합니다.
§ 01 DESIGN TOKENS

모바일 토큰 — 폰트 / 박스 / 터치 / 라운드를 한 단 위로

기존 `:root`에 정의된 데스크톱 토큰은 그대로 두고, `@media (max-width: 767px)`에서 덮어쓰는 모바일 변형을 추가합니다. 컴포넌트 코드에는 변경 없음 — 토큰만 바꿉니다.

D. 위험 액션 — risk sheet
