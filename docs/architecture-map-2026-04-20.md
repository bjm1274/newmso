# MSO ERP 현재 구축 구조도
> 검증일: 2026-04-20
> 기준: 실제 코드 기준 재정리

## 1. 검증 결론
기존 `erp 전체흐름도.md` 내용은 현재 코드와 완전히 일치하지 않습니다.

주요 불일치 지점:
- 주요 화면 파일이 `app/main/` 직하가 아니라 `app/main/기능부품/` 기준으로 재구성되어 있습니다.
- 좌측 메인 사이드바의 상시 메뉴는 8개이며, `조직도`와 `알림`은 상시 고정 메뉴가 아닙니다.
- `인사관리`는 메인 셸의 공통 서브메뉴를 사용하지 않고, 자체 워크스페이스형 내부 메뉴를 가집니다.
- `재고관리`는 현재 `이력`, `거래처`, `내부서재고` 등 실제 뷰 체계가 기존 문서와 다릅니다.
- `관리자`는 `admin-menu-config.ts` 기반의 외부 탭 + 내부 탭 구조로 동작합니다.

검증에 사용한 핵심 파일:
- `app/main/page.tsx`
- `app/main/admin-menu-config.ts`
- `app/main/기능부품/조직도서브/조직도측면창.tsx`
- `app/main/기능부품/조직도서브/조직도본문.tsx`
- `app/main/기능부품/마이페이지/index.tsx`
- `app/main/기능부품/전자결재.tsx`
- `app/main/기능부품/인사관리.tsx`
- `app/main/기능부품/재고관리통합.tsx`
- `app/main/기능부품/관리자전용.tsx`
- `app/main/기능부품/추가기능공통.tsx`

## 2. 실제 메인 셸 구조

```text
app/main/
├── page.tsx
├── admin-menu-config.ts
├── navigation-state.ts
├── contexts/
├── hooks/
└── 기능부품/
    ├── 조직도서브/
    │   ├── 조직도측면창.tsx
    │   ├── 조직도본문.tsx
    │   └── OrgChart.tsx
    ├── 알림센터.tsx
    ├── 알림시스템.tsx
    ├── 채팅알림배너.tsx
    ├── 마이페이지/index.tsx
    ├── 메신저.tsx
    ├── 게시판.tsx
    ├── 전자결재.tsx
    ├── 인사관리.tsx
    ├── 재고관리통합.tsx
    ├── 관리자전용.tsx
    └── 추가기능.tsx
```

실제 동작 흐름:
1. `page.tsx`가 세션, 회사 선택, 메인 메뉴 상태, 진입 쿼리, 권한을 관리합니다.
2. `조직도측면창.tsx`가 좌측 메인 메뉴를 렌더링합니다.
3. `조직도본문.tsx`가 `next/dynamic`으로 각 메인 화면을 lazy-load 합니다.
4. `알림센터.tsx`의 벨 버튼이 `알림` 화면을 엽니다.
5. `조직도`는 렌더 가능한 상태이지만, 상시 사이드바 메뉴가 아니라 별도 진입 상태로 취급됩니다.

## 3. 실제 메인 메뉴 상태 맵

| 상태값 | 사이드바 상시 노출 | 렌더 컴포넌트 | 실제 경로 | 비고 |
|---|---|---|---|---|
| `내정보` | 예 | `MyPage` | `app/main/기능부품/마이페이지/index.tsx` | 기본 진입 |
| `추가기능` | 예 | `ExtraFeatures` | `app/main/기능부품/추가기능.tsx` | 카드형 런처 |
| `채팅` | 예 | `ChatView` | `app/main/기능부품/메신저.tsx` | 실시간 채팅 |
| `게시판` | 예 | `BoardView` | `app/main/기능부품/게시판.tsx` | 게시판 내부 탭 존재 |
| `전자결재` | 예 | `ApprovalView` | `app/main/기능부품/전자결재.tsx` | 결재함/기안함/작성하기 |
| `인사관리` | 예 | `HRView` | `app/main/기능부품/인사관리.tsx` | 자체 사이드바 사용 |
| `재고관리` | 예 | `InventoryView` | `app/main/기능부품/재고관리통합.tsx` | 공통 서브메뉴 사용 |
| `관리자` | 예 | `AdminView` | `app/main/기능부품/관리자전용.tsx` | `admin-menu-config.ts` 기반 |
| `조직도` | 아니오 | `OrgChart` | `app/main/기능부품/조직도서브/OrgChart.tsx` | 즐겨찾기/추가기능/검색 등으로 진입 가능 |
| `알림` | 아니오 | `NotificationInbox` | `app/main/기능부품/알림인박스` | 벨 드롭다운에서 진입 |

중요:
- 실제 고정 메인 메뉴는 `내정보`, `추가기능`, `채팅`, `게시판`, `전자결재`, `인사관리`, `재고관리`, `관리자`입니다.
- 기존 문서처럼 `조직도`, `알림`을 동일 레벨의 고정 메인 메뉴로 적는 것은 현재 기준으로는 부정확합니다.

## 4. 모듈별 현재 구조

### 4.1 내정보
파일: `app/main/기능부품/마이페이지/index.tsx`

탭 구조:
- `profile`: 프로필 요약 + 역할별 대시보드 + 프로필 카드
- `commute`: 출퇴근기록
- `todo`: 나의할일
- `records`: 급여·증명서 허브
- `documents`: 서류제출
- `notifications`: 알림인박스

특징:
- 즐겨찾기로 다른 메인 메뉴로 점프할 수 있습니다.
- `records` 내부는 `salary` / `certificates` 2단 구조입니다.
- `menu_org` 즐겨찾기로 `조직도` 상태를 직접 열 수 있습니다.

### 4.2 전자결재
파일: `app/main/기능부품/전자결재.tsx`

상위 뷰:
- `기안함`
- `결재함`
- `참조 문서함`
- `작성하기`

기본 양식:
- `연차/휴가`
- `연차계획서`
- `연장근무`
- `물품신청`
- `수리요청서`
- `보고서작성`
- `업무기안`
- `업무협조`
- `공문발송`
- `양식신청`
- `출결정정`

추가 특징:
- 커스텀 양식이 별도로 붙을 수 있습니다.
- 결재선 템플릿, 참조자, 자동저장, 문서 출력까지 이 파일에서 통합 처리합니다.

### 4.3 인사관리
파일: `app/main/기능부품/인사관리.tsx`

주의:
- 메인 셸 공통 서브메뉴를 사용하지 않습니다.
- 인사관리 화면 내부에서 별도 워크스페이스와 메뉴를 렌더링합니다.

워크스페이스:
- `인력관리`
- `근태 · 급여`
- `복지 · 문서`

현재 상위 메뉴:
- `구성원`
- `인사변동`
- `입퇴사·교육센터`
- `근태`
- `연차/휴가`
- `급여`
- `경조사`
- `자격·안전센터`
- `계약`
- `문서센터`
- `캘린더`
- `채용관리`

주요 내부 탭:
- `인사변동` → `인사발령`, `포상/징계`
- `입퇴사·교육센터` → `교육`, `오프보딩`
- `근태` → `근태관리`, `근태이상분석`, `근태차감시뮬레이터`, `근태이상탐지`, `근무형태이력`
- `자격·안전센터` → `건강검진`, `면허/자격증`, `의료기기점검`, `사고보고서`
- `문서센터` → `문서보관함`, `증명서`, `서류제출`
- `계약` → `계약 현황`, `계약서 자동생성`

현재 구조상 포인트:

- `내부서재고`는 내부 연결용 상세 뷰로 존재합니다.
- 레거시 진입값 `명세서`, `유통기한`은 현재 뷰로 매핑만 유지합니다.

## 5. 실제 라우팅 해석 시 주의할 점

- `조직도본문.tsx`는 렌더 가능한 상태와 사이드바 상시 메뉴를 동일 개념으로 다루지 않습니다.
- `인사관리`는 메인 프레임 외부 공통 서브메뉴가 아니라, 화면 내부 워크스페이스 구조가 실제 기준입니다.
- `알림`은 `기능부품/알림센터.tsx` 벨 드롭다운에서 여는 인박스 진입 상태입니다.
- `조직도`는 별도 상태로 렌더되지만 사이드바 고정 메뉴가 아니며, 즐겨찾기/추가기능/검색 등 보조 진입점이 있습니다.

## 6. 최종 판단
현재 구축도 기준으로 보면, 기존 `erp 전체흐름도.md`는 참고용으로는 볼 수 있지만 최신 구조 문서라고 보기는 어렵습니다.

현재 기준의 올바른 상위 구조는 다음처럼 이해하는 것이 맞습니다:
- 메인 셸: `page.tsx`
- 메인 렌더 라우터: `기능부품/조직도서브/조직도본문.tsx`
- 고정 메인 메뉴: 8개
- 특수 진입 상태: `조직도`, `알림`
- 독립 내부 구조 모듈: `인사관리`, `재고관리`, `관리자`, `추가기능`

이 문서를 현재 구축 기준의 정본으로 사용하면 됩니다.
