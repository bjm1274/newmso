# 메뉴 전수조사 보고서 — 재고관리

> 조사 대상: `app/main/기능부품/재고관리통합.tsx` + `재고관리워크센터/` + `재고관리서브/` + `app/main/inventory-*.ts` + `lib/inventory-*.ts` (약 25+ 파일)

## 1. 메뉴 개요

재고관리는 의료소모품/자산 재고를 관리하는 메뉴다. 사이드바 4워크센터(현황/입출고·발주/물품·자산/분석·마감) + 내부 7대 워크센터(status/io/order/audit/udi/item/master/analyze) 구조.

## 3. 기능별 상세 분석

### 3.1 라우팅 (재고관리통합)
- 사이드바 id(`status/io/item/analyze`)와 내부 7대 id, 레거시 한글 id를 `resolveInventoryRoute`로 통합 해석.
- **기존 버그 수정 흔적**: 사이드바가 `io`·`item`을 쓰는데 통합 화면이 7대 영문 id만 허용해 메뉴 클릭이 무반응이던 문제를 `SIDEBAR_WORKCENTER_IDS`로 해결.
- 워크센터별 dynamic import(첫 진입 시 status만 로드).

### 3.2 재고 현황 (StatusWorkcenter)
- scope 필터(전체/내물품/부족/재고0/유효기간), 정렬(위치/카테고리/재고적은/만료임박).
- 공급신청 패널(기본 접힘), 승인 물품신청 접이식 요약.
- `useSupplyWorkflow` + `useStatusData`로 공급/현황 데이터 연동.
- `open_inventory_approval` 쿼리 파라미터로 딥링크 하이라이트.

### 3.3 공급 워크플로 (재고↔결재 연계)
- `useSupplyWorkflow`: 공급 신청 → 결재 승인 → 불출(issued)/발주(ordered) 상태 전이.
- `INVENTORY_SUPPORT_COMPANY`/`INVENTORY_SUPPORT_DEPARTMENT`(MSO 본사) 사용자만 재고 운영 가능.

## 4. 발견된 문제점 / 잠재 리스크

### 🟡 경미 (품질/리스크)
1. **레거시-신규 이중 구조** — `재고관리서브/`(레거시 7개 파일)와 `재고관리워크센터/`(신규)가 병존. `재고관리통합.tsx`가 양쪽을 모두 라우팅해 복잡도 증가.
2. **라우팅 분산** — 사이드바 id·내부 id·레거시 한글 id 3종을 세 곳(`재고관리통합`, `stock-types`, `재고관리서브/types`)에서 해석. 정합성 리스크.
3. **`filterByScope`의 'my' 필터 하드코딩** — `r.loc !== '본사' && r.loc !== 'MSO 본사 창고'` 문자열 하드코딩. 위치명 변경 시 오동작.
4. **`StatusWorkcenter` 내 인라인 타입(`WI`, `AR`)** — `Record<string, unknown>` 광범위 사용, 타입 안전성 낮음.
