# 메뉴 전수조사 보고서 — 알림

> 조사 대상: `app/main/기능부품/알림시스템.tsx` + `알림시스템/` + `알림센터.tsx` + `알림인박스.tsx` + `public/push-notification-shared.js` + `public/sw.js`
> 참고: 본 메뉴는 최근(2026-07-24) **PC/모바일 알림 팝업 미표시 버그**를 수정함.

## 1. 메뉴 개요

알림은 KakaoTalk 스타일 Toast + OS 시스템 팝업(Web Push) 이중 채널로 새 알림을 전달한다. DB(notifications 테이블) INSERT → realtime 수신 → Toast/시스템 팝업 표시가 기본 흐름이다.

## 3. 기능별 상세 분석

### 3.1 알림 수신 파이프라인
1. 서버가 notifications 테이블에 INSERT.
2. `subscribeRealtime`(polling-bus: WS 우선, 폴링 폴백)이 변경 감지.
3. `fetchUnreadNotificationsSince` → `emitIncomingNotification(row)`.
4. 설정/키워드/방알림 필터 통과 후 Toast 표시 + (조건부) 시스템 팝업.
5. 병행 경로: SW `push` 이벤트 → `erpDisplayIncomingNotification` → 시스템 알림 + `erp-push-preview` 브로드캐스트.

### 3.2 시스템 팝업 판정 (`sendNotification` / `emitIncomingNotification`)
- Electron: 네이티브 알림(브리지) → 폴백 HTML5 Notification.
- 브라우저: SW `showNotification` 사용, tag/requireInteraction 처리.
- 크로스탭 중복 방지: `claimCrossTabDisplayNotificationAsync` + BroadcastChannel 경합.

### 3.3 알림 설정
- 소리/진동, 방해금지(DND 시간), 주말 무음, 키워드 알림, 타입별 on/off.
- `settings.ts`가 localStorage에 저장, `filter-helpers.ts`가 표시 전 필터링.

### 3.4 푸시 구독 초기화
- `initNotificationService`: SW 등록 → 권한 요청 → VAPID 구독 → 서버 저장.
- Electron은 웹푸시 대신 네이티브 알림 모드.
- 실패 시 8초 재시도 + focus/visibilitychange resync 자가복구.

## 4. 발견된 문제점 / 잠재 리스크

### ✅ 최근 수정 완료 (2026-07-24)
1. **PC foreground에서 OS 팝업 미표시** — `erpShouldShowForegroundPopup`이 모바일에서만 true를 반환해 PC에서 시스템 팝업을 스킵하던 문제. 항상 true로 수정.
2. **`sendNotification` tag 고정('erp-noti')** — 연속 알림이 이전 알림을 덮어쓰던 문제. `options?.tag || 'erp-noti'`로 동적 태그 적용 + `requireInteraction: true`.

### 🟡 경미 (품질/리스크)
3. **`알림시스템.tsx` 2153줄 과대** — 실시간 구독/푸시 초기화/Toast/할일리마인더/급여이상치/연차촉진 알림 생성이 한 파일에 집중.
4. **알림 생성이 클라이언트에 분산** — 할일 리마인더·급여 이상치 알림을 클라이언트 useEffect에서 insert. 서버 cron과 중복 생성 가능성(제거된 채널 주석 참고).
5. **DND 판정이 로컬 시각 기준** — `isInDND`가 `new Date().getHours()`(로컬) 사용. KST가 아닌 기기에서 DND 시간 오판 가능(출퇴근 late-status는 KST 정본 사용 중, 여기는 아님).
