# 메뉴 전수조사 보고서 — 전자결재

> 조사 대상: `app/main/기능부품/전자결재.tsx` + `전자결재서브/` + `전자결재-types.ts` + `전자결재-utils.ts` + `lib/approval-*.ts` (약 42개 파일)

## 1. 메뉴 개요

전자결재는 기안→결재→참조 흐름의 문서 결재 시스템이다. 내장 양식(연차/비품/인사/출결정정/공문/관리행정/수리요청/연차사용계획/직원평가) + 커스텀 양식 빌더를 지원한다.

## 3. 기능별 상세 분석

### 3.1 상신 흐름 (useApprovalSubmit)
1. 중복 제목/중복 신청 검증 → 비품 미등록 품목 재고 검토.
2. `buildApprovalSubmitPayload` → `insertApprovalWithLegacyFallback` (optional column fallback).
3. `appendApprovalHistory`로 이력 기록, 문서번호 생성.
4. 참조자(CC) 알림 + 첫 결재자에게 `d1.notifications`(type='approval') 알림 생성.
5. 재기안 시 이전 문서 `superseded_by` 마킹.

### 3.2 결재선 라우팅 (useApprovalRouting)
- `approverCandidates`: 재직중 + APPROVER_POSITIONS 직위만 필터링·정렬.
- `useApprovalDelegation`: 위임 처리, 지연 알림(threshold/repeat/max), 현재 결재자 해석.
- 잠금(edit_locked) 스냅샷, 리비전(revision) 관리.

### 3.3 비품 구매 (재고 연계)
- `useSuppliesForm` + `supplies-helpers.ts` + `inventory-utils`로 재고 품목 연계.
- 미등록 품목은 재고 검토 플로우(`SupplyInventoryReviewState`)로 분기.

### 3.4 결재 인쇄
- `approval-print-utils.tsx`가 결재선·도장·문서번호 포함 인쇄 HTML 생성. 내정보 증명서관리에서 재사용.

## 4. 발견된 문제점 / 잠재 리스크

### 🟡 경미 (품질/리스크)
1. **`전자결재.tsx` 1428줄·`useApprovalSubmit.ts` 808줄 과대** — 상신/라우팅/필터/위임이 대형 파일에 집중.
2. **알림 생성이 클라이언트에서 직접 `d1.notifications` insert** — 첫 결재자 알림·참조자 알림을 클라이언트에서 생성. 서버 cron/알림시스템과 이중 생성 또는 누락 가능성(더블체크 필요).
3. **비품 구매 ↔ 재고 연계 복잡도** — 미등록 품목 검토, 부서/회사 매칭이 결재 플로우에 깊이 결합. 데이터 불일치 시 상신 실패 가능.
4. **`any` 타입 사용 잔존** — `전자결재.tsx`의 `resolveStoredTemplateDesign(store: Record<string, any>)`, `useApprovalSubmit` 일부. 타입 안전성 저하.
