# 메뉴 전수조사 보고서 — 내정보 (마이페이지)

> 조사 대상: `app/main/기능부품/마이페이지/` (22개 파일)
> 조사 방식: 파일별 병렬 정독 → 기능 동작·데이터 흐름·연계 지점·문제점 기록

## 1. 메뉴 개요

내정보는 로그인 직원 본인의 프로필/근태/급여/증명서/할일/서류/알림을 한 곳에서 보는 개인 대시보드다. `마이페이지/index.tsx`가 진입점이며 탭(내 정보·출퇴근·할일·연차휴가·급여·증명서·서류제출·알림)을 라우팅한다.

## 3. 기능별 상세 분석

### 3.1 내 정보 (프로필카드)
- **동작**: 직원 본인 정보(이메일/연락처/내선/주소/계좌) 조회·편집.
- **저장 흐름**: `submitProfileChangeRequest()` 호출 → **전자결재 요청으로 승인 프로세스**를 타는 구조. 즉시 반영이 아니라 결재 승인 후 반영되는 패턴.
- **데이터 소스**: `staff_identity.normalizeStaffLike`, `profile-photo.normalizeProfileUser`, `db`.
- **연계**: `erp-profile-updated` 커스텀 이벤트 브로드캐스트로 전역 프로필 동기화.

### 3.2 출퇴근 (출퇴근기록)
- **동작**: GPS 기반 출근/퇴근 체크. 위치가 병원 반경(`ALLOWED_DISTANCE_M`) 밖이면 GPS 경고.
- **판정 로직**: `late-status.ts`가 KST 기준으로 지각/정상 판정. 시프트 미지정·격일제 휴무일은 오탐 방지.
- **퇴근 판정**: `calculateEarlyLeaveMinutes`로 조퇴 여부 결정.
- **연계**: `shift-resolution`, `staff-shift-resolver`로 근무표(shift_assignments) 조회, `attendance-sync`로 attendances 동기화.

### 3.3 할일 (나의할일)
- **동작**: UI만 담당, 비즈니스는 `hooks/useTodoWorkflow`에 위임.
- **연계**: 채팅 메시지에서 생성된 할일(`source_message_id`)은 채팅방으로 바로 이동 가능.

### 3.4 연차휴가 (연차휴가내역)
- **동작**: `useAnnualLeaveSummary(staffId)`로 발생·사용 내역과 잔여 연차 표시.
- **재계산**: `/api/admin/annual-leave/sync` POST 호출.
- **연계**: 인사관리 연차 현황과 동일 `leave_ledger` 원장 공유.

### 3.5 급여명세서
- **동작**: 확정 후 발송된 급여 명세만 표시. 데스크톱은 A4 인쇄(`SalaryDetail`), 모바일은 카드형(`MobileSalarySlip`).
- **중요**: 공제 행 구성은 `lib/payroll-slip-rows` 정본을 사용 (중복 제거 완료).

### 3.6 증명서관리
- **동작**: `certificate_issuances`(직접 발급) + `approvals`(결재 승인 문서) 두 소스를 통합 표시.
- **인쇄**: 결재 인쇄 유틸(`approval-print-utils`)을 재사용. 모바일은 iframe + `window.print()` 폴백.

### 3.7 서류제출
- **동작**: 필수 제출 서류(16종) 업로드 + 카메라 촬영 스캔. `document_repository` 저장, `employment_contracts` 조회.
- **XSS 방어**: 미리보기 `document.write` 주입 값에 `escapeHtml` 적용.

### 3.8 즐겨찾기/단축키
- **동작**: 메뉴/서브메뉴/마이페이지 탭을 즐겨찾기 등록, Alt+키 단축키 바인딩.
- **권한**: `canAccessFavoriteEntry`가 모든 진입점을 `access-control`로 재검증.

## 4. 발견된 문제점 / 잠재 리스크

### 🔴 중대 (기능 결함 가능성)
1. **출퇴근 GPS 판정과 퇴근 판정의 의존성 결합도 높음** — `출퇴근기록/index.tsx`가 1265줄로 과대. GPS/날씨/시프트/집계/모달이 한 파일에 혼재하여 유지보수·회귀 위험.

### 🟡 경미 (품질/리스크)
2. **`급여명세서/index.tsx` 이중 데이터소스** — 급여는 `db`(Postgres), 발송 알림은 `d1`(D1 notifications)로 분리 조회. 데이터 정합성은 명시적이지만 두 저장소 시차로 "발송됨"과 "조회 가능"이 어긋날 수 있음.
3. **`서류제출.tsx`에 `document.write` 사용** — escapeHtml로 방어하고 있으나, 향후 신규 주입 경로 추가 시 XSS 재발 위험. DOM API로 대체 권장.
4. **프로필 편집 → 결재 연계** — 정보 변경이 즉시 반영되지 않고 결재 프로세스를 거침. 사용자 혼란 가능성(UX). 기획 의도 확인 필요.
