# 연계 기능 더블체크 보고서

> 1차 메뉴별 보고서(11개 메뉴)에서 제기한 문제·연계 지점을 실제 코드로 교차 검증한 결과.

## 1. 교차 검증 결과 (확정/기각)

### ✅ 검증 1. 연차·급여 계산 정본 공유 — **확정 (문제 없음)**
- `lib/leave-cycle.ts` `aggregateLedgerEntries` → 조직도본문(연차촉진 배너)·내정보·인사관리 공유.
- `lib/annual-leave-summary.ts` `useAnnualLeaveSummary` → 연차휴가내역 공유.
- `lib/payroll-slip-rows.ts` `buildPayrollDeductionRows` → 급여명세서·모바일명세서 공유.
- `lib/unified-leave-ledger.ts` 존재 → 연차 원장 SSOT 의도 확인.
- **결론**: 1차 보고서의 "동일 계산 함수 공유" 판단은 정확. 정본 일원화가 잘 되어 있음.

### ✅ 검증 2. 조직도 부서 스타일 중복 — **확정 (실제 미사용 잔재)**
- `org-chart-types.ts`의 `DEPT_STYLES`(진료부=blue)는 `OrgChart.tsx`에서 **사용되지 않음**.
- `OrgChart.tsx`는 자체 `DIVISION_STYLE_MAP`(진료부=green) + `getDivisionStyle`만 사용.
- **결론**: `DEPT_STYLES`·`DEFAULT_DEPT_STYLE`·`toSafeText`(org-chart-types)는 dead code. 색상 매핑 불일치(진료부 blue/green)는 실제로는 무해하나 혼동 유발. 제거 권장.

### ✅ 검증 3. 클라이언트 알림 생성 이중 경로 — **확정 (리스크 실존)**
- `알림시스템.tsx`: 할일 리마인더·급여 이상치·결재 요청을 클라이언트에서 `notifications` insert.
- `전자결재서브/useApprovalSubmit.ts`: 첫 결재자·참조자 알림을 클라이언트에서 `d1.notifications.insert`.
- **결론**: 결재 상신 시 알림 생성이 두 곳(전자결재 직접 + 알림시스템 경유)에서 발생할 가능성. `dedupe_key`/`claimCrossTab`이 중복 방지하나, 서버 cron(chat-push-dispatch 등)과의 교차는 별도 검토 필요.
