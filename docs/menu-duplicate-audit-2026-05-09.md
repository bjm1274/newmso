# 메뉴 중복 점검 보고서

작성일: 2026-05-09

## 1. 점검 범위

코드 기준으로 실제 노출 메뉴, 숨김/레거시 진입값, 컴포넌트 재사용 여부를 확인했다.

- 메인/하위 메뉴: `app/main/기능부품/조직도서브/조직도측면창.tsx`
- 관리자 메뉴: `app/main/admin-menu-config.ts`, `app/main/기능부품/관리자전용.tsx`
- 관리자 회사/조직: `app/main/기능부품/관리자전용서브/회사관리.tsx`
- 인사관리: `app/main/기능부품/인사관리.tsx`, `app/main/기능부품/인사관리서브/**`
- 재고관리: `app/main/기능부품/재고관리통합.tsx`
- 추가기능: `app/main/기능부품/추가기능공통.tsx`
- 전자결재/게시판: `app/main/기능부품/전자결재.tsx`, `app/main/기능부품/게시판*.ts*`

## 2. 결론

현재 가장 큰 중복 위험은 `관리자 > 회사 / 조직`이 회사 기준정보 화면이면서 인사관리 운영 컴포넌트를 여러 개 직접 품고 있다는 점이다. 다만 모두 같은 수준의 중복은 아니다. `휴가 정책`, `급여 정책`, `근무표 정책`, `문서 정책`은 이미 admin mode나 권한 플래그로 정책/운영 역할을 나누려는 구조가 들어가 있다. 반대로 `계약 설정`, `문서 정책`, `엑셀 일괄 등록`은 사용자가 실제로 두 메뉴에서 같은 화면처럼 느낄 가능성이 높다.

정리 원칙은 아래처럼 잡는 것이 안전하다.

- 기준정보/정책 생성은 `관리자`.
- 직원별 운영, 신청, 처리, 현황 확인은 `인사관리`, `재고관리`, `전자결재`.
- 같은 컴포넌트를 두 메뉴에 붙여야 한다면 메뉴명과 노출 탭을 분명히 다르게 한다.
- 단순 바로가기는 별도 업무 메뉴처럼 보이지 않게 처리한다.

## 6. 정리 우선순위

### P1. 바로 정리할 후보

1. `관리자 > 회사 / 조직 > 계약 설정`
   - `ContractMain`을 직접 렌더링하면서 인사관리 계약 화면과 체감 중복이 크다.
   - 관리자에는 계약 템플릿/정책만 두고, 계약 현황/발송은 인사관리로 이동 또는 링크 처리한다.

2. `관리자 > 회사 / 조직 > 문서 정책`
   - `DocumentRepository`를 관리자와 인사관리에서 모두 렌더링한다.
   - 관리자에는 관리 권한 화면, 인사관리에는 조회/연결 화면만 남긴다.

3. `관리자 > 엑셀 일괄 등록`과 `재고관리 > 일괄 업로드`
   - 같은 `ExcelBulkUpload` 컴포넌트를 두 메뉴가 직접 사용한다.
   - 재고 업로드는 재고관리, 직원/전사 데이터 업로드는 관리자처럼 업로드 유형을 분리한다.

### P2. 라벨/역할 정리 후보

1. `회사 / 조직 > 휴가 정책`
   - 내부적으로 admin/operational 분리는 되어 있다.
   - 라벨을 `휴가 기준/공휴일`로 바꾸면 운영 휴가 화면과 덜 헷갈린다.

2. `회사 / 조직 > 근무표 정책`
   - adminMode가 있어 정책 화면으로 쓸 수 있다.
   - 라벨을 `근무표 규칙`으로 바꾸고 월간 편성 저장은 인사관리 근태에서만 처리하는 방향이 좋다.

3. `게시판 > 경조사`
   - 인사관리의 `경조사 지원`과 이름이 겹친다.
   - 게시판 라벨을 `경조사 소식`으로 바꾸는 것이 가장 가볍다.

### P3. 유지해도 되는 바로가기

- `추가기능 > 조직도`
- `추가기능 > 부서별 재고`
- `추가기능 > 근무현황`

이 셋은 독립 업무 메뉴라기보다 빠른 진입점 성격이다. 다만 좌측 메뉴나 관리자 메뉴에도 다시 노출하면 중복으로 보이므로, 추가기능 카드/즐겨찾기/검색으로만 유지하는 것이 좋다.

## 7. 권장 IA

관리자 `회사 / 조직`은 아래 정도로 줄이면 혼선이 줄어든다.

- 회사 기본정보
- 팀/조직 기준
- 근무형태
- 근태 규칙
- 휴가 기준/공휴일
- 급여 기준
- 근무표 규칙
- 계약 템플릿
- 문서보관 정책

인사관리에는 아래처럼 운영 화면만 남기는 것이 좋다.

- 구성원 배정/조회
- 근태 현황/수정/이상 탐지
- 연차/휴가 신청내역/원장
- 급여 정산/대장/명세
- 계약 현황/발송
- 문서보관함 조회/직원 연결

재고관리와 전자결재도 같은 원칙을 적용한다.

- 재고관리: 품목/입출고/발주/재고 업로드
- 전자결재: 문서 작성/결재/참조/양식 사용
- 관리자: 결재 양식 관리, 전사 데이터 가져오기, 정책/권한/감사

## 9. 적용 상태

2026-05-10에 아래 항목을 반영했다.

- `관리자 > 회사 / 조직 > 계약 템플릿`에서 인사관리 `ContractMain` 직접 렌더링을 제거하고 계약 템플릿 관리만 남겼다.
- `관리자 > 직원 엑셀 등록`은 직원 업로드만, `재고관리 > 일괄 업로드`는 재고/이카운트 업로드만 보이도록 `ExcelBulkUpload` 모드를 분리했다.
- 회사/조직 정책 탭 라벨을 `휴가 기준/공휴일`, `급여 기준`, `근무표 규칙`, `문서보관 정책`으로 정리했다.
- 관리자 `문서 양식` 라벨을 `결재 양식 관리`로 바꿨다.
- 게시판 `경조사` 라벨을 `경조사 소식`으로 바꿔 인사관리 `경조사 지원`과 구분했다.
