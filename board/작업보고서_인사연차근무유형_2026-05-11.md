## 1. 작업 배경

사용자 요청 4가지:

1. **인사관리에서 구성원 등록 시 입력된 면허/자격 정보가 자격안전센터의 면허 자격증정보로 연동되지 않는다.** 두 화면이 같은 데이터를 보지 않는 상태.
2. **직종(간호사·방사선사·물리치료사·임상병리사·간호조무사 등)별로 어떤 교육을 받아야 하는지 교육센터에 자동 연동되어야 한다.**
3. **연차·연차소진·연차촉진통보가 정확히 운영되는지 재점검** (촉진 시점, 사용일수, 만료 처리).
4. **신규 직원 등록 시 근무유형을 한 가지가 아니라 여러 개 선택할 수 있어야 한다** — 각 회사가 정의한 근무형태 목록에서 다중 선택.

## 7. TypeScript 정합성 — 35 → 0 에러

5개 워커 통합 직후 발생한 35개 타입 에러를 추가 서브에이전트에 일괄 위임하여 정리.

주요 수정 카테고리:
- **zod v4 API 변경**: `error.errors` → `error.issues`
- **PromiseLike vs Promise**: `Promise.resolve(supabase.from(...))` 패턴
- **SupabaseLike 타입 너무 좁음**: `Pick<SupabaseClient, 'from'>` 형태로 완화
- **StaffLike.department**: `string | undefined` → `string | null | undefined`
- **LicenseAlert 타입 명시**
- **catch 절 error**: `any` 금지 → `unknown` + narrowing

## 8. 빌드 트러블슈팅 일지

| 단계 | 에러 | 원인 | 해결 |
|---|---|---|---|
| ① | LINE 1 syntax error | UTF-8 BOM (PowerShell `Out-File -Encoding utf8` 기본 동작) | `UTF8Encoding($false)` 로 BOM 없이 재작성 |
| ② | `ADD CONSTRAINT IF NOT EXISTS` syntax error | PostgreSQL 미지원 구문 | `information_schema.table_constraints` 체크 후 ADD CONSTRAINT |
| ③ | `column "expiry_date" does not exist` | 기존 staff_licenses에 컬럼 누락 가정 안 함 | 001 마이그레이션을 CREATE TABLE + ADD COLUMN IF NOT EXISTS 전수 보완 + 인덱스 DO 블록 보호 |
| ④ | `operator does not exist: text = uuid` | 기존 staff_licenses.staff_id가 TEXT 타입 | 백필 SQL에 `sm.id::TEXT` 캐스트 추가 |
| ⑤ | Next.js 빌드 시 `analysis_artifacts/` 깨진 import | tsconfig include가 전체 .ts/.tsx 캡처 | tsconfig exclude에 `analysis_artifacts`, `board` 추가 |

- `staff_members.license/license_no/license_date/license_note` 4컬럼은 즉시 제거하지 않고 deprecate 상태로 유지. is_primary=TRUE 행과 동기화. 한 사이클(약 1~2개월) 후 제거 검토.
- `staff_members.shift_id` 도 동일 — staff_shift_assignments.is_primary 행과 동기화.

### 10-3. 직종↔교육 seed 갱신
- 법령 개정 시 `job_category_required_trainings` row만 update/insert로 갱신 (코드 변경 불필요).

### 10-4. 연차 정책
- 회사별 `companies.leave_policy = '입사일' | '회계연도'` 선택 가능
- 회계연도 시작 월은 `companies.fiscal_year_start_month` (기본 1월)
- `companies.unused_leave_compensation = TRUE` 시 만료 잔여일 자동 보상 기록

### 10-5. 근무유형 다중
- 직원당 1개를 반드시 `is_primary=TRUE` 로 지정
- 일별 적용 근무유형은 근태기록 > is_primary > legacy(staff_members.shift_id) 3단계 폴백
